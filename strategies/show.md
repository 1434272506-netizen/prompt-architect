# 动作手册 · SHOW（给方向）

> 本文件是 V0.3 不确定性消解引擎的**动作手册**之一，只处理 **SHOW**。
> 类型判据、动作定义、优先级与组合规则一律以 `core/uncertainty-classifier.md`（下称**契约**）为准；本文件不发明第六种类型或第六种动作。
> 所有「用户可见模板」遵守 `SKILL.md` §2.1（对外表达规范）：不出现机制词、章节号、工具名。

---

## 适用对象

**对应类型：Type B（Unknown Known）—— 用户能判断好坏，但说不清标准。**

| 项 | 内容（契约 §2 判据） |
|---|---|
| 判据 | 用户用**形容词、感受、参照物**表达目标；能判断好坏，说不清标准 |
| 典型原话 | "要高级感""像苹果一样简洁""电影感""清爽一点" |
| 一句话 | 给他看，他立刻能说"对/不对"；逼他定义，他只会编 |

**不适用（命中任一即换动作）**：

- 用户已明确说清且无冲突 → Type D → **不动作**
- 答案是环境事实（现有风格规范、设计系统、品牌色）→ Type E → **INSPECT**
- 用户提出了待定项、要求拍板 → Type A → **ASK**（用户给出参照物时仍属 B：参照物是用来判断的，不是选择题）
- 用户未意识到该缺口存在 → Type C → **TEACH**
- B 与 C 混合（如"要高级感"= 能判断 + 不知道有哪些方向可判断）→ **按决策树取到的主导类型执行，另一性质只作备注，不同时展开两套**（契约 R5）

## 前置条件

**以下任一成立时，本动作不得使用：**

1. **主目标未明确时不做方向（锚点口径，V0.3.3）**：**P0 锚点「要什么产物」无依据前，不对风格词给方向**；此时最多承诺一句"等用途明确后，我再帮你把它拆成具体方向"（`SKILL.md` §4 时机）。**依据：契约 R11（P0 分级例外）+ `SKILL.md` §11.0 规则 8**。对应回归案例：`tests/cases.md` T-05（三项全缺 → ASK）、Case B（产物缺 → ASK 产物）。
2. **锚点已定、修饰缺失 → 可以 SHOW**：产物已锚定、仅缺"给谁用 / 怎么算成功"时，**不冻结 SHOW**；方向必须对受众/成功**中立**，并在同轮说明"选定方向后还需确认给谁看、怎么算成功"（**不得**把这两个槽位当成问句塞进同一轮，见前置条件 3）。对应案例：Case A / W6。
3. **同轮额度与顺序**：一轮最多 1 个 TEACH 块 + 1 组 SHOW + 1 组 ASK（≤3 题），SHOW 一组即 3 个方向，不得铺开两组。同轮内有多个动作时顺序依动作优先级：`INSPECT → SHOW → TEACH → ASK`；**SHOW 与 ASK 同轮时，SHOW 的结果必须先处理完（拿到用户选择）才能展开 ASK**——方向类答案会改变后续哪些问题值得问（`SKILL.md` §11.0 规则 7；同轮顺序见 §11.0 规则 6；契约 R4）。
4. **同轮内不得追问模糊词**：命中 Type B 后，**同轮内不得再出现"你所说的 X 具体是指什么"**（R2）；SHOW 之后只接收选择 / 修改 / 混搭。
5. **缺口是环境事实**：→ INSPECT，不得用"给三个方向让用户挑"来回避查证（R1）。
6. **目标/范围/权限/费用/数据用途/不可逆操作**：属阻塞项，必须用户拍板（R6），不得由 SHOW 的选项代替决定。
7. **已确定的方向不重开**：用户已选定过的方向不再 SHOW（§6.4：不重复询问已答过的）。

> **SHOW 不是交付（硬边界）**：只给"够判断"的**粗略草案**——不得完成主交付物，不得借 SHOW 绕过采访。
> 反例：用户要一张海报，SHOW 阶段就交出一张精修成片 = 采访未完成就出稿，返工成本最高。
> 正例：三张潦草的方向示意（或三段方向描述 + 各一句视觉特征），用户指出"第二张的感觉，再冷一点"。

## 执行步骤

1. **确认 Type B 且 P0 已明确**（否则先处理 P0）。跑决策树 Step 1→3，Step 3 命中即本动作。
2. **取模糊词并查 `SKILL.md` §4 内置模糊词表**：表内 8 词（高级/自然/漂亮/震撼/舒服/真实/科技感/电影感）直接取其"正交方向"作为**方向素材库**；表外词（"有质感""上头""清爽"）按同一方法现场生成方向。
3. **生成 3 个差异明显的正交方向**，按维度切，不按程度切：
   - ❌"很高级 / 更高级 / 超级高级"（程度）
   - ✅"极简克制 / 材质做工 / 稀缺感"（维度）
4. **每个方向给"够判断"的粗略草案**：一两句特征描述（色调、密度、材质、节奏），必要时加**极简示意**（随手草图、灰阶框图、参考图链接）。示意只服务判断，不求好看、不求完整。
5. **写清这是草稿**：明确告诉用户这是用来挑方向的草稿，不是成品；避免用户误以为交付已开始。
6. **给自由描述通道 + 明确允许混搭**："也可以完全不按这三个，直接描述你想要的"，以及"选一个、改一个、两个都想要各取一半都行"。
7. **只接收选择 / 修改 / 混搭**：不接受、也不主动索取"标准定义"。用户给出第四条路时**欣然接受并优先采用**（`SKILL.md` §4 注意）。
8. **复述并落痕**：一句复述用户选了什么、要改哪里 → 决策记录写 `类型B / 动作 shown / 状态 / 依据 / 结果`（正文格式见 `SKILL.md` §6.6）。**未收到选择前状态保持 `待决定`，不得提前写成已确认**（契约 §6 约束 3）。
9. **一轮不行按 R7 升级**：提高保真度再 SHOW 一次（示意 → 更具体草案）；**两轮仍不行**才按 `SKILL.md` §3.2 走默认值并写入「待确认假设」。
10. **方向确定后立即重跑决策树**：选定方向会改变下游哪些约束/选项集（如"黑暗电影感"会淘汰高亮配色类需求），受影响的缺口重开（R9；`SKILL.md` §6.5 局部重开）。

## 用户可见模板

```
"高级"这个词容易各有各的理解，我先不让你去下定义，直接给你三个差别很大的方向看看——
你只要说"哪个对、哪里不对"就够了：

A. 极简克制 —— 大面积留白、元素极少、单色为主，靠排版的呼吸感撑住
B. 材质做工 —— 画面里有真实材质：哑光金属、细纹纸、磨砂玻璃，靠触感取胜
C. 稀缺感 —— 暗场、低调光、只打亮一个主体，其余压在阴影里，拒绝一切装饰

（下面各附一张潦草示意，只为让你挑方向，不是成品。）

也可以完全不按这三个说：直接描述你脑子里那个画面，或者"B 的感觉但更冷一点"这种
混搭也完全可以。你选定的方向我会记下来，之后所有配色、字体、构图都往它上面收。
```

> **内部说明（非用户可见）**：示意可以是随手草图、灰阶框图、参考图链接或一段特征描述——**保真度只要够判断**。用户说不出好坏不是因为他不懂，而是因为**还没东西可看**。

## 失败/降级路径

| 失败信号 | 换什么动作 / 怎么收场 |
|---|---|
| 用户没反应 / 只回"嗯" / 答非所问 | **按未答处理**（契约 R8）：状态保持 `待决定`，不重复追问模糊词，可在同一轮结束后按 R7 提高保真度再给一次 |
| "都不太对，但我说不上来" | **R7 第一层升级**：提高保真度——从文字方向升级为更具体的草案（加配色块、版式、局部放大示意），或换一组维度。仍**不得完成主交付物** |
| 两轮 SHOW 后仍无法判断 | **停止**：按 `SKILL.md` §3.2 采用合理默认值 → 显式写入「待确认假设」，注明"若不符请指出"（`SKILL.md` §7 铁律：用户沉默 ≠ 同意） |
| 用户"两个都喜欢 / 想要混搭" | 按混搭执行并复述组合方式；不必逼二选一（Tension 不强迫二选一，`SKILL.md` §3.1） |
| 用户给出第四条路 | **优先采用**用户的路，把三个方向降为参考坐标系（`SKILL.md` §4 注意） |
| 用户说"随便 / 你决定" | **授权默认**：直接取最贴合已确认用途的方向；进「待确认假设」；不计 unresolved（`SKILL.md` §6.3） |
| 方向已选定，但其中有一处只能等真跑一次才知道（如某类素材是否拿得到） | 该处**非阻塞** → 转 **DISCOVER**：写成"执行前先验证…；若 A 则…；若 B 则…"；若涉及目标/范围/权限/费用/数据用途/不可逆操作 → 必须拍板，不可转 DISCOVER（R6） |
| SHOW 过程中发现 P0 其实没定 | 暂停方向讨论 → 转 **ASK** 补 P0；方向问题暂缓（`SKILL.md` §4 时机） |
| 用户选的方向在成本/技术/合规上不可实现 | 按 §2.1 A4：**只描述替代结果**（能做到什么程度）→ 需要用户选择时才列为待确认项，不解释内部原因 |
| 用户要求"别给我看草稿，直接出成品" | 明确这是采访阶段的判断材料；若用户坚持跳过采访 → 按 `SKILL.md` §6.3 授权默认处理：默认方向 + 全部自定内容进「待确认假设」 |

## 反模式

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 对"高级感"连续追问"到底什么意思" | Type B 用户会开始编造标准，答案不可信（R2） | 给 3 个正交方向让他挑/改/混 |
| SHOW 时直接交付成品 | 采访未完成就出稿，返工成本最高（契约 §3 硬边界） | 只给"够判断"的粗略草案 |
| 拿 SHOW 当借口跳过 P0 | 用途不同，"高级"含义完全不同（`SKILL.md` §4 时机） | 先 ASK 定 P0，再给方向 |
| 三个方向其实是同一意思 | 用户无从判断，等于没给选项（§4 硬约束 1） | 按维度切，不按程度切 |
| 只给菜单不给自由通道 | 把采访变成选择题，用户第四条路被堵死 | 每题附"也可以直接说你的想法" |
| 把 AI 偏好写成"推荐" | 违反 `SKILL.md` §11.4 选项中立 | 三个方向平等呈现，不排名 |
| 用户给了第四条路还强拉回菜单 | 用户表达优于 AI 选项（§4 注意） | 优先采用用户方向 |
| 收到选择前就写"已确认" | 违反契约 §6 约束 3 | 保持 `待决定`，收到选择再更新 |
| SHOW 后追着要"设计说明/评价标准" | 又把不可描述的东西推回给用户 | 只在方向上收敛，标准由已选方向反推 |
