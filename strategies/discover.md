# 动作手册 · DISCOVER（转执行期验证）

> 本文件是 V0.3 不确定性消解引擎的**动作手册**之一，只处理 **DISCOVER**。
> 类型判据、动作定义、优先级与组合规则一律以 `core/uncertainty-classifier.md`（下称**契约**）为准；本文件不发明第六种类型或第六种动作。
> **DISCOVER 不是第六种类型**，而是任意类型的**兜底出路**：B / C / A 都可能落到它（契约 §2 注）。
> 所有「用户可见模板」遵守 `SKILL.md` §2.1（对外表达规范）：不出现机制词、章节号、工具名。

---

## 适用对象

**对应判据（契约 §2 注 + §4 Step 6）：该缺口在当前信息条件下无法确认，且必须由真实执行结果来回答。**

| 项 | 内容 |
|---|---|
| 判据 | 现在**无法确认**（环境里查不到、用户也答不出），只有**真跑一次**才知道 |
| 典型原话 | "这接口到底分不分页？""对方系统支持哪种格式？""这个库在这台机器上能不能跑？""线上数据到底有多脏？" |
| 一句话 | 不是不知道问谁，而是**这个问题此刻没人能回答**，答案在执行结果里 |
| 产出 | 一段**写进最终 Prompt 的验证步骤**，不是一句"到时候再看" |

**从哪类落过来**：Type A 问过但问不出 → 转 DISCOVER；Type B 两轮 SHOW 仍判断不出且**非阻塞** → 默认值 + DISCOVER；Type C 教过、用户仍无法定且**非阻塞** → DISCOVER。任何情况下都要先跑决策树 Step 1–5。

**不适用（命中任一即换动作）**：

- **阻塞项**：目标 / 范围 / 权限 / 费用 / 数据用途 / 不可逆操作 → **必须当场拍板，禁止 DISCOVER**（R6）
- 答案在可读环境里 → Type E → **INSPECT**（R1：能查不问、也不该"留给执行阶段"）
- 用户能判断方向 → Type B → **SHOW**
- 用户未意识到该缺口存在 → 先 **TEACH**（R3），教完再判断是否落到本动作
- 用户已明确说清 → Type D → **不动作**

---

## 前置条件

**以下任一成立时，本动作不得使用：**

1. **阻塞项检查必须先跑**：逐项核对 `目标 / 范围 / 权限 / 费用 / 数据用途 / 不可逆操作`，命中任一项即转 **ASK**、结束本流程（R6）。禁止用"执行阶段再验证"逃避必须拍板的事。
2. **必须有明确的验证触发点与分支**（硬边界）：写不出"什么时候验、看什么、若 A 怎么办、若 B 怎么办"，就不是 DISCOVER，是拖延（契约 §3 硬边界）。
3. **必须先排除可查**：能从配置、文档、依赖、历史记录读到的，一律先 INSPECT（R1）。
4. **不能用来逃避 TEACH**：用户不知道自己缺什么时先 TEACH（R3），不得直接把它转成执行期问题。
5. **非阻塞项才能留默认**：走到 DISCOVER 的缺口必须是**非阻塞**的；阻塞项已在第 1 条被拦掉。
6. **必须写进产物并让用户可见**：验证步骤要落在最终 Prompt 的约束/验收段落里，同时在「待确认假设」区可见；不得只写在内部记录里。
7. **验证不得有未授权副作用**：验证动作默认只读；若验证本身会改状态、花钱或对外产生不可逆影响，则它已升级为阻塞项，必须先取得用户明确授权。
8. **授权默认下的口径**：用户已授权默认（"随便 / 你决定"）的非阻塞缺口，可以直接取默认值，也可以转 DISCOVER——取成本更低的一种；若默认值已经够用，就不必再写验证步骤（`SKILL.md` §6.3）。
9. **同轮顺序里它排在最后**：同轮出现多个动作时，按动作优先级 `INSPECT → SHOW → TEACH → ASK` 处理（契约 R4；`SKILL.md` §11.0 规则 6）；DISCOVER 是优先级最低的兜底，其产物写进最终 Prompt，不在同一轮里取代其他动作、也不追加追问。

---

## 执行步骤

1. **跑阻塞项检查**（目标 / 范围 / 权限 / 费用 / 数据用途 / 不可逆操作）。命中任一 → 转 ASK，停止（R6）。
2. **确认无法在当前信息条件下确认**：INSPECT 已试过或不可达；问过用户或按 §11.2 降维后仍答不出。两条都成立才继续。
3. **按固定句式写验证步骤**（格式不可省）：

   ```
   执行前先验证 X；若 A 则 …；若 B 则 …
   ```

4. **明确触发点**：写清在哪个环节、哪一步**之前**验证（如"在写取数逻辑之前先跑一次接口探测"），触发点必须**可观察、可判定**（看什么字段、跑哪条只读命令、检查哪个文件）。
5. **写全分支**：至少覆盖 **主路径分支 + 失败/不可用分支 + 兜底**。兜底固定为："若两种都不成立 → 暂停并回报，由你确认后再继续"，不得默默选一条继续。
6. **写明验证结果如何影响产物**：选哪条实现路径、是否降级、要不要改输出格式（让执行者拿到结果后知道该怎么分叉）。
7. **落地到产物**：写进最终 Prompt 的**约束段**（做法分叉）或**验收段**（判定条件），并在「待确认假设」区列一条，注明"执行阶段验证"（`SKILL.md` §8 出口格式）。
8. **落痕**：决策记录写 `类型 / 动作 discovered / 状态 待决定 / 依据 / 结果`（正文格式见 `SKILL.md` §6.6），**结果里必须注明"执行阶段验证"**（契约 §6 约束 5）。
9. **诚实告知用户**：说明这一段为什么现在只能这样处理、它不会挡住开工；不暴露内部机制词（`SKILL.md` §2.1）。
10. **验证结果回来后立即重跑决策树**（R9）：结果常常会变成一个全新的 Type A 缺口，届时按新分类重新处理。

## 用户可见模板

（下列第一段是**对用户说的话**，第二段是**写进最终 Prompt 的原文**。）

````
有一件事我现在确实没法替你确定：对方那个接口到底会不会分页。这一项在代码和文档里都
查不到，只有真跑一次才知道。所以我不会在这儿反复猜，而是把它写成一条"先验证再选择"的
做法放进最终稿里：

- 如果接口会分页 → 按游标翻页取全量，并处理翻到最后一页的情况；
- 如果接口不分页 → 一次性取回，省掉翻页逻辑；
- 两种都不成立（比如需要额外权限）→ 先停下告诉我，不自己硬选。

这样写的好处是：不管真实情况是哪一种，执行时都不会做错方向，你也不用现在去帮我查。
```

```markdown
## 约束（节选）
- 取数前先验证接口是否分页（探测返回体的分页字段）：
  - 若返回分页字段 → 按游标翻页取全量，并处理空页终止；
  - 若无分页字段 → 单次取回全部结果，不实现翻页；
  - 若探测失败或需要额外授权 → 暂停并回报，不得自行假定。

## 待确认假设
- 接口是否分页：执行阶段验证（探测后按上述分支处理；若不符请指出）
```

## 失败/降级路径

| 失败信号 | 换什么动作 / 怎么收场 |
|---|---|
| 检查后发现该缺口其实是阻塞项（目标/范围/权限/费用/数据用途/不可逆） | **立即撤回 DISCOVER**，转 **ASK**，请用户当场拍板（R6）；产物中对应段落删掉 |
| 写不出可观察的触发点或分支 | 说明该缺口**不适合**进执行期：多半是 Type A（需要拍板）或 Type E（其实查得到）→ 回到决策树重分类 |
| 用户说"这个必须现在定" | 转 **ASK**，取最小必要澄清问题（一次 1 题） |
| 用户不同意把该问题留到执行期 | 转 **ASK** 当场定；若用户仍不定 → 非阻塞则默认值 + 进「待确认假设」（§6.3） |
| 执行期验证发现两条分支都不成立 | 走兜底：**暂停 + 回报 + 请用户确认**；不得默默继续。兜底必须写进产物，否则视为验证步骤不合格 |
| 验证动作本身会改状态 / 花钱 / 对外不可逆 | 该验证已升级为阻塞项 → 先取得用户明确授权，或改为只读替代验证 |
| 验证结果回来后缺口性质变了 | 立即重跑决策树（R9），按新分类处理（通常是新的 Type A） |
| 发现了本可查证的事实却被写成"执行期验证" | 违反 R1 → 撤回，改 **INSPECT** 后直接给结论 |
| 用户已授权默认且默认值够用 | 直接取默认值并进「待确认假设」，**不必**再写验证步骤（避免无谓复杂度） |

## 反模式

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 把"用户该拍板的目标/范围/权限"写成执行期验证 | 违反 R6，用 DISCOVER 逃避必须拍板的事 | 阻塞项一律 ASK |
| 只写"到时候再看情况" | 没有触发点、没有分支，等于没处理 | 写"执行前先验证 X；若 A 则…；若 B 则…" |
| 分支只写成功路径 | 真实系统先失败；缺失败分支必然在异常处返工 | 补失败/不可用分支 + 兜底 |
| 用 DISCOVER 掩盖自己没查环境 | 违反 R1，把可查事实推给未来 | 先 INSPECT，再决定是否真需要验证 |
| 验证步骤有未授权副作用 | 验证不能以改状态/花钱为代价 | 只读验证；有副作用则先取得授权 |
| 写进产物却不告诉用户 | 用户读到一段无法理解的悬空条款，且无从纠正 | 一句话说明 + 在「待确认假设」区可见 |
| 兜底是"自行选一条继续" | 把不可知当已知，风险后移 | 兜底固定为"暂停 + 回报 + 等确认" |
| 验证结果回来不重分类 | 违反 R9，后续动作全部走偏 | 结果一到就重跑决策树 |
| 记录里只写"已转验证" | 无法复盘，违反 R10 | 写全 `类型 + 动作 discovered + 状态待决定 + 依据 + 结果` |
