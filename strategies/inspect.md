# 动作手册 · INSPECT（读环境）

> 本文件是 V0.3 不确定性消解引擎的**动作手册**之一，只处理 **INSPECT**。
> 类型判据、动作定义、优先级与组合规则一律以 `core/uncertainty-classifier.md`（下称**契约**）为准；本文件不发明第六种类型或第六种动作。
> 所有「用户可见模板」遵守 `SKILL.md` §2.1（对外表达规范）：不出现机制词、章节号、工具名。

---

## 适用对象

**对应类型：Type E（Evidence Unknown）—— 答案客观存在，只是不在用户脑子里，而在可读环境里。**

| 项 | 内容（契约 §2 判据） |
|---|---|
| 判据 | 答案**客观存在于可读环境**（代码库、文档、配置、历史记录、既有产物）中，**不该问用户** |
| 典型原话 | "现在项目用什么 Python 版本？""我们之前是不是定过这个？""接口现在返什么字段？" |
| 一句话 | 这个问题**有唯一正确答案**，而且它就写在某个文件/记录里 |

**可读环境的范围（按建议顺序）**：README / 项目规范 → 配置文件 → 依赖清单 → 目录结构 → git history（log / show，只读）→ 既有产物与测试 → 项目内文档。

**不适用（命中任一即换动作）**：

- 用户意图、偏好、业务规则、可接受的风险 → **不是环境事实**，属于 Type A/B/C，不得用"我查一下"替用户决定
- 用户已明确说清且无冲突 → Type D → **不动作**
- 用户用形容词表达目标 → Type B → **SHOW**
- 必须由真实执行结果回答 → **DISCOVER**（契约 §4 Step 6）
- 目标/范围/权限/费用/数据用途/不可逆操作 → 阻塞项，必须用户拍板（R6）

---

## 前置条件

**以下任一成立时本动作不得执行（或必须改变做法）：**

1. **只读是硬边界**：可读 README / 配置文件 / 依赖清单 / 目录结构 / git history / 既有产物；**不得修改任何文件，不得安装依赖，不得运行会改变状态的命令**（构建、迁移、部署、启动服务、写缓存、`git` 写操作、任何写库/写盘命令）（契约 §3 硬边界）。
2. **读不到不得转问用户**：文件不存在、无权限、环境不可达 → 如实标注**"未核实"**并说明对结果的影响；**不得转身去问用户**（R1）。
3. **不得声称读过未读的内容，也不得暴露不该暴露的路径**：没有引用的证据就不能写成事实；不编造文件名、行号或结论。证据出处**只给项目内文件的相对路径 + 行号**；机器绝对路径、盘符、挂载点、工具名与服务状态一律不对外暴露（契约 §3 INSPECT 行；`SKILL.md` §2.1）。
4. **不得把现状当意图**：代码目前怎么写 ≠ 用户想要什么。技术事实可以 INSPECT，产品决定不能。
5. **不索取、不回显敏感内容**：密码、密钥、Token、凭证一律不读取不回显；发现疑似敏感字段只说明"此处存在敏感配置，未展开"。
6. **不得越界扩大范围**：INSPECT 只回答当前缺口，不做与需求无关的全库大扫除；不顺手重构、不顺手升级。
7. **不得用 INSPECT 代替必须拍板的决定**：即使读到默认值，若该决定属阻塞项，仍须用户确认（R6）。
8. **信息变化即重分类**：读到新事实后立即重跑决策树（R9），不得沿用旧分类。

## 执行步骤

1. **确认这是环境事实而不是用户意图**：问题有唯一正确答案、且答案写在某个可读载体上，才继续。
2. **列出候选证据源**，按上面的建议顺序定位；优先读最小必要范围（一个配置项就够，就不要通读全库）。
3. **只读执行**：
   - 用只读读取/检索工具查文件内容；
   - 需要历史时用只读命令（如 `git log`、`git show`、`git blame`）；
   - 不做任何写操作、不装依赖、不启动服务、不运行有副作用的脚本。
4. **提取"事实 + 证据出处"**：每条结论都带**项目内文件的相对路径**，能定位到行号就带行号（如 `pyproject.toml` 第 12 行）。只给相对路径——不写盘符、不写机器绝对路径、不提工具名与服务状态。**证据出处是 INSPECT 的标准产出，不是可选项。**
5. **发现冲突时并列处理**：多个来源不一致（如 `requirements.txt` 与 `pyproject.toml` 版本不同）→ 同时列出，指明更权威/更新的一方，并说明冲突本身对方案的影响；不静默取一个。
6. **读不到就标"未核实"**：写明缺什么、为什么缺，以及它对结果的影响程度。若该缺失实质降低结果的准确性/完整度/可信度，即使用户此刻没有可做的动作，也要说明限制（`SKILL.md` §2.1 A2）。
7. **保守缺省**：对未核实项采用保守默认，并在产物中可见（「待确认假设」区），不得把未核实项写成事实（R8）。
8. **落痕**：决策记录写 `类型E / 动作 inspected / 状态 证据已核实 / 依据 / 结果`（正文格式见 `SKILL.md` §6.6）。只读到部分内容时状态写**"部分核实"并列出缺什么**（契约 §6 约束 2）。
9. **重跑决策树**：读到的结论若改变了其他缺口的定义或选项集，重开受影响的分支（R9；`SKILL.md` §6.5 局部重开）。

## 用户可见模板

```
我先自己看了一下项目里的内容，这几个问题不用你回答：

- 运行时版本是 Python 3.11（见 `.python-version` 第 1 行；`pyproject.toml` 第 12 行要求 >=3.11，两处一致）
- 依赖管理用的是 poetry（`pyproject.toml` 第 1–20 行；仓库里没有 `requirements.txt`）
- 测试框架是 pytest（`pyproject.toml` 第 45–52 行，且 `tests/` 下已有 6 个测试文件）

有一处我没能核实：仓库里没有找到部署配置，所以"上线怎么发布"这一项我无法从现有内容确认。
这不影响我先把方案给出来，但发布环节我只能写成不依赖具体平台的做法；如果你有相关文件，
发给我我就补上。

其余我按查到的事实推进，不再问你版本类的问题。
```

> **未核实时的表达（内部说明，非用户可见；同样遵守 §2.1）**
> - ✅ "我目前无法读取你提到的那个文件，请重新上传后我才能基于原文继续。"（这是**请用户提供材料**，不是把事实问题改成提问）
> - ✅ "没有找到部署配置，这一部分我只能先给出不依赖发布平台的做法。"
> - ❌ "你们的 Python 版本是多少？"（答案本该自己查）
> - ❌ 汇报内部工具名、挂载状态、机器路径、日志或诊断码。
> - ❌ 证据里写盘符或机器绝对路径（如 `C:\...`、`Z:\...`）、挂载点、服务状态；证据只给**项目内相对路径 + 行号**。

## 失败/降级路径

| 失败信号 | 换什么动作 / 怎么收场 |
|---|---|
| 目标文件/目录不存在 | 标**"未核实"** + 写明缺什么 + 说明影响；**不得转问用户**（R1）；保守缺省并让缺省在产物里可见 |
| 无读取权限 / 环境不可达 | 同上标"未核实"；若已实质降低结果质量 → 按 §2.1 A2 说明限制（只说影响，不解释内部原因） |
| 只能读到一部分 | 状态写**"部分核实"**并列出缺什么（契约 §6 约束 2）；未核实部分按保守默认处理 |
| 多个来源互相冲突 | 并列列出 + 指明更权威/更新者 + 标注不确定性；把"按哪一方走"作为可见假设写入产物 |
| 读到的内容与用户已确认的说法冲突 | **不得静默覆盖用户意图**：并列呈现事实与用户说法，请用户在该点上拍板（属 Type A，转 ASK） |
| 缺口其实是用户意图/偏好 | 转 **ASK**（必要时先 TEACH），并把"这是决定、不是事实"说清楚 |
| 缺口必须由执行结果回答 | 转 **DISCOVER**：写成"执行前先验证 X；若 A 则…；若 B 则…" |
| 读到的结论推翻了原分类 | 立即重跑决策树（R9），重开受影响分支 |
| 需要运行命令才能得到答案、且该命令有副作用 | **不做**：不得为取证改变环境状态；改为只读替代（读配置/日志/文档），或说明该缺口须在执行阶段验证（DISCOVER） |
| 读到的内容含敏感凭证 | 停止展开，只说明"此处存在敏感配置，未读取"；不写入产物、不回显 |

## 反模式

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 问用户"你们用哪个版本" | 答案在依赖清单里，问用户是浪费（R1） | INSPECT 后直接给结论 |
| "我查了一下，你们用的是 X"（其实没读） | 编造证据，比不问更糟 | 没读到就标"未核实" |
| 读不到就转身问用户 | 违反 R1 的"不得转成问用户" | 标"未核实" + 说明影响 + 保守缺省 |
| 边"调查"边改文件 / 装依赖 / 跑迁移 | 违反只读硬边界，可能改变用户环境 | 只读读取与只读命令 |
| 把代码现状当成用户意图 | 现有实现不能替代用户意图，静默降级会走错方向 | 事实归事实，决定转 ASK |
| 结论不带出处 | 无法复核，用户只能选择相信或不信 | 每条事实带项目内相对路径（能带行号就带） |
| 结论里写机器绝对路径 / 盘符 / 挂载点 / 工具名 | 违反 §2.1：与用户决定无关的内部环境信息不该外露 | 只给项目内相对路径 + 行号 |
| 多个来源冲突时静默取一个 | 隐藏了真实分歧，返工在后面 | 并列 + 指明权威来源 + 标注不确定性 |
| 顺手做了一次全库大扫除 | 越界、耗时，且与当前缺口无关 | 只读最小必要范围 |
| 把未核实项写成既定事实 | 违反契约 §6 约束 2 与 R8 | 状态"部分核实/未核实" + 进「待确认假设」 |
| 为了取证运行有副作用的命令 | 取证不能以改变环境为代价 | 换只读证据源，或转 DISCOVER |
