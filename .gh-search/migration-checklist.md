## 5. SHOW 误抢 P0 的判定口径（统一）

**误抢 = P0 语义槽位整类缺失（且环境不可查）时，首个动作是 SHOW。**
- 触发契约 R11 的案例：首个动作必须是 ASK(P0)，**SHOW 一律算误抢**。
- P0 只有部分缺失（如产物已知、受众未知）：按 §11.0 规则 8，**只补缺的那一项，不冻结 SHOW 直到 P0 全齐** → 此时 SHOW 不算误抢，但要记录为"观察项"。
- 环境可查 P0（契约 R1）：必须 INSPECT，ASK 与 SHOW 都算错。

## 6. 三种终局（对应 Lead 的裁定）

| 情况 | 条件 | 处理 |
|---|---|---|
| **1 全稳定** | 无 M3、无新增 M4、11 例旧不唯一至少不劣化 | **冻结 V0.3** |
| **2 少量边界** | 出现 M3 或新增 M4，但可归因于**单条规则措辞** | **只加最小契约**（最小补丁措辞） |
| **3 大量迁移错误** | M3 集中出现，或 SHOW 误抢 P0 成规模 | 说明 Type 层过早介入 → **需要调整决策树**，不加补丁 |
