## 1. 核心命题

**同一个缺口，消解方式不同，成本和成功率差一个数量级。**

- 答案客观存在 → 问用户是**浪费**（用户还得替你查）
- 用户能判断但不能描述 → 连续追问是**伤害**（越问越乱，用户开始编）
- 用户根本不知道有这个缺口 → 只问不教，用户无法决策
- 只有真实执行才能确认 → 在需求阶段反复追问是**假精确**

因此：**先分类，再选动作。** 采访（ASK）只是五种动作之一，不是默认动作。

## 2. 五种类型（Type A–E）

| Type | 名称 | 判据（用户侧证据） | 典型原话 | 动作 |
|---|---|---|---|---|
| **A** | Known Unknown | 用户**明确提出**一个待定项，或**承认**某个决定还没做 | "数据库选 MySQL 还是 PostgreSQL？""这个我还没定" | **ASK** |
| **B** | Unknown Known | 用户用**形容词、感受、参照物**表达目标；能判断好坏，说不清标准 | "要高级感""像苹果一样简洁""电影感" | **SHOW** |
| **C** | Unknown Unknown | 用户**未意识到**该缺口存在；缺口一旦踩空会造成返工、风险或不可逆后果 | "我要做一个 AI 客服""自动交易机器人" | **TEACH** |
| **D** | Known Known | 用户**已明确说清**，且无冲突 | "竖版 1080×1920，主标题不超 8 字" | **不动作**（直接进规划/组装） |
| **E** | Evidence Unknown | 答案**客观存在于可读环境**（代码库、文档、配置、历史记录、既有产物）中，**不该问用户** | "现在项目用什么 Python 版本？" | **INSPECT** |

> **Discovery（DISCOVER）不是第六种类型**，而是**任意类型的兜底出路**：B/C/A 都可能落到它。
> 判据：该缺口**在当前信息条件下无法确认，且必须由真实执行结果来回答**。

**缺口的 Type 归属（V0.3.3 统一口径，最小补丁）**：

| 缺口性质 | 归属 | 理由 |
|---|---|---|
| P0/P1/P2 中**用户未提及**的语义槽位（产物 / 受众 / 成功标准 / 对象细节 / 硬约束） | **一律 Type A → ASK** | 决策树 Step 4 的"用户承认还没定"包含**未提及**；不得因为"用户没主动提"就落到 Step 5 变 C，否则目标类缺口会走成 TEACH |
| **风险 / 后果类**未意识缺口（资金、权限、数据用途、幻觉、不可逆操作、行业合规） | **Type C → TEACH** | Type C 专用于"用户不知道自己缺什么"，不用于普通信息缺失 |
| 环境可查事实 | Type E → INSPECT | 见 R1 |
| 只能由执行结果回答 | DISCOVER | — |

## 3. 五种动作（Resolution Actions）

| 动作 | 一句话定义 | 成本 | 用户负担 | 典型产出 | **硬边界** |
|---|---|---|---|---|---|
| **ASK** | 生成**决策问题**，请用户拍板 | 低 | 中（需回答） | 1–3 个带推荐默认值的结构化问题 | 每轮 ≤3 题；能 INSPECT 的不问；每题附影响说明 |
| **SHOW** | 生成**3 个差异明显的方向**（选项扇），让用户选/改/混 | 低—中 | 低（只需反应） | 3 个正交方向草案（可选极简示意） | **禁止连续追问模糊词**；**SHOW 不是交付**：只给"够判断"的粗略草案，不得完成主交付物，不得借 SHOW 绕过采访 |
| **INSPECT** | **只读**读取环境事实 | 低 | 无 | 事实结论 + 证据出处（**项目内**文件相对路径 + 行号） | **只读**；不得修改、安装、运行会改变状态的命令；读不到就如实标"未核实"，**不得**转成问用户。证据出处只给**项目内文件与行号**；机器绝对路径、盘符、挂载点、工具名与服务状态不对外暴露（`SKILL.md` §2.1） |
| **TEACH** | 指出用户**不知道自己缺**的问题，并说明后果 | 中 | 低（只需知晓） | "还有 3 个常见遗漏 + 各自后果"，随后按需转 ASK/SHOW | 一次 ≤3 条；**不制造焦虑、不要求用户立即回答**；只讲后果与最低必要知识 |
| **DISCOVER** | 把无法预先确认的问题**转成执行阶段的验证步骤**，写进产物 | 低 | 无 | 写入 Prompt 的"执行前先验证 X：若 A 则…，若 B 则…" | 不得用于**阻塞项**（目标/范围/权限/费用/不可逆操作必须当场定）；必须有明确的验证触发点与分支 |

**动作优先级（高→低）**：`D 不动作` > `E→INSPECT` > `B→SHOW` > `C→TEACH` > `A→ASK` > `DISCOVER`

> 读法：能自己查的别问；能让用户"看一眼就选"的别追问；用户不知道自己缺什么就先教；只有真正需要用户拍板的才问；确实问不出来的转执行期验证。

**⚠️ 例外（P0 语义优先，V0.3.1 裁定）**：以上优先级仅在**目标已明确**时适用。
当 P0 语义槽位整类缺失时（**要什么产物 / 给谁用 / 怎么算成功** 全无依据），**先把 P0 目标缺口按 Type A 走 ASK**，其余动作（含 SHOW）**一律让位**。

- 理由：目标决定"哪种方向算对"。目标未定时 SHOW 出来的方向可能整体不适用，等于让用户为错误的问题集做选择。
- **"整类缺失"必须先扣除可读环境证据（V0.3.2 裁定）**：先按 **R1 / Step 2 走 INSPECT** 查 README、配置、既有产物；**查得到 → 该槽位不算缺失，问用户反而违规**。只有"环境查不到、用户也没说"的 P0 槽位才触发本例外。
- **P0 内部分级（V0.3.3 裁定，最小补丁）**：P0 三项**不等权**：
  - **锚点槽位 = 要什么产物**：**产物无依据 → 一律先 ASK 产物，SHOW 让位**（不论受众/成功是否有依据）。依据：产物决定方向**本身**是否适用；产物不定还出方向扇 = 让用户为错误的问题集做选择。
  - **修饰槽位 = 给谁用 / 怎么算成功**：产物已锚定 → **不冻结 SHOW**；方向必须对受众/成功**中立**，并在同轮说明"选定方向后还需确认给谁看/怎么算成功"。受众/成功缺失**不单独触发**本例外（只补缺项）。
  - **与冻结 §3/§4 的统一口径**：`SKILL.md` §3「若 P0 缺失先问目标」与 §4「P0 未明确前不对风格词做澄清」，在 V0.3 下按本分级**收敛为"锚点缺失时先问"**；两处措辞同步（不修改冻结判据，仅对齐触发条件）。**§11.0 规则 8 的"整类缺失"一律按本分级理解**，不得再按字面"三项全缺"执行。
- **不冲突**：Type B 仍被正确分类（不违反 R2），只是**动作时序**让位于 P0；拿到目标后对同一模糊词执行 SHOW 即可。
- **边界**：P0 已有部分依据（如"产物已知、受众未知"）→ 只补缺的那一项，**不冻结 SHOW 直到 P0 全齐**；不得把本例外扩大成"任何情况下都先问目标"。
- 既有案例对应：`tests/cases.md` **T-05**（`我要一个电影感的方案`，无产物/受众/场景）与本例外一致；R11 触发/不触发两侧案例见 `tests/unknown-known.md` UB-11（触发）与 Test 01 / UB-05（不触发）。

### 3.1 高风险 Type C 前置（R14 完整判据，V0.3.4）

**为什么需要单独一条**：R3 只说"命中 Type C 先 TEACH"，但**没有限定哪些 C 才该占位**。若不限定，会退化成两种事故：
- **C 膨胀**：任何"用户没提"都被当成 C → 每轮都在教学，需求永远问不完；
- **C 空洞**：泛泛罗列风险（"要注意安全、合规、性能"）却不落到本项目 → 用户被吓到却不产生任何决策。

**核心口径（不得简化为"C 永远优先"）**：

```
高风险 C  >  普通 A
普通 C  <  阻塞 A
高风险 C  =  阻塞 A   → 同轮并列：先 TEACH，紧接 ASK（不推迟阻塞项）
```

**⚠️ 适用对象限定（V0.3.5，防 C 膨胀的第一道闸）**：本闸门**只适用于风险/后果类缺口**（资金、权限、数据用途、幻觉、不可逆操作、行业合规）。
**P0/P1/P2 中用户未提及的语义槽位（产物形态 / 受众 / 成功标准 / 对象细节 / 硬约束）一律按 §2 Type 归属表走 Type A，不进本闸门。**
- **类别词边界（V0.3.5）**：产物**只有类别词而无形态度**（"物料""方案""东西""一个页面"）→ **一律归语义槽位，走 Type A**（问产物形态）。
- **闸门①第三项的反向限定**：**"用户目标可能被根本误解"仅用于"产物已明确、但目标含义存在多种读法"**（如"给投资人看的"——是路演 PPT 还是一页纸）；**不得**用于产物本身未定的情形。
（依据：§2 归属表已定"未提及 ≠ 未意识到"，本闸门不得绕过它。）

**三个闸门必须同时满足（缺一不前置）**：

| 闸门 | 判据（可操作） | 反例 |
|---|---|---|
| ① **高风险五类之一** | 重大返工 / 安全 / 合规 / 不可逆架构选择 / 用户目标可能被根本误解。<br>**"重大返工"的判据**：需推翻**已完成产物的结构**或**已确认的上游决定**；重跑一次、改措辞、调参数**不算**。<br>**"目标被根本误解"的判据**：**仅限用户已表达过目标、且该表述存在会导致产物类别错误的多种读法**；**不得**用于用户完全没说的 P0 空白 | "要不要加缓存"属实现细节 → 不算；"重跑一次脚本"→ 不算重大返工 |
| ② **用户尚未意识到** | **可判为"已意识到"的三种信号**：㈠用户提到该维度；㈡用户声明过相关约束或流程（如"我们院对这块管得挺严"）；㈢可读环境有其既往表述。<br>**信号㈡的范围（V0.3.6/7）**：**仅当该声明与该风险维度"同域"时成立** —— 内网 / 离线 / 专用终端 ↔ 权限·合规·数据用途；**一般运行环境表述（"我自己电脑上用""手机上跑""简单一点"）不构成㈡**。理由是这类声明直接决定风险判定与后果范围，无关表述则不算。<br>**"维度"的粒度（V0.3.5）**：以 §2 风险清单条目为准；**泛化风险词（"注意安全""要合规""别出事"）视为已提到该维度 → ②❌ → 该缺口走 Type A 的 ASK**，不 TEACH。<br>**三者皆无时**：风险/后果类缺口默认按 C；语义槽位按 Type A（§2）。<br>**沉默不足以证明用户"已意识到"**（不得据此判 Type A） | 用户说"我们院管得挺严"或"注意安全"或"要在内网跑" → ②❌ → 该风险不 TEACH，转 ASK |
| ③ **本项目真实存在** | 必须给出本项目中的**具体载体**（哪个字段 / 哪条数据流 / 哪个操作）**+ 不处理的后果**；只写"风险名 + 项目名"**不算** | "注意数据安全" + 官网表单邮箱 → 通用话术，不算；"用户手机号会明文落库、导出给第三方" → 算 |

**执行顺序（与 R4 / R6 / R11 的关系）**：

1. 先跑决策树判定 Type；命中 C 且**三闸门全过** → **本轮先做 TEACH**（≤3 条，每条讲后果）。
2. **TEACH 与阻塞项（R6）重叠——本格必须并列，不得推迟（V0.3.5 修订）**：若该高风险 C 与 R6 阻塞项（目标 / 范围 / 权限 / 费用 / 数据用途 / 不可逆操作）**指向同一件事**，则**同一轮内先 TEACH、紧接 ASK 该阻塞项**。
   - **"指向同一件事"的判定口径（V0.3.6，消除两读）**：**必须同时满足**：
     - ⓐ 被问的槽位**属于 R6 闭集**（目标 / 范围 / 权限 / 费用 / 数据用途 / 不可逆操作）；**且**
     - ⓑ **不拿到该槽位，用户就无法对该风险作出知情拍板**（即该槽位是该风险决策的必要输入）。
   - **⚠️ 复核对象必须包含两侧（V0.3.7，防漏检）**：**高风险 C 自身若对应某个 R6 槽位**（权限风险 ↔ 权限范围、合规/数据风险 ↔ 数据用途、资金风险 ↔ 费用授权、不可逆风险 ↔ 不可逆操作边界），**该槽位默认视为"未定的必问项"**。
     **复核时不得只检查"原本被推迟的那个槽位"，必须同时检查"该风险自身对应的 R6 槽位是否未定"。**
   - **判据句**：问自己"**教了这个风险，却不拿到这个答案，用户能定吗？**" 不能 → 必须同轮 ASK；能 → 该 ASK 属普通项，按 §3 梯队排后续轮次（**不算推迟阻塞项**）。
   - **典型对照**：
     | 场景 | ⓐ 属 R6 | ⓑ 是风险决策的必要输入 | 结论 |
     |---|---|---|---|
     | 幻觉/权限风险 + ASK **权限范围** | ✅ | ✅ | **同轮 TEACH + ASK** |
     | 医院影像 + "要在**医院内网**跑"（环境已声明） | — | — | **本条由闸门②裁定（非并列判定）**：已声明 ⇒ **不 TEACH**，直接 ASK 该维度细节；同时段其他未决项按 §3 梯队 |
     | 幻觉风险 + ASK **受众**（内部员工 or 外部客户） | ❌（受众不在 R6 闭集） | — | **不触发并列**，受众按 §3 梯队排后续轮次 |
     | 数据风险 + ASK **抽取字段**（P1 内容细节） | ❌ | — | 不触发并列 |
     | **资金风险 + ASK 费用授权**（谁有权下单 / 单笔与总额上限） | ✅ | ✅ | **同轮 TEACH + ASK 费用授权** |
     | **不可逆风险 + ASK 不可逆操作边界**（是否允许真实执行） | ✅ | ✅ | **同轮 TEACH + ASK** |
   - **多个阻塞项重叠时（≥2 个）**：同轮 **最多 ASK 2 个阻塞项**（依 R4 ≤3 题，留 1 题余量），**按 §3 梯队 + §11.6 取上游者优先**；**梯队与上游关系都无法区分时，按"后果不可逆程度"排序取前 2**（不可逆 > 费用/权限 > 范围）；其余阻塞项**必须同轮以一行列出并标注「本轮未拍板」**，**不得静默顺延**（静默顺延 = 违规）。
   - **与 R6 的关系（V0.3.7 同步）**：R6 要求阻塞项"必须用户拍板"这一点不变；§3.1 只规定**同轮的拍板顺序与题量**——同轮最多拍板 **2 项**，第 3 项起须显式标注「本轮未拍板」，且**下一轮必须拍板**。执行者不得以 R6 为由一次问 3 题。
   - **R6 闭集的边界（V0.3.6）**：R6 只覆盖**产品级边界与对外约束**（目标 / 范围 / 权限 / 费用 / 数据用途 / 不可逆操作）；**P1 内容细节（字段、布局、文案、命名）、P2 技术实现细节不属于 R6**，不得借"阻塞"名义抢位。
   - **禁止**：把阻塞项整体推后（`strategies/teach.md` 反模式明令）；不得借并列夹带**非阻塞**的普通 P0 问题。**TEACH 前置只是让用户带着后果去拍板，不是代替或推迟拍板。**
   - **"当轮容量已满"的判定条件（V0.3.5，取消原模糊豁免）**：**只有**同时满足"同轮已含 1 个 TEACH 块 + 1 组 SHOW + 2 题阻塞 ASK"才算满（R4 上限）；未达此条件时**不得**以"容量"为由顺延阻塞项；确因容量顺延的，**必须显式写出顺延原因与下一轮承诺**。
3. **TEACH 与 R11（P0 锚点缺失）同时命中**：高风险 C 前置**优先于 R11**，但同样按第 2 条并列——**先 TEACH，紧接 ASK 产物（≤1 题）**；不要求把 ASK 推到下一轮。
4. TEACH 完成后 **重跑决策树**（R9），决策记录记 `taught`（阻塞项的 ASK 另记一行 `asked`）。
5. 该缺口后续走向三选一：
   - **需要用户判断** → **ASK**（正常进入 ASK 通道，按 §3 梯队排序）；
   - **用户明确"暂不考虑"** → 记录为「待确认假设」或「暂不做」+ 写明原因（R12）；
   - **用户已被教会且自行决定** → 记 `用户已确认`。
6. **"本轮先做 TEACH"不排除同轮 SHOW —— 但 ASK 阻塞项优先**：若同轮还有 Type B 的模糊词缺口、且其**产物锚点已有依据**，按 R4 / §11.0 规则 6 顺序 `INSPECT → SHOW → TEACH → ASK` 执行。
   - **冲突处理（V0.3.5）**：若同轮还需 ASK 阻塞项，而 §11.0 规则 7 要求"SHOW 的结果必须先处理完才能展开 ASK"，则 **SHOW 让位到下一轮**（阻塞项不得让位）；即该轮为 `TEACH → ASK`，SHOW 顺延。
   - **产物锚点缺失时不 SHOW**（R11）。

**防膨胀闸门（硬约束，违反即算事故）**：

- **一次 TEACH ≤3 条**；**"条"的单位 = 一个缺口维度**（同一维度下的子项合成一条）。
- **同一维度 ≤1 次**；**累计 ≤2 轮**。二者**独立计数**：
  - **"轮"的计量口径**：**整个采访中 TEACH 出现的轮次数上限**（与缺口数量无关）；
  - **"同一维度 ≤1 次"优先于"用户追问"**：用户主动追问同维度时，**可再讲 1 次**（仍受"累计 ≤2 轮"限制），**不得**无限续期。
- **禁止清单式恐吓**：不得输出与用户目标无关的风险目录；每条 TEACH 都要能回答"这条会影响你哪一步"。
- **普通 C 不得抢阻塞 A**：只有**三闸门全过**的高风险 C 才能与阻塞项并列；**普通** C（未过高风险五类）一律让位，阻塞项先问。

**归因说明（避免误引）**：本节第 1–3 条对"同轮不叠加普通 P0 ASK"的限制，属**§3.1 特别规定**（从严），**不是** R4 的要求 —— R4 本身**允许**同轮 1 TEACH + 1 SHOW + 1 ASK。引用时请写"§3.1 第 1–2 条"，不要写"违反 R4"。

**回归案例（固定，见 `tests/high-risk-c.md`）**：① 高风险 C 抢普通 ASK；② 普通 C 不抢 P0 ASK；③ TEACH 后进入 ASK；④ TEACH ≤3 条且讲后果；⑤ 同一维度不重复教学；⑥ 高风险 C 与 R11/R6 同时命中 → 同轮先 TEACH 再 ASK。

## 4. 决策树（判定顺序，逐条短路）

```
Step 1  用户是否已明确说清，且无冲突？            → 是：Type D → 不动作，进规划/组装
Step 2  答案是否客观存在于可读环境？              → 是：Type E → INSPECT
Step 3  用户是否已用形容词/感受/参照物表达目标？   → 是：Type B → SHOW
Step 4  用户是否提了待定项，或承认还没定？         → 是：Type A → ASK
Step 5  是否存在用户未意识到、且踩空会造成返工的缺口？
        是（含风险/不可逆）：Type C → TEACH → 输出后按 Step 2–4 重新分类
Step 6  是否当前无法确认、须由执行结果回答？       → 是：DISCOVER（写入产物）
Step 7  以上皆非                                    → 该缺口暂不处理或标「暂不做」
```

**判定顺序说明**：Step 1 必须最先走——已经说清的东西再问一次是采访事故。
Step 3 排在 Step 4 前面：用户说"要高级感"时，如果他在同一轮里还提了"数据库选哪个"，**先处理 SHOW 再处理 ASK**（视觉方向会改变后续哪些技术问题值得问）。
**但 P0 语义整类缺失时例外**（见 §3 例外块）：先 ASK 目标，SHOW 让位 —— 目标决定"哪种方向算对"。

## 5. 冲突与组合规则

| # | 规则 | 说明 |
|---|---|---|
| **R1** | **能查不问** | 任何情况下，可读环境中的事实一律 INSPECT，不得包装成问题问用户 |
| **R2** | **能选不追** | 命中 Type B 后，**同轮内不得再出现"你所说的 X 具体是指什么"**；SHOW 之后只接收选择/修改/混搭 |
| **R3** | **先教再问** | 命中 Type C 时，先 TEACH 补齐认知（≤3 条），再决定该缺口的后续动作；**不得跳过 TEACH 直接问**用户答不出的问题 |
| **R4** | **同轮有容量、且有顺序** | 同轮最多 1 个 TEACH 块 + 1 组 SHOW + 1 组 ASK（≤3 题）。**同轮内动作顺序依动作优先级，不依决策树 Step 序**：`INSPECT → SHOW → TEACH → ASK`。其中 **TEACH 恒先于 ASK**（用户不知道有这个缺口时，先教再问，否则用户是在信息不全时作答）。**SHOW 与 ASK 同轮时，SHOW 的结果必须先处理完才能展开 ASK**；同一缺口内不得对已 SHOW 的模糊词追加 ASK。 |
| **R5** | **混合处理** | 一个缺口可同时具备两种性质（如"要高级感"= B + C：能判断 + 不知道有哪些方向可判断）。**动作按决策树所取的主导类型执行，另一性质只作备注**，不得同时展开两套 |
| **R6** | **阻塞项不可 DISCOVER；且必须拍板** | 目标、范围、权限、费用、数据用途、不可逆操作 → 必须用户拍板（与 `SKILL.md` §6.3 口径一致）。**同轮并列场景见 §3.1 第 2 条**：同轮最多拍板 **2 项**，第 3 项起须同轮显式标注「本轮未拍板」，**下一轮必须拍板**；不得以 R6 为由一次问 3 题 |
| **R7** | **Type B 的升级路径** | SHOW 一轮后用户仍无法判断 → 提高保真度再 SHOW 一次（示意 → 更具体草案）；**两轮仍不行**才按 §3.2 走默认值并写入「待确认假设」 |
| **R8** | **未解决仍计数** | 分类不改变 unresolved 规则：ASK 被回避记 unresolved；SHOW 无反应按未答处理；INSPECT 失败标"未核实"并保守缺省 |
| **R9** | **发现即重分类** | 用户补充信息、INSPECT 读到新事实、TEACH 后用户表态 → **立即重跑决策树**，不得沿用旧分类 |
| **R10** | **必须留痕** | 每个被处理的关键缺口都要在决策记录里写 `类型 + 动作 + 依据 + 结果`；只写"已澄清"不算 |
| **R11** | **P0 语义例外（V0.3.1 / P0 分级见 V0.3.3）** | **锚点槽位「要什么产物」无依据 → 先 ASK 产物，SHOW 让位**；**修饰槽位「给谁用 / 怎么算成功」缺失不单独触发本例外**（产物已锚定 → 不冻结 SHOW，方向须对受众/成功中立，同轮说明后续仍需确认）。**与 R1 的优先级（V0.3.2 裁定）：先扣除可读环境证据再判缺失** —— 若目标可从 README / 配置 / 既有产物**只读查明**，该槽位**不算缺失**，走 INSPECT（R1 优先），不得拿 R11 去问用户。**与 R3 的优先级（V0.3.3 裁定；V0.3.5 修订为并列执行）**：同时存在高风险 Type C 缺口时，先按 R3 走 TEACH（≤3 条），**同一轮紧接 ASK 产物（≤1 题，依 §3.1 第 3 条）**——**不再顺延到下一轮**。本例外优先于 R11 的"SHOW 让位"表述 |
| **R12** | **备注中的 Type C 不得永久搁置（V0.3.1）** | 依 R5 被降为"备注"的 Type C 性质，**必须在随后 1–2 轮内以 TEACH 处理**，或在决策记录中显式标为「暂不做」并写明原因；**不得静默丢弃**。高风险类（资金、权限、数据用途、幻觉、不可逆操作）优先于其他待办。**计时起点（V0.3.2 裁定）：从"该备注产生的这一轮"的下一轮起算** —— 即备注出现在第 N 轮，则第 N+1 轮必须 TEACH（最迟 N+2 轮内完成 TEACH 或标「暂不做」）；用户当轮已在回答其他问题时不得打断，但不得因此顺延超过 1 轮 |
| **R13** | **多来源冲突时只报冲突、不裁决、不改问用户（V0.3.1）** | INSPECT 读到多个来源互相矛盾时：标「部分核实」，**并列列出各来源与其出处**，说明冲突点与影响；**不得**替用户择一，**不得**把冲突转成问题去问用户（仍受 R1 约束）。是否升级为用户决策，按该冲突是否改变目标/范围/权限判断（是 → 转 Type A 走 ASK） |
| **R14** | **高风险 Type C 前置（V0.3.4–6）** | **Type C 不默认优先于其他未知**，且**只适用于风险/后果类缺口**（语义槽位一律走 §2 Type A，不进本闸门）。仅当①**高风险五类之一**（重大返工 / 安全 / 合规 / 不可逆架构选择 / 用户目标可能被根本误解）**且**②用户**尚未意识到**（三信号皆无）**且**③该缺口**在本项目中真实存在**（有具体载体+后果）时，**先 TEACH**。**与阻塞项（R6）"指向同一件事"时同轮并列、不推迟**——双条件：**ⓐ被推迟槽位 ∈ R6 闭集**（只含产品级边界与对外约束，不含 P1/P2 细节）**且 ⓑ不拿到它用户无法对该风险知情拍板**；不满足者按 §3 梯队顺延。**与 R11 同时命中同理**。完整判据、计数口径与防膨胀闸门见 §3.1 |

## 6. 决策记录字段（在五状态之上扩展）

**保留原五状态**：`用户已确认` / `证据已核实` / `AI 建议` / `待决定` / `暂不做`

**新增 `Resolution`（消解动作）**，取值仅五个：

```
asked | shown | inspected | taught | discovered
```

**新增 `Unknown Type`（可选，建议填写）**：`A` / `B` / `C` / `D` / `E` / `—`

**记录格式（每条关键缺口一行或一块）**：

```
事项：<缺口是什么>
类型：B（Unknown Known）
动作：shown
状态：待决定
依据：用户说"高级感"，属可判断不可描述；直接追问会诱导用户编造标准
结果：已给 3 个方向（极简科技/黑暗电影/温暖人文），用户选了 B 并要求降低对比度
```

**填写约束**：

1. `动作 = asked` → 状态只能是 `待决定` 或 `用户已确认`；`证据已核实` 不能配 `asked`
2. `动作 = inspected` → 状态应为 `证据已核实`；若只读到部分内容，须写"部分核实"并列出缺什么
3. `动作 = shown` → 未收到选择前状态保持 `待决定`，**不得提前写成已确认**
4. `动作 = taught` → 本身不改变任何需求状态，只追加认知；后续动作另起一行记录
5. `动作 = discovered` → 状态写 `待决定` + 明确"执行阶段验证"，并在产物中落地验证步骤
6. **AI 建议永远不能因为写了 Resolution 就升级成"用户已确认"**

## 8. 反模式（本层新增）

| 反模式 | 为什么错 | 正确做法 |
|---|---|---|
| 对"高级感"连续追问 3 轮 | Type B 用户会开始编造标准，答案不可信 | SHOW 3 个差异明显的方向 |
| 问"你们项目用哪个版本" | 答案在 `requirements.txt` 里，问用户是浪费 | INSPECT 后直接给结论 |
| 用户不懂风险就直接设计功能 | 踩空即返工或不可逆损失 | 先 TEACH（≤3 条）再展开 |
| 把所有缺口都用提问处理 | 单一动作造成采访疲劳、答案质量下降 | 按决策树分类后再选动作 |
| 把能问的都写进"执行阶段验证" | 用 DISCOVER 逃避必须拍板的事 | 阻塞项一律 ASK（R6） |
| SHOW 时直接交付成品 | 采访未完成就出稿，返工成本最高 | SHOW 只给"够判断"的粗略草案 |
| 决策记录只写"已澄清" | 无法复盘、无法判断哪条规则可删 | 写全 类型+动作+依据+结果 |
