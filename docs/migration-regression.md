### ⚠️ 必须如实指出：Case A 与你的期望不一致，且这是**有意的设计裁定**

你在 Case A 要求"ASK P0，不是 SHOW"；V0.3 裁定后判 **SHOW**。原因：

- 你的 Case A 输入**已给出产物**（"官网"）。按 V0.3.3 的 **P0 分级**：**锚点 = 要什么产物**决定方向**本身**是否适用；**受众 / 成功标准**是**修饰槽位**，决定方向的**筛选**，不改变方向的**维度**。
- 因此"官网 + 高级"→ 方向维度成立 → SHOW 合法；受众/成功在选定方向后补。
- 这与你自己在 V0.3 验收里强调的架构一致：**第一层只判 Type，不决定整轮优先级**。若反过来要求"受众缺失也必须先 ASK、冻结 SHOW"，就等于让 Type B 的分类重新被 P0 优先级吞掉 —— 正是你明确要避免的。
- **要点**：`做一个高级 AI 产品官网。` 与已有的 `Test 01`（`做一个高级官网`，判 SHOW）是**同形输入**。若 Case A 判 ASK，会与 Test 01 直接冲突（同一形态、两个"唯一正确动作"）。这是本轮最重要的一致性约束。

**如果你的原意是"产物只有一个类别词（如'东西'/'方案'）时不算锚点"**，那 Case A 仍应判 SHOW（"官网"是**有形态的产物**）；只有 **Case B（"苹果风"无任何产物）** 与 **Case D（"项目"无产物形态）** 才触发锚点缺失。→ 现行裁定正是这个口径。
