# 失败模式 → 规则映射表（V0.1 – V0.3.1）

> **用途**：把每条规则的"存在理由"钉在一个具体的失败模式上。改规则前先查这张表——**找不到失败模式的规则，就是可以删的规则**；找不到规则映射的失败模式，就是漏掉的规则。
> **数据来源**：`SKILL.md` §6.6（决策记录）用途②："复盘时能判断哪条规则没起作用——这是 `docs/failure-map.md` 的数据来源。" 每条关键缺口的 `类型 + 动作 + 依据 + 结果` 记录就是本表的输入。
> **列定义**：
> - **失败模式**：可观察到的错误行为（用户侧或内部记录侧），不是抽象原则。
> - **对应规则**：`SKILL.md` 章节号，或契约 [core/uncertainty-classifier.md](../core/uncertainty-classifier.md) 的规则编号。
> - **验证案例**：能判 PASS / FAIL 的具体案例 ID（含本轮新增的三个专项文件）。
> - **有无测试支撑**：`✅ 有`（有可唯一裁定的案例）／`⚠️ 部分`（有案例但未覆盖全部分支）／`❌ 无`（仅有人工自检条目或口头约定，**没有案例**）。
>
> **⚠️ 命名空间（必读）**：本仓库有**两套独立的 R 编号**，恰好重号：
> - **契约 R1–R13** = [core/uncertainty-classifier.md](../core/uncertainty-classifier.md) 的冲突与组合规则（Type / 动作层）；
> - **核心规则 R1–R8** = `tests/acceptance.md` / `tests/cases.md` 使用的 V0.1 八条核心规则。
>
> **跨文件引用一律写全前缀**（"契约 R3" / "核心规则 R3"），否则本表的映射会串行。契约页首已加同款警示块。
>
> **本轮新增的验证案例来源**：
> - Type B / SHOW 专项：[tests/unknown-known.md](../tests/unknown-known.md)（Test 01–03、UB-04–UB-11，共 11 例）
> - Type E / INSPECT 专项：[tests/evidence-unknown.md](../tests/evidence-unknown.md)（EU-01–EU-10，共 10 例）
> - Type C / TEACH 专项：[tests/blind-spot.md](../tests/blind-spot.md)（BS-01–BS-09，共 9 例）
> - 既有：`cases.md`（T/N 系列）、`acceptance.md`（核心规则 R1–R8）、`adversarial-2.1.md`（A1–A12）、`adversarial-interview-core.md`（B/C/D/E/F + 4 微型判例，21 例）、`adversarial-question-selection.md`（W/I/V/T/S/A，23 例）、`adversarial-merge-questions.md`（M1–M12）
