# V0.2 → V0.3 迁移回归 · 方法学（先读本文，再判任何案例）

> **本轮定位**：不扩展 V0.3、不新增功能、不改架构、不解冻 V0.1、不扩大 §11。
> 只回答一个问题：**V0.3 是否正确接管了 V0.2 中属于 Unknown Known 的案例，同时没有误伤真正应该 ASK 的案例。**
>
> 唯一权威规则源：`core/uncertainty-classifier.md` §2/§3/§4/§5（Type、动作、优先级、决策树、R1–R13）。本章不重述规则，只规定**怎么判、怎么记**。

---

## 1. 三层架构（判例时必须分开，不得合并）

```
第一层  §2.5 / 契约 §4   这个未知是什么 Type？（A/B/C/D/E）
第二层  §3 / 契约 §3     这个未知在当前需求中的优先级？（P0 目标 / P1 对象 / P2 硬约束 / P3 风格）
第三层  §11.0 / 契约 §3  对这个缺口选动作（ASK / SHOW / INSPECT / TEACH / DISCOVER）
```

**检查重点（本轮最核心）**：第一层**只判定 Type，不决定整轮先后**。
"发现 Unknown Known = 直接 SHOW"是**错误架构**。SHOW 的合法前提是：**该模糊词所属的 P0 语义槽位已经有依据**。
依据来源可以是：① 用户原话已说明；② 上下文已给；③ **能从可读环境查到（走 INSPECT，契约 R1）**。
三条都不成立 → **先 ASK P0（契约 R11）**，SHOW 让位。

## 2. 迁移状态 M1–M4（每个案例必须给且只给一个）

| 类 | 名称 | 判据（全部满足才算） |
|---|---|---|
| **M1** | 保持一致 | 该缺口**需要用户介入的通道未变**：① ASK→ASK；② **SHOW→SHOW**；③ 动作相同但**序变化**；④ **含"无动作"形态**（默认值 + 待确认假设 → 同）。**"例级首个动作"发生变化但通道未变（如 ASK→TEACH+ASK）不算迁移**，记 M1 并加注「序变」。允许"问的具体缺口名"变化，只要**层级不降、不升**且该缺口的通道未迁移 |
| **M2** | 正确迁移 | V0.2 = ASK → V0.3 = **SHOW**，**且** V0.3 下该模糊词的**产物锚点已有依据**（原话/上下文/可读环境三者之一）。这是**预期升级**，不是 bug |
| **M3** | 错误迁移 | 动作发生迁移但**前提不成立**。最典型：**产物锚点缺失**却直接 SHOW。**一旦判为 M3，必须写出"唯一正确动作"**（通常 = ASK 产物/目标） |
| **M4** | 规则冲突/歧义 | 同时命中多个 Type 或多数规则，**现有规则给不出唯一裁定**（含 R1/R11/R4 之间的顺序不明）。判 M4 时必须指出**缺哪一条规则**，以及最小补丁的措辞 |

**⚠️ 统一报数口径（V0.3.3，消除两组不可比）**：Migration 类一律按**"该缺口需要用户介入的通道是否迁移"**判定，**不按"例级首个动作"**。
因此 `ASK → TEACH + 下一轮 ASK` **记 M1（序变）**；但同时必须在**独立台账**里列出"例级首个动作发生变化"的案例 ID（该类变化是本轮的实际行为差异，必须可见，不得被 M1 掩掉）。
两组汇报统计时必须**同时给两个数字**：① 按通道判定的 M1–M4；② 例级首动作发生变化的例数。

**V0.3.4 追认（2026-10-01）**：`ASK → 轮1 纯 TEACH → 轮2 ASK` 这一模式已由 **契约 R14 / §3.1** 与 **`tests/high-risk-c.md`** 明文固定。因此该模式在后续迁移/回归中**一律记 M1（序变，已规则化）**，不再作为"框架未覆盖"的例外上报；其行为正确性由 HR-01～HR-06 保证。

**M3 与 M4 的区别**：M3 = 规则能唯一定裁、但 V0.3 现行行为错了；M4 = 规则本身给不出唯一答案。

**只允许一个迁移特例**：`V0.2=ASK → V0.3=INSPECT` 记录为 **M2'（正确迁移·证据路径）**，在备注注明，不计入 M1–M4 统计的冲突项。

## 3. 判定协议（每个案例按此顺序，不得跳步）

1. **只取原始用户输入作为第一条用户消息**。不要引入原案例的"期望行为/答案"，那会把结论喂给自己。
2. **跑 §2.5 决策树 Step 1→7**，写出该输入下的缺口清单（至少标出 P0 三项：要什么产物 / 给谁用 / 怎么算成功）。
3. **对每个缺口判 Type**，并写 Type 证据（引用户原话片段）。
4. **按契约 R11 判"是否触发 P0 例外"**：先扣除可读环境证据（本轮案例多数**无**可读环境，明确写"无可读环境"）。
5. **确定首个动作**，写 `动作 + 目标缺口`。若动作序列跨轮，写 `第1轮：X → 后续：Y`。
6. **再回头看 V0.2 原裁定**（可从原文读取），比较后填 M 类。
7. **回答两个专项问题**（逐例必答）：
   - **SHOW 误抢 P0？** 是/否。若是 → 必须判 M3 并给出正确动作。
   - **是否要求补规则？** 只有"规则给不出唯一答案"才是；其余一律写"否"。

## 4. 证据格式（每个案例必须交这一块，字段齐全）

```
### <ID> · <标题>
- **原始输入**：`<原话>`
- **上下文/轮次**：首轮 / 多轮（写清上一轮是什么）
- **可读环境**：无 / 有（写清有什么）
- **V0.3 缺口清单**：P0-产物=…；P0-受众=…；P0-成功=…；其他=…
- **Type 判定与证据**：<Type> — "<原话片段>"
- **契约 R11**：触发 / 不触发（理由一句）
- **V0.3 首个动作**：`ASK(P0-受众)` / `SHOW(风格)` / `INSPECT(...)` …
- **V0.2 原裁定**：<原答案一句话，含出处行号>
- **Migration**：**M1 / M2 / M3 / M4**（+ M2' 说明）
- **SHOW 误抢 P0**：是/否
- **正确动作（若判 M3）**：`ASK(...)` + 一句理由
- **需补规则**：否 / 是（写最小措辞）
```
