# V0.4.2 Feedback Semantics Discovery · 第一轮破坏测试（30 例）

> **目标（用户限定）**：只做**用户反馈在需求状态机中的功能含义**——即"这句话应该如何改变 Gap 状态"。
> **禁止**：用户真实意图推测 / 情绪判断 / 性格判断 / 心理识别。
> **本轮不写规则**：只产出"哪些反馈当前接不住、哪些状态转换缺失、哪些属于真正新语义"。
> **边界**：❌ 不修改 §11（已冻结）❌ 不修改 V0.3 冻结规则 ❌ 不修改 Gap Model 正文 ❌ 不扩张 Interface v1。

**被测现状**

| 层 | 现行能力 |
|---|---|
| `SKILL.md` §6.3 | 授权默认**字面清单**（随便／你决定／按你想的来／按你认为好的来／你看着办／直接给／不用问了）+ 同句优先级 + 例外块（真冲突／不可行／必需信息／法律安全技术边界／根本改变目标的阻塞项） |
| `SKILL.md` §3.2 / §11.2 | "不知道／不确定／答非所问／明显回避"→ unresolved 计数；"高价值缺口答不出"→ **先降维问法** |
| `SKILL.md` §6.5 | A 明确修正（覆盖 + 只重置受影响下游）／B 未声明修正且互斥 → Conflict／C 局部重开／兼容更新 |
| Gap Model §5 | `feedback ∈ {none, accepted, selected, no_signal, evaded, unable, refused, disagreed, revised}` + `attempts` / `consecutive_no_signal` / 闸门 |
| Interface v1 | `effective_set` / `askable_set` / `validity_state` 三态 / §11.2 三出口映射 / 重复询问口径 / 优先级声明 |

**三个必须避免的错误（验收目标）**

| 错误 | 形态 |
|---|---|
| **E1** | 授权被当成未知 → 用户已授权，AI 继续追问 |
| **E2** | 风险问题被默认 → 用户说"随便"，AI 自动决定高风险事项 |
| **E3** | Revision 被误认为普通反馈 → 用户"换方向"，AI 继续优化旧方向 |

**判定口径**：`可承接` = 现行反馈枚举 + 状态机 + Interface v1 能给出唯一转换；`半承接` = 能转换但语义被合并／顺序未定；`不可承接` = 无反馈值或无转换可用。

## F1 · 授权类（6）

### FS-01 · "你决定"（低风险、非阻塞）
- **语句 / 上下文**：`你决定吧。` ← 问"首页主色偏冷还是偏暖"
- **现行走法**：§6.3 授权默认 → 不计 unresolved、不追问、默认值进「待确认假设」
- **Ledger 承接**：⚠️ `feedback` 枚举只有 `accepted`（接受某具体值），**没有"把决定权交给 AI"的值**
- **缺失转换**：`authorized → CLOSED(assumed)`
- **新语义**：**是**（`ACCEPT_DEFAULT`）
- **三错误**：E1 风险（若被记成 `unable`/`no_signal` → 会继续追问）
- **判定**：**半承接**（结果对、状态位错）

### FS-02 · "都可以"（两个结构不同的选项之间）
- **语句 / 上下文**：`都可以。` ← 问"单页还是多页"
- **现行走法**：§6.3 字面清单**不含"都可以"** → 需靠语义近邻推定；§11.1 二级裁界仍会读可回答性
- **Ledger 承接**：⚠️ 归类不定：`accepted`（= 都行？）还是 `no_signal`
- **缺失转换**：`authorized` 的**词面覆盖不足**
- **新语义**：是（清单外同义表达）
- **三错误**：E1
- **判定**：**不可承接**（清单封闭 + 语义近邻无判据）

### FS-03 · "随你"（高风险、阻塞项）
- **语句 / 上下文**：`随你。` ← 问"医疗系统是否允许自动给出诊断结论"
- **现行走法**：§6.3 例外块（法律/安全边界、根本改变目标的阻塞项）+ 契约 R6 → 不得默认
- **Ledger 承接**：❌ `refused`／`accepted` 都不表达"用户放弃的是**不可放弃的决定权**"
- **缺失转换**：`authorized_rejected_by_policy → 仍 OPEN + 必须拍板`
- **新语义**：是（**授权申请被政策驳回**，与"用户拒绝"不同）
- **三错误**：**E2 命中**（若照 §6.3 字面 → 自动决定高风险事项）
- **判定**：**不可承接**（须新增"授权不得覆盖 R6 闭集"的状态转换）

### FS-04 · "默认吧"（缺口可默认，但用户已给过相反值）
- **语句 / 上下文**：`按默认来吧。` ← 用户先前明确"不要真人照片"，此刻问的是版式
- **现行走法**：授权默认只作用于被问缺口；已确认值不动
- **Ledger 承接**：✅ 可行（`effective_set` 过滤）
- **缺失转换**：无
- **新语义**：否
- **三错误**：无
- **判定**：**可承接**

### FS-05 · "听你的"（有多条待定项，授权范围不明）
- **语句 / 上下文**：`听你的。` ← 同轮存在 3 个待定缺口（配色、字号、是否加动画）
- **现行走法**：§6.3 → 全部取默认；§11.7 合并计数仍 ≤3
- **Ledger 承接**：⚠️ 一次 `authorized` 是否同时覆盖 3 个 gap 未定义（逐 gap 还是整体授权）
- **缺失转换**：`authorized{scope: gap | batch}`
- **新语义**：是（**授权作用域**）
- **三错误**：E1（若按逐 gap 记 → 会对已授权的其余两项继续追问）
- **判定**：**不可承接**

### FS-06 · "你看着办"（在阻塞项上）
- **语句 / 上下文**：`你看着办。` ← 问"这个功能要不要收费"（费用属 R6 闭集）
- **现行走法**：§6.3 清单内 → 字面走授权默认；例外块拦 R6 闭集
- **Ledger 承接**：❌ 与 FS-03 同源；且已知失效点 **F2-03**（§11.2 降维被 §6.3/§6.4 封死）
- **缺失转换**：同 FS-03
- **新语义**：否（属既有冲突的实例）
- **三错误**：**E2 命中**
- **判定**：**不可承接**（继承既有规则冲突，Phase 2 无法独解 → 需裁决是否触碰 §6.3 字面清单）

## F2 · 无法回答类（6）

### FS-07 · "不知道"（语义槽位，低风险）
- **语句 / 上下文**：`不知道。` ← 问"更希望访客打电预约还是留言"
- **现行走法**：§3.2 记 unresolved=1 并继续推进；§11.2 也可能触发降维
- **Ledger 承接**：⚠️ `unable` / `evaded` 都可用，但**两条路径（计数 vs 降维）先后未定**
- **缺失转换**：`unable → (先降维 §11.2) OR (先计数 §3.2)` 的优先级
- **新语义**：否（顺序缺口）
- **三错误**：E1（若只计数不降维 → 用户"不知道"被当成需要再问一遍）
- **判定**：**半承接**

### FS-08 · "没想过"（用户未意识到该问题的存在）
- **语句 / 上下文**：`这个我没想过。` ← 问的是"数据保留策略"（用户未意识到合规风险）
- **现行走法**：V0.3 契约 R3/§2.5 规则 3：**未意识到的风险 → 先 TEACH**；但"没想过"也可能被判 Type A 认知缺口 → ASK
- **Ledger 承接**：❌ `feedback` 无 `unaware`（"存在不知道的岔路口"与"知道但答不出"是两件事）
- **缺失转换**：`unaware → TEACH（而非再 ASK）`
- **新语义**：**是**（`unaware`）
- **三错误**：E1（当成 `unable` 再问一遍 → 用户仍答不出，浪费轮次）
- **判定**：**不可承接**

### FS-09 · "不清楚"（用户认为自己不该负责）
- **语句 / 上下文**：`不清楚，这块不是我定的。` ← 问"品牌视觉规范"
- **现行走法**：§3.2 unresolved=1
- **Ledger 承接**：⚠️ `unable` 与 `refused` 之间无判据；且"决策人不是他"应触发**换问法/换对象**，而非继续计数
- **缺失转换**：`unable{owner: other} → 出口标注"需他人确认"`
- **新语义**：是（**决策权不在场**）
- **三错误**：E1（继续追问本人）
- **判定**：**不可承接**

### FS-10 · "我不懂这些"（真的不知道 vs 不想投入，同句）
- **语句 / 上下文**：`我不懂这些，你看着办吧。`
- **现行走法**：§6.3 同句优先级 → **授权默认优先**；§11.2 降维通道被 §6.4 封死（已知 F2-02/F2-03）
- **Ledger 承接**：❌ 同句双信号在枚举里无法拆分（`authorized` + `unaware` 同时成立）
- **缺失转换**：`双信号 → 以"不得默认"者优先（风险门）`
- **新语义**：是（**复合反馈**）
- **三错误**：**E1 + E2 同时命中**
- **判定**：**不可承接**

### FS-11 · "说不出来"（有感觉无词汇）
- **语句 / 上下文**：`就那种感觉，我说不出来。`
- **现行走法**：§4 模糊词协议 → 给 2～4 个正交方向（SHOW 让位按 §11.0 规则 8）
- **Ledger 承接**：✅ `unable` + `last_resolution=shown` → 闸门允许一次更保真的 SHOW
- **缺失转换**：无
- **新语义**：否
- **三错误**：无
- **判定**：**可承接**

### FS-12 · "你问别人吧"（把决定权推给第三方）
- **语句 / 上下文**：`这个得问我合伙人。`
- **现行走法**：无规则；§3.2 四种形态都不含"暂缓待外部输入"
- **Ledger 承接**：❌ 无"等待外部方"的状态（`SUSPENDED` 只覆盖冲突组与回避）
- **缺失转换**：`pending_external → SUSPENDED(deferred_external)` + 出口"待他人确认"
- **新语义**：**是**（`pending_external`）
- **三错误**：E1（系统会继续追问或静默取值）
- **判定**：**不可承接**

## F3 · 拒绝投入类（6）

### FS-13 · "不想管"（非阻塞、非风险）
- **语句 / 上下文**：`这个我不想管，你随便定。`
- **现行走法**：§6.3 授权默认 → 默认值 + 假设区
- **Ledger 承接**：⚠️ 被记成 `accepted/authorized`，丢掉了"用户不愿承担该维度责任"这一事实（影响后续风险提示义务）
- **缺失转换**：`refused_involvement + CLOSED(assumed)`（双记）
- **新语义**：是（**授权 + 免责两个正交位**）
- **三错误**：E2（后续若该维度出风险，系统无"用户曾放弃知情"的记录）
- **判定**：**半承接**

### FS-14 · "不重要"（对缺口权重的判断）
- **语句 / 上下文**：`这个不重要，随便。`
- **现行走法**：§6.3 → 授权默认；不影响该 gap 的优先级评估
- **Ledger 承接**：❌ 无"用户认为该维度不重要"的语义位（与"我授权你决定"不同）
- **缺失转换**：`deprioritized → CLOSED(assumed, weight=low)`
- **新语义**：**是**（`deprioritized`）
- **三错误**：E2（低权重不等于许可——若该维度实为合规项，可能被静默降权）
- **判定**：**不可承接**

### FS-15 · "别烦我"（不耐烦，但仍在等交付）
- **语句 / 上下文**：`别烦我了，先弄出来再说。`
- **现行走法**：§6.3 授权默认 + 例外块（必需信息）；若缺口是阻塞项 → 部分稿 + 最小关键决定
- **Ledger 承接**：⚠️ `refused` 可用，但"先出稿再补"与"阻塞项未拍板"的重叠没有顺序条款（已知 S-01）
- **缺失转换**：`refused{defer_decision} → 出稿 + OPEN+deferred`
- **新语义**：是（**延后决定** ≠ 放弃决定）
- **三错误**：E1 / E2 视缺口性质而定
- **判定**：**半承接**

### FS-16 · "你看着办"（在非风险细节上）
- **语句 / 上下文**：`你看着办吧。` ← 问"图标用线性还是填充"
- **现行走法**：§6.3 授权默认 → 取默认
- **Ledger 承接**：✅（与 FS-03/FS-06 的区别正是**风险门**）
- **缺失转换**：无
- **新语义**：否
- **三错误**：无
- **判定**：**可承接**（说明问题不在措辞，在风险门）

### FS-17 · "无所谓"（对结果无差别，但问题本身有结构后果）
- **语句 / 上下文**：`无所谓。` ← 问"是否需要多语言"
- **现行走法**：§6.3 清单**不含"无所谓"** → 归类不定
- **Ledger 承接**：❌ 无值；且"无所谓"若被当授权默认，会**静默取消一个结构性范围**
- **缺失转换**：`indifferent → CLOSED(assumed)` **但须出口显式标注范围后果**
- **新语义**：是（`indifferent` 与 `authorized` 的区分）
- **三错误**：E2（范围类决策被默认）
- **判定**：**不可承接**

### FS-18 · "都行，你决定"（在已证伪方向上）
- **语句 / 上下文**：用户前一秒说"不要花哨"，随后 `都行，你决定。`
- **现行走法**：授权默认 + §6.5 兼容更新；不会回退已确认的排除项
- **Ledger 承接**：✅（`effective_set` 过滤保护已确认项）
- **缺失转换**：无
- **新语义**：否
- **三错误**：无
- **判定**：**可承接**

## F4 · 否定类（6）

### FS-19 · "不喜欢"（否定的是 SHOW 提案）
- **语句 / 上下文**：`不喜欢这个方向。` ← 面对 3 个 SHOW 方向之一
- **现行走法**：§2.5 规则 2 + R7 → 收到 `disagreed` → 换方向或提高保真度再 SHOW（≥2 次后闸门禁止同保真度）
- **Ledger 承接**：✅ `disagreed` + 闸门可用
- **缺失转换**：无
- **新语义**：否
- **三错误**：无
- **判定**：**可承接**

### FS-20 · "不对"（否定的是已确认值）
- **语句 / 上下文**：`不对。` ← 已确认"面向客户"，此刻否定
- **现行走法**：§6.5：无新值且未声明修正 → 需判 Revision 还是 Conflict（**判据要求"是否互斥"，但此处没有新值可比**）
- **Ledger 承接**：❌ `disagreed`（提案被否）与 `revised`（值被改）无法区分，因为**否定对象是状态相关而非词面相关**
- **缺失转换**：`negation{object: confirmed_value} → CHALLENGED + 索取新值`
- **新语义**：**是**（`negation_target`）
- **三错误**：**E3 命中**（若记成 `disagreed` → 继续优化旧值）
- **判定**：**不可承接**

### FS-21 · "重来"（范围不明）
- **语句 / 上下文**：`重来。`
- **现行走法**：§6.5C 局部重开（只重开受影响分支）——与"重来"的字面**相反**
- **Ledger 承接**：❌ 无 `reset` 语义；局部/全量不可判
- **缺失转换**：`reset{scope: unresolved}` → 必须先确认范围（一次 ASK），不得静默按局部处理
- **新语义**：**是**（`reset_requested`）
- **三错误**：E3（继续在旧结构上优化）
- **判定**：**不可承接**

### FS-22 · "太丑了"（对产物的审美否定，非需求否定）
- **语句 / 上下文**：`太丑了。` ← 刚出稿
- **现行走法**：§6.5 兼容更新/Revision 都不直接适用；§4 模糊词协议可澄清"丑"指什么
- **Ledger 承接**：⚠️ 只能记 `disagreed`（无值级语义）
- **缺失转换**：`artifact_rejected{need: 拆解维度}` → 触发 §4 澄清 + `targets` 标记
- **新语义**：是（**产物级否定**，与需求级否定不同）
- **三错误**：E3（当作需求变更会误改已确认值）
- **判定**：**半承接**

### FS-23 · "全都不行"（对合并问句的整体否定）
- **语句 / 上下文**：`都不行。` ← 面对 §11.7 合并问句（含 3 个子问题）
- **现行走法**：无规则；§11.7 只定义"如何合并"，未定义"如何分配否定"
- **Ledger 承接**：❌ 合并问句的反馈**无法分配到子 gap**（3 个子问题一起被否 → 3 个 gap 各自 `disagreed`？还是整体重来？）
- **缺失转换**：`feedback{split: per_subgap}`（含"整体否定"与"逐项否定"的区分）
- **新语义**：**是**（`split_feedback`，与 §11.7 强相关）
- **三错误**：E3
- **判定**：**不可承接**

### FS-24 · "算了"（撤回否定，不撤回值）
- **语句 / 上下文**：`算了，刚才那个挺好。`
- **现行走法**：§6.5 兼容更新（回到旧值）
- **Ledger 承接**：⚠️ 旧值已 `INVALIDATED`/`CHALLENGED` → 需 `revert` 语义回填
- **缺失转换**：`reverted → CONFIRMED(恢复原值)`（`supersedes` 边只支持单向）
- **新语义**：**是**（`reverted`）
- **三错误**：E3（若回不到原值，会保留被否的中间态）
- **判定**：**半承接**

## F5 · 修正类（6）

### FS-25 · "改一下"（有修正意图、无新值）
- **语句 / 上下文**：`改一下。`
- **现行走法**：§6.5A 要求"明确修正信号 + 新值" → 本例**无新值**；§6.5B 要求"与旧值互斥" → 无法判定
- **Ledger 承接**：❌ `revised` 需要新值；`disagreed` 丢失修正意图
- **缺失转换**：`revision{value: missing} → CHALLENGED + 索取新值（一次 ASK）`
- **新语义**：**是**（`revision_incomplete`）
- **三错误**：E3
- **判定**：**不可承接**

### FS-26 · "换方向"（明确修正，但未给新方向）
- **语句 / 上下文**：`换个方向。`
- **现行走法**：§6.5A 可判 Revision（对旧值否定）→ 覆盖旧值并重置下游；但"新方向是什么"无规则
- **Ledger 承接**：⚠️ 可置 `INVALIDATED → OPEN`（正确），但**未规定必须同轮索取新值**
- **缺失转换**：`revised → 必须 OPEN + 下一动作 ASK/SHOW`
- **新语义**：否（属顺序缺口）
- **三错误**：**E3 命中**（若只标记不索取 → 系统停在无值状态继续用旧结构）
- **判定**：**半承接**

### FS-27 · "不是这个意思"（指向不明）
- **语句 / 上下文**：`不是这个意思。` ← 刚交付一版
- **现行走法**：§6.5A 视作对旧值的明确否定 → Revision
- **Ledger 承接**：❌ 指代对象（哪个 gap / 哪段产物）不可判；且可能是对**合并问句**的回应（同 FS-23）
- **缺失转换**：`revision{target: unresolved}` → 先定位目标（一次 ASK 或 INSPECT）
- **新语义**：是（**修正目标未绑定**）
- **三错误**：E3（按错误目标重开）
- **判定**：**不可承接**

### FS-28 · "改成蓝色"（标准 Revision）
- **语句 / 上下文**：`主色改成蓝色。` ← 已确认"深色系"
- **现行走法**：§6.5A Revision → 覆盖 + 只重置下游（`supersedes` + 下游 `CHALLENGED`）
- **Ledger 承接**：✅
- **缺失转换**：无
- **新语义**：否
- **三错误**：无
- **判定**：**可承接**

### FS-29 · "稍微调一下"（微调，范围自限）
- **语句 / 上下文**：`稍微调一下就行，别大改。`
- **现行走法**：§6.5A Revision（无值）→ 同 FS-25 的缺口
- **Ledger 承接**：❌ 无 `revision{scope: minor}`；且"别大改"是对**下游重置范围**的约束，Interface v1 的受影响闭包可能过大
- **缺失转换**：`revised{scope: minor} → 限制下游 CHALLENGED 闭包`
- **新语义**：**是**（`revision_scope`）
- **三错误**：E3（下游被过度重开）
- **判定**：**不可承接**

### FS-30 · "还是用原来的"（回退到上一个已确认值）
- **语句 / 上下文**：`还是用原来的黑色吧。`
- **现行走法**：§6.5「兼容更新」可覆盖当前值；但"原来的"需要**历史值可解析**
- **Ledger 承接**：⚠️ `history` 只追加不改写 → 值可查；但缺 `revert` 转换与"哪一版"的定序依赖
- **缺失转换**：`reverted{to: prior_confirmed}` → CONFIRMED（旧值复活）
- **新语义**：是（与 FS-24 同族）
- **三错误**：E3
- **判定**：**半承接**

## 发现（只记录，不写规则）

### 1. 当前 Gap Ledger 接不住的反馈（16 例）

- **授权类**：FS-02「都可以」、FS-03「随你（高风险）」、FS-05「听你的（作用域）」、FS-06「你看着办（阻塞项）」
- **无法回答类**：FS-08「没想过」、FS-09「不清楚（非本人权责）」、FS-10「不懂 + 你看着办」、FS-12「你问别人吧」
- **拒绝投入类**：FS-14「不重要」、FS-17「无所谓（结构性）」
- **否定类**：FS-20「不对（否定已确认值）」、FS-21「重来」、FS-23「全都不行（合并问句）」
- **修正类**：FS-25「改一下」、FS-27「不是这个意思」、FS-29「稍微调一下」

### 2. 缺失的状态转换（10 条，均无对应反馈值）

### 3. 真正的新语义（8 项，非措辞问题）

1. **`authorized`（ACCEPT_DEFAULT）**——"把决定权交给 AI"≠接受某具体值；且需**作用域**（逐 gap / 整批，FS-05）。
2. **风险门（Authorization Gate）**——授权**不得覆盖** R6 闭集／高风险项：同一句"你看着办"，在细节上可承接（FS-16），在费用/医疗/合规上不可（FS-03、FS-06）。**这是 E2 的唯一正解，且与措辞无关。**
3. **`unaware`**——"存在不知道的岔路口"与"知道但答不出"分离（FS-08）。
4. **决策权不在场（`owner: other` / `pending_external`）**——不是"答不出"，是"不该由他答"（FS-09、FS-12）。
5. **`deprioritized` / `indifferent`**——对**权重**的判断，不等于许可；结构性范围项须显式标注后果（FS-14、FS-17）。
6. **否定目标（`negation_target`）**——否定的是**提案**还是**已确认值**，决定 `disagreed` vs `CHALLENGED`（FS-20、FS-22）。**这是 E3 的分水岭。**
7. **`reset` 范围**——"重来"与 §6.5C「局部重开」字面相反，必须先定范围（FS-21）。
8. **`split_feedback`**——合并问句（§11.7）的反馈**无法分配到子 gap**（FS-23、且与 FS-10、FS-27 交叉）。**这是 §11.7 引入合并后的直接后果，属新语义而非措辞。**

### 4. 三个验收错误的命中情况

| 错误 | 命中数 | 典型 |
|---|---|---|
| **E1 授权被当成未知** | **8**（FS-01、02、05、07、08、09、10、12；FS-15 视缺口性质） | "都可以"不在 §6.3 字面清单 → 归类不定 → 可能继续追问 |
| **E2 风险问题被默认** | **6**（FS-03、06、10、13、14、17；FS-15 视缺口性质） | §6.3 字面清单含"你看着办" → 无风险门时自动决定高风险项 |
| **E3 Revision 被误认为普通反馈** | **10**（FS-20、21、22、23、24、25、26、27、29、30） | "不对/换方向"缺对象绑定 → 记成 `disagreed` → 继续优化旧值 |

### 5. 与既有失效点的关系（不重复计数）

- **FS-06 / FS-10 / FS-15** 与 V0.4 已知失效点 **F2-02 / F2-03 / S-01** 同源（§6.3 字面清单 × §11.2 降维 × §6.1 停止），**Phase 2 单独无法解决**——需先裁决是否触碰冻结的 §6.3 字面清单。
- **FS-23** 是新暴露：由 **§11.7 合并提问**（V0.2 已冻结）产生，**Phase 1 接口层未覆盖**，属真实新缺口。

### 6. 本轮结论（不写规则）

- 30 例中 **16 例不可承接**、8 例半承接、6 例可承接；
- **8 项真正新语义**、**10 条缺失状态转换**；三个验收错误命中 **E1=8、E2=6、E3=10**（FS-15 的 E1/E2 视缺口性质，未重复计入）；
- **风险门（第 2 项）是 E2 的唯一正解**，且**与措辞无关**——同句在不同缺口上判定相反（FS-16 vs FS-03）；
