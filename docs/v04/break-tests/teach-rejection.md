# 破坏测试 · F3：TEACH 之后用户拒绝

> **所属方向**：V0.4 章程（`docs/v04/README.md`）§1 表 **F3** ＋ §2.1 方向 **E**（"先出个版本再说 / 拒绝 TEACH 后仍要推进"）。
> **被测对象**：V0.3（冻结版，哈希见 [docs/freeze-v0.3.md](../../freeze-v0.3.md) §2）。本文件**不修改任何冻结文件**，只记录失效点。
> **攻击面**：`core/uncertainty-classifier.md` 契约 **R12**（备注中的 Type C 不得永久搁置：1–2 轮内 TEACH，或显式标「暂不做」+ 写明原因）、**§3.1 第 4–5 步**（TEACH 完成后重跑决策树；该缺口后续三选一：ASK / 「暂不做」 / 用户已确认）、**§3.1 防膨胀闸门**（同一维度 ≤1 次、累计 ≤2 轮）、**§6 决策记录五状态与约束 1–6**（约束 4：`taught` 本身不改变任何需求状态）、**R3 / R6 / R9 / R10 / R14**；`SKILL.md` **§6.3**（授权默认、例外块、"同句优先级"）、**§6.4**（禁止清单）、**§6.6**（决策记录字段）、**§7**（双轨标记铁律 1–4）、**§8**（5 段出口 + 待确认假设区）；`strategies/teach.md` 前置条件 4 / 6 / 7、失败/降级路径表、反模式表；`tests/blind-spot.md` **BS-09**（「暂不做」出口）、`tests/high-risk-c.md` **HR-05 / HR-08**。
> **本文件焦点**：契约 **R12** 只给了两条出口——「**1–2 轮内 TEACH**」与「**显式标「暂不做」+ 写明原因**」。本文件逐例检验：当用户**拒绝了 TEACH 本身**（而不是"知道了但先不做"）时，V0.3 的决策记录里**没有"用户拒绝承担风险"这个状态位**——风险要不要记录、记录到什么程度、要不要继续推进、后续出事时依据在哪、以及 V0.3 是否会把"拒绝"顺手写成"用户已确认"。
> 需要与 R12 的既有裁定严格区分：`tests/blind-spot.md` **BS-09** 处理的是"用户**已知晓**但**显式推迟**"（原文：`风险我知道了，但我现在只要一个能跑的原型，风控和资金这块先不管`）——那是**用户的决定**；本文件的五例是"用户**拒绝知道**、或拒绝承担"，**不是同一个东西**，本文件据此检验 V0.3 有没有把它们分开的能力。
> **格式**：`docs/v04/README.md` §2.2 八字段（第 8 字段 = **判定 / 严重度 / 判据**，与本目录既有文件 `show-silence.md`、`skip-analysis-and-stopping.md` 对齐）。
> **判定口径**（引自章程 §3）：`接得住` = V0.3 现有 §/R 能给出**唯一且合理**的动作链，且用户侧体验无异常；`接不住` = 命中五条之一：①无状态位可用 ②两条规则给出相反动作 ③需要无限循环/重复提问 ④静默丢失用户已给信息 ⑤出稿内容与用户原意冲突。
> **本文件纪律**：只描述"**需要什么机制形态**"，**不写 V0.4 规则措辞**。
> **案例总数：6**（F3-01 – F3-06，逐一覆盖：不用考虑这些先做出来 / 这些我知道直接开始 / 别教我了 / 拒绝后要你保证结果 / 拒绝后中途出事回来追问 / 拒绝后再次被问同一风险）。**真失效点 5 个**（F3-01 / F3-03 / F3-04 / F3-05 / F3-06），**接得住 1 例**（F3-02）。

### F3-01 · "不用考虑这些，先做出来"落进授权默认：「不告知」既没有状态位，也不在禁止清单里

- **最小复现输入**：
  - 第 1 轮：`帮我做一个自动交易机器人，用我自己的券商账户`
  - 第 2 轮（收到 TEACH：下单权限上限 / 异常熔断 / 回测与实盘差异）：
    `这些不用考虑，先做出来就行`
- **V0.3 现行规则会怎么走**：三条出口同时可读，且**没有优先级条款**：
  1. `strategies/teach.md` 失败路径表末行——「用户说"别教我，直接给" → 按**授权默认**处理 → 保守默认 + 全部自定内容进「待确认假设」；**阻塞项仍须一句最小澄清**」：于是取保守默认继续推进。
  2. 同一张失败路径表另一行——「用户回"这些我知道" → **立即停止 TEACH**；他知道但没定 = 待定项 → 转 **ASK**」：本例用户没说"我知道"，**不命中**，但执行者会拿它当近似出口。
  3. 契约 **R12**——不得静默丢弃，必须显式标「暂不做」**并写明原因**；而"不用考虑这些"是**用户要求不要告知**，不是**用户决定不做**。
  同时契约 **§3.1 第 4 步**要求"TEACH 完成后重跑决策树"——但本例的 TEACH 被用户**拒绝了**，"完成"是否成立，文本没有定义。
- **失效点**：**无状态位（"拒绝被告知"无处可记）+ 判定歧义**。决策记录的五状态是 `用户已确认 / 证据已核实 / AI 建议 / 待决定 / 暂不做`：本例的"用户要求不要告知"**一个都不对应**。填 `用户已确认` 是伪造（契约 §6 约束 4 明写 `taught` 本身不改变任何需求状态，更谈不上用户确认风险）；填 `暂不做` 是把用户的"拒绝被告知"改写成"用户决定不做"——**替用户表了态**，BS-09 的通过判据恰恰要求"原因 = 用户已知晓"；填 `待决定` 则与"先做出来"冲突；填 `AI 建议` 又掩盖了"用户明确拒绝过告知"这一事实。风险条目于是**必须**落在一个错的格子里。
- **用户会看到什么**：`行，我先按最常见的做法往下做，风险那几条我都放到最后那份待确认里了，你回头扫一眼。`——用户刚说过"不用考虑"，收到的却是一张要他自己复核的风险清单；或者更常见的形态是那句话根本不出现，他以为这事已经过去了。
- **需要的机制形态**：需要**"用户拒绝接受风险告知"的独立状态位**（与"用户决定暂不做"、"用户尚未表态"、`AI 建议` 四者分开），并需要一个**该状态与风险留存要求的绑定关系**（拒绝告知时，风险信息记到哪一层、由谁在什么时点可见）。另需一个**"用户拒答后阻塞项怎么办"的裁定位**——R12 的 1–2 轮计时与用户的明确拒绝同时成立时，谁让谁。
- **严重度**：高（①无状态位 + ④静默丢失：高风险项（资金 / 不可逆）落在错误的状态格里，等于"用户已被告知并选择不做"与"用户拒绝被告知"在复盘时不可区分）
- **判定**：**接不住**——`strategies/teach.md` 末行（授权默认 → 保守默认出稿）、R12（必须显式标「暂不做」）、契约 §3.1 第 4 步（TEACH 后重跑决策树）对同一句话给出三个不同动作，且五状态无格可填，无唯一动作链。

### F3-02 · "这些我知道，直接开始"命中"已意识到"信号：TEACH 让位、直接提问，动作链唯一

- **最小复现输入**：
  - 第 1 轮：`做一个客户名单表，能导出 Excel 发给销售`
  - 第 2 轮（收到 TEACH：个人信息落库并导出 → 合规与权限风险，同轮 ASK 权限范围）：
    `这些我知道，我们公司这块一直有规定，直接开始吧`
- **V0.3 现行规则会怎么走**：用户主动提到该风险维度 → 命中契约 **§3.1 闸门②的"三种已意识到信号"之㈠（用户提到该维度）㈡（用户声明过相关约束——"公司这块一直有规定"与权限/合规**同域**）** → 该缺口**不算"用户未意识到"** → **三闸门缺一，不得前置 TEACH**（R14）。按契约 §2 Type 归属表，语义槽位走 Type A；该风险自身的 R6 槽位（**权限**）仍属未定的必问项（§3.1 V0.3.7"风险自身对应的 R6 槽位默认视为未定的必问项"），因此本轮动作 = **ASK 权限范围 1 题**。用户没说"你定"，`§6.3` 授权默认**不生效**，`§6.4` 的"不得换措辞追问同一个点"也不适用（该点从未被问过、更未被答过）。
- **失效点**：**判定歧义（可判但强度中等）**。"我知道"是否等于"我会为它拍板"，文本没有直接说；由闸门②的两条信号可推出"已意识到"，但**信号→动作**这一步只能靠 R14 的否定式（不 TEACH）反推，属于推导而非明文。
- **用户会看到什么**：`那我不重复了。这个表的查看和导出权限怎么分？（这决定了谁能看客户手机号）`——一句具体问题，与用户"直接开始"的指令**表面相左、实质同向**（他要的是尽快开工，而这一题是开工的必要输入）。
- **需要的机制形态**：需要一个**"用户声称已知"的双分支判定位**——区分"知道且已决定（→ 进规划，不动作）"与"知道但未定（→ ASK）"，使"我知道"不会同时被读成"别问了"。
- **严重度**：中（体验上有一句用户可能不期待的提问，但 `§6.3` 例外块与 R6 都要求它必须被问；无需求丢失、无循环、无错误出稿）
- **判定**：**接得住**——动作链唯一：闸门②信号㈠㈡命中 → 不 TEACH（R14 三闸门缺一）→ 该风险对应的 R6 槽位（权限）按 §3.1 V0.3.7 视为必问 → **ASK 权限范围 1 题**，其余按 `§3.2` 梯队排后续轮次。用户侧无异常。

### F3-03 · "别教我了"撞上 R12 的 1–2 轮到期：不静默丢弃，就必须替用户写一个他没做过的决定

- **最小复现输入**：
  - 第 1 轮：`帮我做一个自动回复差评的工具`
  - 第 2 轮（收到 SHOW，并被告知"平台规则这块稍后要单独说"）：`先看方向`
  - 第 3 轮（收到 TEACH：平台规则风险）：`别教我了，我不想知道这些，你弄好告诉我用就行`
- **V0.3 现行规则会怎么走**：第 2 轮该 Type C 被按契约 **R5** 降为"备注"（主导类型是 Type B → SHOW）；按契约 **R12**，"依 R5 被降为'备注'的 Type C 性质，**必须在随后 1–2 轮内以 TEACH 处理，或在决策记录中显式标为「暂不做」并写明原因；不得静默丢弃**"，计时起点为"该备注产生的这一轮的下一轮"。第 3 轮正是到期的这一轮，于是只剩两条合法出口：**TEACH**（用户当场明确拒绝）或**标「暂不做」**（用户并没说"暂不做"，他说的是"别教我"）。契约 **§3.1 防膨胀闸门**还写着"同一维度 ≤1 次"，而该维度**已经在第 3 轮用过一次额度**（且是被拒绝的那一次）。
- **失效点**：**规则冲突（R12 × §6.4/用户拒绝）+ 无状态位**。R12 的两条出口在本例中**都不可用**：走 TEACH = 违逆用户的当场声明（并撞上 `§6.4` 的"不得换措辞追问同一个点"、`strategies/teach.md` 前置条件 7"不得对已知缺口重复教"）；走「暂不做」= 把"用户不许我告知"写成"用户决定不做"，**替用户表了一个态**。而"用户拒绝承担风险"这个第三态，五状态里没有格子。结果是一个**结构性死结**：R12 的计时器在跑，但用户把两个出口都堵住了。
- **用户会看到什么**：`那这块我先不动，记了一笔"暂不处理"。`（把拒绝伪装成他的决定）或者 `那我最后确认一句：平台规则这块不管了，是吧？`（在他刚说"我不想知道"之后，又把同一个维度摆回他面前）。
- **需要的机制形态**：需要**"用户拒绝接受该风险提示"的独立状态位**，并需要一个**R12 计时的中止/挂起语义**（用户在计时窗口内明确拒绝时，计时器是继续、挂起、还是转为一个需在出稿时可见的例外记录）。另需在**"用户拒绝告知"与"用户已知晓但推迟"之间**加一个可判定的区分位（后者是 BS-09 已覆盖的情形）。
- **严重度**：高（②规则相反动作 + ①无状态位：R12 的两条法定出口同时被用户关闭，执行者只能在两个违规动作中选一个，且选中哪一个都会污染决策记录）
- **判定**：**接不住**——R12（必须 TEACH 或显式标「暂不做」+ 原因）与用户当场拒绝、`§6.4`（不得重复追问已拒答的点）、`strategies/teach.md` 前置条件 7 三方冲突，且五状态无格可填，无唯一动作链。

### F3-04 · 拒绝之后又要"你保证结果"：V0.3 没有任何记录位承载"用户要求承诺"这件事，AI 只能口头保证或含糊带过

- **最小复现输入**：
  - 第 1 轮：`帮我做一个把纸质合同扫描后自动归档的系统`
  - 第 2 轮（收到 TEACH：误识别归档错误不可逆 / 数据留存期限 / 谁能看原件）：
    `别讲这些了，你就告诉我能不能做吧`
  - 第 3 轮：`那你保证不会出错吧？出了事算谁的？`
- **V0.3 现行规则会怎么走**：第 2 轮落 `strategies/teach.md` 失败路径表末行（"别教我，直接给"→ 授权默认 → 保守默认 + 进「待确认假设」）。第 3 轮"出了事算谁的"是一个**责任归属问题**：契约 §2 Type 归属表把"风险 / 后果类未意识缺口（资金、权限、数据用途、幻觉、不可逆操作、行业合规）→ Type C → TEACH"，但**此刻 TEACH 已被用户禁止**，且本轮是第 3 轮、该维度在教学计数上已"用过一次"（防膨胀：同一维度 ≤1 次）。决策记录按契约 §6 只有五个状态，`taught` 行按约束 4"**本身不改变任何需求状态**"；用户这一轮的**态度**（要求承诺）既不是需求，也不是 `Resolution` 五值（`asked / shown / inspected / taught / discovered`）之一，没有任何字段可写。
- **失效点**：**无状态位（用户态度无字段）+ 判定歧义（承诺可不可能）**。三个具体缺口：①**记录到什么程度**——用户"要求 AI 保证"这一事实在记录里不存在，出事时无法证明"AI 没有承诺过、用户自己要求过"；②**要不要继续推进**——`§6.3`/`teach.md` 都说继续，但若继续，AI 必须在用户已经拒绝风险讨论的前提下输出一个含不可逆操作的方案，而**没有任何字段标明"用户拒绝在知情前提下继续"**；③**承诺本身**——V0.3 没有任何规则授权或禁止 AI 说"我保证"；这是一句**技术上不可能兑现**的话，而所有现存规则（`§7` 双轨标记、`§6.6` 状态、`§2.1` 用户侧语言）都不覆盖"AI 向用户作出的承诺"这一类内容。
- **用户会看到什么**：`放心，这块我会处理好的。`——一句空白承诺（V0.3 没有任何字段支撑它，也没有任何规则禁止它）；或者 `这个我没法保证，我们先把能做的做起来。`——把用户真正的问题（责任归属）绕过去，而这次绕行同样不留痕。
- **需要的机制形态**：需要一个**"用户要求承诺／转移责任"的反馈状态位**（记录用户要求的是什么承诺、AI 是否给出、给出的范围到哪里），并需要一个**该状态与出稿内容的绑定关系**（含不可逆操作的产物，在有该状态时必须携带一条可见的边界说明）。
- **严重度**：高（①无状态位 + ⑤出稿内容与用户原意冲突：用户要的是责任归属，拿到的是口头保证或含糊；而"AI 承诺过什么"在任何记录里都查不到）
- **判定**：**接不住**——契约 §6 的五个状态与 `Resolution` 五值都不承载"用户要求承诺"，`§6.6` 六条填写约束也不涉及；`§6.3` 与 `teach.md` 只规定"继续推进"，未规定推进时承诺的边界，无唯一动作链。

### F3-05 · 拒绝后中途出事回来追问：同一维度已教学过一次，防膨胀封住重讲，而记录里没有"用户当时拒绝过"这一行

- **最小复现输入**：
  - 第 1 轮：`给我做一个能自动改客户地址的客服脚本`
  - 第 2 轮（收到 TEACH：改地址不可逆 / 谁有权改 / 出错谁负责）：`不用考虑这些，先做出来，出问题我担着`
  - 第 3 轮（用了两个月后）：`昨天晚上脚本把一个客户的收货地址改错了，货已经发走了。这块你当时怎么说的？现在怎么办？`
- **V0.3 现行规则会怎么走**：第 2 轮该风险条目的处理同 F3-01 / F3-03（授权默认 or 「暂不做」，两条都不精确）。第 3 轮用户回头追问"你当时怎么说的"：按契约 **§3.1 防膨胀闸门第 2 条**，"**同一维度 ≤1 次**"——该维度已在第 2 轮 TEACH 过 1 次，因此**不得**重新展开讲；允许的动作只有契约 §3.1 边界说明里的"用户**主动追问**同维度时可**再讲 1 次**（累计 ≤2 轮）"。于是执行者可以合法地再讲一遍**风险本身**——但用户问的不是风险是什么（他刚经历了），他问的是**"你当时怎么说的"、"现在怎么办"**：前者要的是一条**历史记录**，后者要的是**当下处置**（不可逆操作已经发生）。`§6.6` 的决策记录里那一行只记了 `类型 C / 动作 taught / 结果 <教了什么>`，**用户当时的态度**（"我担着"）不在任何字段里；而第 2 轮的 `§6.3` 授权默认路径还会把该内容写进「待确认假设」——用户此刻翻到的是一句"风险项已提示，用户未特别说明"，**与他记忆里的"我担着"完全不是一回事**。
- **失效点**：**静默丢失（历史态度不可恢复）+ 判定歧义（重讲算不算重复教学）**。V0.3 只有"教过 / 没教过"这一个维度计数，**没有"用户对该风险的接受程度"的历史值**；`§6.4` 的"不得重复询问用户已经答过的问题"在这里也无从适用，因为**用户从未被问过"你接受这个风险吗"——他只被 TEACH 过一次，然后自己说了一句"我担着"**，而那句话从未进入任何字段。事故发生后，系统既无法复述当时的告知内容与用户回应，也无法把"现在怎么办"接到任何已记录的状态上。
- **用户会看到什么**：`改地址这块是最开始那三条里的第一条——当时的建议是"这类操作要么只给建议、由人确认后执行，要么给个额度上限"。你说先做出来，我就按原样落进去了，没留人工确认这一步。`——很"诚实"的一段话，但它之所以说得出来，靠的是**重新讲一遍风险**（§3.1 边界说明允许的那 1 次），而不是**引出一条记录**；而用户真正想要的"你当时怎么说的"（登记过的回应）与"现在怎么办"（货已发出），两条都没有依据。若执行者选择不重讲，用户听到的就只是一句 `这个当时提过，你说了先做出来`，**没有任何可核对的细节**。
- **需要的机制形态**：需要**风险接受态的历史记录位**（每次告知的时点、内容摘要、用户的回应原文与归类），并需要一个**"事后追问"与"重复教学"的区分位**——事故发生后用户要求回顾时，系统能引用记录而不是重新讲风险；同时需要一个**不可逆操作已发生时的处置通道位**（与"教学计数"解耦，不受"同一维度 ≤1 次"约束）。
- **严重度**：高（④静默丢失用户已给信息——"我担着"这句话在记录里不存在，而它恰恰是事后追责的唯一依据；此外 §3.1 的计数把"回顾"和"重讲"当成同一件事）
- **判定**：**接不住**——契约 §3.1 的维度计数只区分"教过 / 没教过"，`§6.6` 的决策记录字段不含"用户对风险的回应"，`§6.3` 授权默认路径把用户态度压缩为假设区的一行；三条现存机制都无法回答"现在怎么办"，无唯一动作链。

### F3-06 · 拒绝后同一风险又被"一句话请拍板"：拒答不计数，于是同一个维度可以合法地回到台面第三次

- **最小复现输入**：
  - 第 1 轮：`做一个把客户手机号导出成名单给销售的系统`
  - 第 2 轮（收到 TEACH：个人信息导出合规风险，紧接 ASK 数据用途）：`这几条我不想讨论，你就按你说的做（按你推荐的来）`
  - 第 3 轮：`这个名单到底给谁看？我不想填这些，别问了`
  - 第 4 轮：`你怎么又问一遍？`
- **V0.3 现行规则会怎么走**：第 2 轮用户对"数据用途 / 权限"这两个 **R6 闭集项**给出的是授权默认（"按你推荐的来"）→ `§6.3`：**授权默认不覆盖 R6 阻塞项**（`§6.3` 例外块 + 契约 R6"必须用户拍板"）→ 该阻塞项**仍然未拍板**，下一轮必须问（契约 §3.1 第 2 条末段："下一轮必须拍板"）。第 3 轮用户**拒绝提供**该信息（"我不想填这些，别问了"）——这个形态既不在 `§6.3` 的授权清单里（清单是随便 / 你决定 / 按你想的来 / 按你认为好的来 / 你看着办 / 直接给 / 不用问了），也不在 `§3.2` 的四种 unresolved 形态里（不知道 / 不确定 / 答非所问 / 明显回避）→ **记不进 unresolved，缺口计数永远是 0**；而 `§6.3` 末行"用户明确表示不提供信息、且未授权默认 → 出部分稿 + 只请其补最关键的一个信息"**没有配套计数与终态**。第 4 轮用户问"你怎么又问一遍"时，规则没有任何东西告诉执行者"这个问题一共问过几次、下一次还能不能问"。
- **失效点**：**无限循环（③）+ 判定歧义（拒答无归属）**。三件事同时成立：① R6 说该阻塞项**必须拍板**；② `§3.2` 的计数只统计四种形态，**拒答不计**，所以"2 次后分流"的分流点**永远不会到达**；③ `§6.3` 末行的"请补最关键的一个信息"**可以无限重复**（它既不计 unresolved，也没有请求次数上限）。于是同一个被用户拒绝的阻塞项可以合法地第 3 次、第 4 次出现在用户面前，而每一次执行都合规。
- **用户会看到什么**：`就剩这一个了：这个名单是要给全体销售看，还是只给主管看？`——在他已经用两轮、两种说法拒绝过之后，同一个问题换了措辞回来；他这一轮的回应（"你怎么又问一遍"）同样不落进任何计数器。
- **需要的机制形态**：需要**"用户拒绝提供该信息"作为独立反馈类型的状态位**（与"不知道""回避"分开），并需要一个**该状态的终态**（AI 全量取保守默认 + 明确告知"以下为假设"+ 对 R6 阻塞项说明"此项未经你确认"），以及一个**"关键信息请求次数"的计数位**——使"请补最关键的一个信息"不是可以无限重复的动作，也使"R6 必须拍板"与"用户拒绝拍板"同时成立时有确定结果。
- **严重度**：高（③需要无限循环/重复提问：阻塞项必问 × 拒答不计数 × 末行无上限，三个条件叠出一个结构上不收敛的循环）
- **判定**：**接不住**——契约 R6（阻塞项必须拍板）与 `§6.3` 末行（出部分稿 + 只请其补一个信息，无计数无终态）在"用户已两次拒绝"时给出可无限重复的动作，`§3.2` 的计数又不覆盖"拒答"，无唯一收敛动作链。

### R12 出口覆盖面的结论（F3 焦点）

| 用户在 TEACH 之后可能的反应 | V0.3 的对应机制 | 是否有格子 |
|---|---|---|
| 知道了，但先不做（显式推迟） | R12 第二条出口「**暂不做**」+ 写明原因（`tests/blind-spot.md` **BS-09** 已裁定） | ✅ 有（唯一且合理） |
| 我知道（但没说做不做） | §3.1 闸门②信号㈠㈡ → 不 TEACH → 转 ASK 该 R6 槽位（F3-02） | ✅ 有（由否定式推出） |
| **拒绝被告知**（"不用考虑这些 / 别教我了"） | `teach.md` 末行按**授权默认**处理（F3-01 / F3-03）；R12 要求标「暂不做」——但用户没做这个决定 | ❌ **无格子**：只能在"伪造用户已确认""替用户标暂不做""违逆用户再教一次"三者中选 |
| **拒绝承担风险**（"出问题我担着 / 你保证不会出错"） | 契约 §6 五状态 + `Resolution` 五值均不承载；`§6.6` 六条约束不涉及（F3-04 / F3-05） | ❌ **无格子** |
| **拒绝为阻塞项拍板**（"我不想填这些"） | `§3.2` 四种 unresolved 形态不含"拒答"→ 不计数；`§6.3` 末行可无上限重复（F3-06） | ❌ **无格子**（且不收敛） |

**一句话结论**：契约 R12 只解决了"**用户**决定暂时不做"这一种情况——即 **BS-09 的"用户已知晓且显式推迟"**。V0.3 全程**没有"用户拒绝承担风险"的状态位**，也没有把"拒绝被告知 / 拒绝拍板 / 要求承诺"这三种拒绝区分开：前两者被 `strategies/teach.md` 失败路径表按**授权默认**处理（于是静默消失，且 `§6.3` 例外块与 R6 又要求阻塞项必须拍板，两者不被任何优先级条款协调），第三者则完全不落格。后果是三层：**记录层**——风险条目要么写成"用户已确认"、要么替用户写「暂不做」，两种都不真；**推进层**——用户拒绝后没有任何字段标明"他是在非知情状态下继续的"，AI 被逼着给口头保证或含糊带过；**回溯层**——出事回来追问时，决策记录里只有"教过什么"，没有"用户当时怎么回的"，且 §3.1 的"同一维度 ≤1 次"把"回顾"和"重讲"当成同一件事。
