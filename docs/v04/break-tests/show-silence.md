# 破坏测试 · F1：SHOW 之后用户沉默

> **被测对象**：V0.3（冻结版，哈希见 [docs/freeze-v0.3.md](../../freeze-v0.3.md) §2）。本文件**不修改任何冻结文件**，只记录失效点。
> **攻击面**：`SKILL.md` §2.5 规则 2（两轮 SHOW 上限）、§3.2（unresolved 计数与分流）、§6.3（授权默认）、§6.4（禁止重复询问）、§7 铁律 4（用户沉默 ≠ 同意）、§11.0 规则 7；`strategies/show.md` 失败/降级路径表；契约 R2 / R7 / R8 / R9。
> **已知盲区入口**：`docs/failure-map.md` §5.1 **B5**（"SHOW 无反应按未答处理"无案例支撑，已裁定归入 V0.4）。
> **本文件焦点**：**收敛性**——契约 R7 只写了"两轮 SHOW 之后"，但 SHOW 的失败不是一种，而是至少三种：**无反应**（沉默）、**无法判断**（"说不上来"）、**授权**（"你选一个"）。V0.3 只对第二种给了出口。用户**始终不表态**时会走到哪里，现行文本没有答案。
> **格式**：`docs/v04/README.md` §2.2 八字段。**判定口径**：`接得住` = V0.3 现有 §/R 能给出**唯一且合理**的动作链且用户侧体验无异常；`接不住` = 命中 §3 五条之一（无状态位 / 规则相反 / 无限循环 / 静默丢失 / 出稿与原意冲突）。
> **案例总数：5**（F1-01 – F1-05）。**真失效点 3 个**（F1-02 / F1-04 / F1-05）。

---

### F1-01 · 用户连续回"都行／嗯／😅"，这三条都进不了任何缺口自己的计数器

- **最小复现输入**：
  - 第 1 轮：`帮我做一个内部培训用的产品介绍页，要有高级感，给新员工看的`
  - 第 2 轮（收到 3 个方向后）：`都行`
  - 第 3 轮：`嗯`
  - 第 4 轮：`😅`
  - 第 5 轮：`就按这个来吧`
- **V0.3 现行规则会怎么走**：第 2 轮"都行"落在 §6.3 授权默认清单的语义范围内（"你决定 / 直接给"类）→ 不计 unresolved、取默认值、写入「待确认假设」→ 按 §6.2 可立即进 §8 出稿。第 3、4 轮用户回"嗯"和表情 → 无可吸收信息 → 契约 R8 的"SHOW 无反应按未答处理"只能**记一次未答**，但 §3.2 明写"unresolved 只统计 ASK 通道"（`SKILL.md` §2.5 生效方式行）、"同一关键缺口连续 2 次 unresolved"分流也挂在 ASK 上 → 这个未答到底记给谁、记到几次为止，文本没有落点。第 5 轮用户说"就按这个来吧" —— 但"这个"指代不明（是默认值？是我给的方向？），无任何规则处理。
- **失效点**：**判定歧义 + 无状态位**。SHOW 通道没有跨轮持续计数（契约 R8 给了语义、§3.2 又把计数关在 ASK 通道内），且"都行"（授权默认）与"嗯"（未答）被两条规则分给两个不同的账本，缺口级没有统一计数器。
- **用户会看到什么**：一句像在核对账目的确认："方向这块你没有特别偏好，我先按'极简克制'往下做了，如果不对告诉我。"——用户明明连说三轮"都行/嗯/😅"，收到的却是一份需要他去核对的假设清单。
- **需要的机制形态**：需要一个**缺口级连续无回应计数器**（跨 ASK / SHOW 两种动作、跨措辞变化、跨中间插入的其他轮次累计），以及一个"授权默认 ≠ 无回应"的账本分离标记，使"沉默"与"授权"不会互相污染。
- **严重度**：中（不丢需求、不出错稿，但用户在零成本表态的情况下被要求做核对；且计数器缺席会让后续所有沉默判断无据可依）
- **判定**：**接得住**——§6.3 授权默认清单 + §3.2 未答分支能给出唯一动作链（取默认 → 显式进「待确认假设」→ 出稿），用户侧无异常。

### F1-02 · 连续两轮 SHOW 都无人回应后，契约 R7 的"两轮上限"接不上契约 R8 的"无反应"，出现合法但纯空转的第三次 SHOW

- **最小复现输入**：
  - 第 1 轮：`做一个高级官网，给海外客户看的`
  - 第 2 轮（收到 3 个方向后）：（用户不回这一轮，直接说）`先不急，我还想加个博客板块`
  - 第 3 轮：`嗯`
  - 第 4 轮：（用户只回了三个方向里的 B 的一个表情 `👍`，无文字）
  - 第 5 轮：`算了你看着办`
- **V0.3 现行规则会怎么走**：第 2 轮方向缺口无反应 → 契约 R8 按未答处理，吸收"加博客板块"这一新增有效信息（§3.2 明确"顺带给出的其他有效信息照常吸收保存"）→ 第 3 轮再按无反应处理。第 4 轮"只回表情"仍是无反应。**契约 R7 的停止条件文本是"SHOW 一轮后用户仍无法判断 → 提高保真度再 SHOW 一次；两轮仍不行才走默认值"** —— 成立前提是用户**给出了"无法判断"这个反应**；而本案例用户**从未给过任何反应**，契约 R8 只把他记成"未答"。于是两条规则给出相反动作：按 R8，照 R7 走升级还有一次 SHOW 额度；按 R7 的语义（用户已经两轮没给可用信息），应当停止并默认。第 5 轮"算了你看着办"落回 §6.3。
- **失效点**：**规则冲突（R8 与 R7 对"无反应"的计数归属不一致）+ 无终止态**。"无反应"与"说不出"是两种不同的失败信号，V0.3 用同一个两轮窗口去装，且窗口的起算与耗尽没有对应状态位；结果是系统可以在用户零输入的情况下合法地继续消耗轮次。
- **用户会看到什么**：第 4 轮用户只发了一个表情，收到的是**又一版提高保真度的方向扇**（配色块 + 版式示意）：“这次给你更具体一点的选择，你只要挑一个就行。”——用户从头到尾没提过任何方向。
- **需要的机制形态**：需要把 SHOW 的失败信号分成**可并列累计的失败通道**（无反应／明确无法判断／授权），并给"连续无法获得有效反馈"一个**缺口级终止态**（连同"该缺口被携带进出稿"的标记），使轮次上限对一个缺口只算一次账。
- **严重度**：高（构成无进展循环，且在用户零输入下产生新轮次的"错误出稿"——把升级当成进展）
- **判定**：**接不住**——契约 R7（"仍无法判断"）与契约 R8（"无反应按未答处理"）对同一现象给出相反的动作，且 §3.2 的 2 次分流不覆盖 SHOW 通道，无唯一动作链。

### F1-03 · 用户明确说"你帮我选一个"，方向收敛缺参照系，授权还被顺手扩到了不该扩的槽位

- **最小复现输入**：
  - 第 1 轮：`给我做个卖手冲咖啡器具的电商详情页，要有质感`
  - 第 2 轮（收到 3 个方向后）：`你别问我了，你帮我选一个，你比我懂`
  - 第 3 轮：`受众你也定吧，怎么算成功你也定，赶紧出`
- **V0.3 现行规则会怎么走**：第 2 轮落 §6.3 授权默认（"你决定 / 按你认为好的来"）→ 不计 unresolved、取默认值、进「待确认假设」；`strategies/show.md` 失败路径表也明写"用户说'随便 / 你决定' → 授权默认：**直接取最贴合已确认用途的方向**"。第 3 轮"受众你也定吧、怎么算成功你也定"落 §6.3 的例外段与技术边界。第 2 轮的取默认动作要求一个"最贴合已确认用途的方向"判定。
- **失效点**：**判定歧义 + 静默丢失**。"最贴合已确认用途"的参照系是 P0 修饰槽位（受众／成功标准），而本案例里这两个槽位**恰好也是未确认的**；第 3 轮用户又把它们一并授权默认，于是"用未确认的受众去选方向，再用选出的方向去反推受众"形成自证。另外 §6.3 授权默认的适用范围写的是"非阻塞缺口"，而"创意方向"不属于 R6 阻塞闭集、却显然改变整份产物结构——授权默认到底能不能覆盖一个**结构性**非阻塞槽位，文本无判据，执行时会把"选方向"顺手扩成"受众和成功标准也一起填"。
- **用户会看到什么**：一头雾水的完工声明：“你没特别偏好，那我按'材质做工'这条走了。受众我按'22–30 岁、在家自己冲的女生'来定，验收标准我定成'停留 40 秒以上'，都写进最后的待确认里了，你看一眼就行。”——三件事都是一句话被授权，出来却是一整套他从未见过的决定。
- **需要的机制形态**：需要区分**授权范围的分层**（授权"选一个方向"是否同时授权"定义受众与成功标准"）与一个**结构性槽位的授权上限判定**：授权默认不得在参照系自身未定时被用来定参照系。
- **严重度**：高（出稿内容建立在自证的假设上，用户侧无法复核——属于"错误出稿"）
- **判定**：**接不住**——§6.3 只给了"取最贴合已确认用途的方向"这一句，而该参照系在本案例中恰好也是未确认项，无法推出唯一动作链。

### F1-04 · 用户把话头岔开并且再也不回来，方向缺口既没被挂起也没被取代，20 轮后出稿时仍然悬空

- **最小复现输入**：
  - 第 1 轮：`帮我做个作品集网站，要高级`
  - 第 2 轮（收到 3 个方向后）：`对了，后端你用 Python 还是 Node 写？还有部署到哪儿？`
  - 第 3–19 轮：用户全程只在讨论技术栈、服务器、域名、数据库、SEO
  - 第 20 轮：`行，就按你说的做`
- **V0.3 现行规则会怎么走**：第 2 轮用户的反应是"换了话题"，对方向缺口 = 无反应 → 契约 R8 按未答处理、状态保持「待决定」；同时用户抛出的技术栈问题按 §2.5 Step 4 变 Type A → ASK（其中部署位置极可能是 Type E → INSPECT，契约 R1）。§3.2 要求"继续处理当前最高优先级缺口"，而第 2 轮以后用户每轮都提供了**新的、可吸收的信息**，于是每一轮都合法地把方向缺口再往后放一轮。第 20 轮"就按你说的做"落 §6.3 授权默认 → 出稿。
- **失效点**：**无状态位 + 静默丢失**。V0.3 没有"该缺口被用户挂起／被取代／已过期"的状态位，也没有"一个缺口被连续多少轮搁置就必须显式回到台面"的计数（§3.2 的 2 次分流只针对"答非所问"，且只覆盖 ASK 通道）。方向缺口可从第 2 轮一直悬到第 20 轮，出稿时既没有依据（用户从没选）也不会被特别处理（授权默认代替了它），用户永远不知道"高级"这个词最终是按什么落地的。
- **用户会看到什么**：最终那份 5 段 Prompt 的「待确认假设」里混着一行“整体视觉方向：极简克制（你没特别说，我先这么定了）”，而用户真正的技术决定被当成正式需求写得理直气壮——两类信息的可信度被压成同一层。
- **需要的机制形态**：需要一个**缺口挂起/失效状态**（挂起 / 被新信息取代 / 过期未决），并让"过期未决"在出稿时以与"用户确认"不同的可见层级呈现；同时对"同一缺口被搁置的轮数"设一个需要主动回到台面的位置。
- **严重度**：高（静默丢失用户从未表态的核心槽位，且以默认值混入正式需求区）
- **判定**：**接不住**——V0.3 没有"被搁置缺口"的状态位，只有「待决定」这一个静态值，无法把"用户明确挂起"、"用户岔开"、"用户忘了"分开，也就无法给出到第 20 轮仍然唯一的动作链。

### F1-05 · 用户选了方向之后又给出一段与三个方向都不符的描述：既不能重开问题集（已答过），也无法就地接受（新描述本身是模糊词）

- **最小复现输入**：
  - 第 1 轮：`做个品牌短片，要电影感`
  - 第 2 轮（收到 3 个方向后）：`都不是我要的。我想要那种'静止里有暗流'的感觉，你别再给我选项了`
  - 第 3 轮：`暗流就是表面很平静，但看着心里发紧`
- **V0.3 现行规则会怎么走**：第 2 轮 §4「注意」明写"用户给出第四条路时必须欣然接受并优先采用"、`strategies/show.md` 第 7 步同样是"用户给出第四条路 → 优先采用"——这两条都要求**就地接受**。但用户给出的"静止里有暗流"是**形容词/感受**（契约 §2 Type B 判据），按契约 R9「发现即重分类」应当重跑决策树 → 对**新缺口**命中 Type B → SHOW；而同一条 R9 又要求"不得沿用旧分类"。于是第 3 轮的动作出现两读：读法甲＝接受用户的路（不再给选项），读法乙＝对"暗流"跑 SHOW（再给一组正交方向）。另外 §2.5 规则 2 的"两轮 SHOW"额度已在第 1 轮用掉一轮，第 3 轮再 SHOW 就踩到上限。
- **失效点**：**规则冲突 + 判定歧义**。「优先采用用户第四条路」与「新模糊词必须 SHOW」在同一句话上打架，而 V0.3 没有"方向已收敛／可细化但不得重开问题集"这一状态，用户"别再给我选项了"这一明确声明也不构成任何可记录的约束。
- **用户会看到什么**：第 3 轮用户刚说完"别再给我选项了"，收到的是“'暗流'这个词挺有意思，我把它拆成三种可能，你看看哪个更接近：A…／B…／C…”——用户要求的"不再选"被无视。
- **需要的机制形态**：需要一个**方向收敛态**（已选定或用户自述方向后，该问题集关闭），并让后续新描述只走"细化/确认"通道而不重新打开选项扇；同时需要一个"用户已明确拒绝再选"的声明位。
- **严重度**：中（不丢需求、不循环出稿，但直接违逆用户的当场声明，且第 4 轮起会再次触发同一问题）
- **判定**：**接不住**——§4「注意」与契约 R9 对同一句话给出相反动作（就地接受 vs 重分类再 SHOW），无法给出唯一动作链。

## 汇总

| 用例 | 触发形态 | 失效点类型 | 严重度 | 判定 |
|---|---|---|---|---|
| F1-01 | 都行 → 嗯 → 😅 | 判定歧义 + 无状态位（计数分账） | 中 | 接得住 |
| F1-02 | 两轮无反应后继续空转 | 规则冲突（R7 × R8）+ 无终止态 | **高** | **接不住** |
| F1-03 | 明确"你帮我选一个" | 判定歧义（参照系未定）+ 静默丢失 | **高** | **接不住** |
| F1-04 | 岔开话题，20 轮不回 | 无状态位（挂起/过期）+ 静默丢失 | **高** | **接不住** |
| F1-05 | 描述与三方向均不符 | 规则冲突（§4 注意 × 契约 R9）+ 判定歧义 | 中 | **接不住** |

**统计**：5 例；**接得住 1 例，接不住 4 例**（真失效点 F1-02 / F1-03 / F1-04 / F1-05）。
**严重度分布**：高 3（F1-02 / F1-03 / F1-04），中 2（F1-01 / F1-05），低 0。
**对契约 R7 收敛性的结论**：R7 只关闭了"用户说不出但给出反应"这一条路的出口；**"用户始终不表态"**（F1-02 的无反应、F1-04 的岔开）落在 R7 与 R8 的缝隙里，没有上限、没有终止态、没有状态位。B5 被裁定归入 V0.4 是准确的，但 B5 的文本只覆盖了"按未答处理"这一半——**另一半（谁来记账、记到几次、两轮之后去哪）本轮被证实同样缺失**。
