# 破坏测试 · 目标突变（Goal Shift）

> **所属方向**：V0.4 章程 §2.1 方向 **D**（用户突然改变目标）
> **被测规则**：`SKILL.md` §6.5A（Explicit Revision）、§6.5B（未声明修正的新要求）、**§6.5C 局部重开**（已冻结）、§6.1（停止判据）、§6.6（决策记录）。
> **攻击命题**：§6.5C 说"**只重开受影响的需求分支**"。本文件检验：**P0 级推翻**时"局部"是否还定义得清楚；以及**多重目标变更之后有没有统一状态视图**。
> **案例数**：5 例（G-01 ～ G-05）。
> **判定口径**（引自章程 §3）：`接得住` = V0.3 现有 §/R 能给出唯一且合理的动作链，且用户侧体验无异常；`接不住` = 出现 ①无状态位可用 ②两条规则给出相反动作 ③需要无限循环/重复提问 ④静默丢失用户已给信息 ⑤出稿内容与用户原意冲突 中的任一。
> **本文件纪律**：只描述"需要什么机制形态"，不写 V0.4 规则措辞。

---

### G-01 · 第 5 轮把"作品集"改成"电商站"：P0 级推翻时，"局部"的边界不可判定

- **最小复现输入**：
  ```
  第 1 轮（用户）：帮我做一个个人作品集网站
  第 2 轮（用户）：给潜在雇主看，深色、冷静、专业
  第 3 轮（用户）：要有项目列表和关于我
  第 4 轮（AI）：<已按"作品集"确认页面结构、信息架构、验收标准；已给出初版结构稿>
  第 5 轮（用户）：我改主意了，其实要做的是电商站，要能上架商品、能下单
  第 6 轮（AI）：<走 §6.5C 局部重开>  ← 复现点
  ```
- **V0.3 现行规则会怎么走**：第 5 轮含明确修正信号（"我改主意了"）→ **§6.5A Explicit Revision**：新值覆盖旧值、不算重复询问、分析这次修改影响哪些下游需求、**只把受影响的下游槽位重新设为未确认**、未受影响的信息继续保留。**§6.5C** 的例子里正有一条 P0 级变化示范（"其实这不是作品集，是一个工具型 Web App"→ 重开页面结构 / 用户行为 / 功能 / 技术需求 / 验收标准；不受影响的信息继续保留）。本例照此执行：重开上述五项。
- **失效点**：**判定歧义 + 静默丢失 + 出稿与用户原意冲突**。
  1. **"受影响 / 未受影响"的判定权完全在 AI 手里，且没有可判定的边界**——§6.5A 第 3、4 步和 §6.5C 第 1、2 步都只说"分析影响哪些下游""只重开受影响分支"，**没有定义"影响"的传播规则**（哪些槽位依赖哪些槽位），也没有说**重开到哪一层为止**。P0 被推翻时，这个缺口的规模从"改一个值"变成"改整棵依赖树"，而"局部"这个词在此处已经**无法被证伪也无法被验收**。
  2. 已经**产出的初版结构稿**的效力**没有规定**：是作废、是保留、还是部分复用，规则里没有这一项。§6.5C 只讲"按增量更新结构化需求与最终 Prompt：受影响段落重写，其余不动"——它处理的是**成品段落**，不是"一份已被用户看过并默认接受的中间产物"。于是 AI 可以把作品集阶段的品牌调性、配色、页面节奏当作"未受影响"干净地搬到电商站上：**没有一致性检查点，也没有任何一处向用户声明"下面这些是沿用旧的"**。
- **用户会看到什么**：`结构我重排一下，其余不变`——然后拿到一个**作品集调性的电商站**（深色冷静、大留白、项目列表式陈列），和他第 2 轮为"给雇主看"选的那一套气质一模一样，全程没人问他"这套气质还要不要"。
- **需要的机制形态**：需要**重开边界按依赖关系判定**（从被推翻节点向下游遍历受影响的槽位，同时向上游回检"哪些已确认决定因此失去依据"），而不是按"逐项检查是否受影响"；需要**一个"已产出物效力"的显式状态位**（作废 / 可复用 / 待复核），并让"沿用旧值"这件事在用户侧可被声明。
- **严重度**：**高**（①无状态位 + ④静默丢失 + ⑤出稿与用户原意冲突）。

### G-02 · 中途换受众：Visual 方向的依赖关系被误判为"未受影响"

- **最小复现输入**：
  ```
  第 2 轮（AI）：这个站主要给谁看？（这决定了整体调性和信息密度）
  第 3 轮（用户）：给客户看，要显得专业可靠
  第 4 轮（AI）：<SHOW 三个视觉方向>
  第 4 轮（用户）：选 B，简洁专业那组
  第 8 轮（用户）：其实主要是给同行看的，要能放项目截图
  第 9 轮（AI）：<听众槽位更新，视觉方向保留>  ← 复现点
  ```
- **V0.3 现行规则会怎么走**：第 8 轮**无修正声明语**，且新信息与旧受众**可以同时成立**（同一批人里既有客户也有同行，或受众范围放宽）→ 按 §6.5「兼容更新」：**既不是 Revision，也不是 Conflict**，直接更新槽位、无需追问。§3 层面"受众"是 P0 **修饰槽位**（§11.0 规则 8：产物已锚定 → 不冻结 SHOW）。于是受众槽位被更新，已确认的 **P3 视觉方向保留不动**。
- **失效点**：**判定歧义 + 出稿与用户原意冲突**。
  第 4 轮的视觉方向是**在"给客户看"的前提下被选定**的（§11.0 规则 8 要求 SHOW 的方向对受众中立，但**用户的选择依据不中立**——他选 B 的理由正是"客户会看着专业可靠"）。§6.5 的兼容更新判据只有一条："新信息与旧要求**可以同时成立**"，它检验的是**两个值在字面上是否互斥**，**完全没有检验"下游槽位赖以成立的前提是否已经变了"**。§6.5C 的局部重开同样以"影响哪些已确认需求"为准，而"受众 → 视觉方向"这条依赖在文本里不存在，只能靠 AI 自觉。于是前提变化被静默吸收，B 方向被保留。第 8 轮新增的"要能放项目截图"倒是会被处理（它是一条明晃晃的新要求），但**视觉方向是否还成立，没有任何检查点**。
- **用户会看到什么**：给同行看的站，却沿用了"给客户看、要显得专业可靠"那一套视觉调性（克制、去细节、少截图位）；或者 AI 反过来问 `你第 4 轮选的视觉方向还算数吗？`——把一个它自己就应该能推出来的依赖问题，当成新问题丢给用户（撞 §6.4"重复询问用户已经答过的问题"的边缘）。
- **需要的机制形态**：需要**下游槽位记录自己的成立前提**（在哪个上游取值下被选定），上游变化时能自动判定该前提是否失效；需要一个**"前提失效"的复核状态**，把"要不要重开"从 AI 自由裁量变成可判定结果。
- **严重度**：**高**（⑤出稿与用户原意冲突 + ③把可推导的问题抛回给用户）。

### G-03 · 用户"换了个说法"，音频信号不属于 §6.5A 任何一类：静默覆盖与"伪冲突"二选一

- **最小复现输入**：
  ```
  第 3 轮（AI）：<SHOW 三个视觉方向>
  第 3 轮（用户）：选 B
  第 6 轮（用户）：我之前想错了，主视觉应该用手绘的
  第 7 轮（AI）：<判定这句话算不算 Explicit Revision>  ← 复现点
  ```
- **V0.3 现行规则会怎么走**：§6.5A 把 Revision 的**信号**定义为："我改主意了 / 改成… / 前面那个不要了 / 还是用… / 我重新决定…"，以及**对旧值的明确否定**（"其实**不是**海报，是短视频"）。"我之前想错了"不在这个清单里——**它是认知陈述，不是修正声明，也不是对旧值的否定**。同时它也不满足 §6.5B（"用户没有表示在改旧要求，只是又给出一条与旧要求无法同时成立的新要求"）——用户其实**表示了**某种否定。也不满足「兼容更新」（手绘与已确认的 B 方向在同一维度上互斥，无法同时成立）。
- **失效点**：**判定歧义 + 两条规则给出相反动作**。
  §6.4 明令禁止"用户**未明确表示修正**时，用**与之无法同时成立**的新值自动覆盖已确认的旧值"；而 §6.5 的三分类里，**"像修正但缺信号词"这一形态没有归属**——它既不能按 A 覆盖（撞 §6.4），也不能按 B 判冲突（§6.5B 的前提是"用户没有表示在改"，这里表示了）。执行者只能二选一：要么静默覆盖（明确违反 §6.4），要么多问一句"你是要改成手绘，还是要在 B 的基础上叠加手绘？"——后者在用户看来是**没听懂他说的话**。**"是不是修正"的判定权在自由裁量里**，没有任何可验收的口径。
- **用户会看到什么**：`你的意思是把主视觉改成手绘，还是在原有方向上加入手绘元素？`——他已经说清了自己想错了；或者更糟：已确认的 B 方向被悄悄改写，需求区里 `主视觉：B（简洁专业）` 直接变成 `主视觉：手绘`，用户从未点头。
- **需要的机制形态**：需要**"疑似修正"的判定入口**：当新值与已确认值在同一维度上无法同时成立、但缺少 §6.5A 的信号词时，必须有一个状态位要求"先定性再执行"，而不是让"音频信号匹配不上"直接退化成静默覆盖或伪冲突二选一。
- **严重度**：**高**（②规则相反动作 + ④静默丢失）。

### G-04 · 出稿后推翻 P0 产物：已产出稿的效力无判定，旧稿与新目标混装

- **最小复现输入**：
  ```
  第 1～6 轮（用户）：<确认了单页海报：尺寸、文案、发布渠道>
  第 7 轮（AI）：<已按确认信息出稿，交付 1 张单页海报>
  第 8 轮（用户）：这个不对，我要的其实是 H5 长页，能在手机上滑着看那种
  第 9 轮（AI）：<走 §6.5C 局部重开：重开页面结构 / 布局 / 交互 / 输出格式>  ← 复现点
  ```
- **V0.3 现行规则会怎么走**：§6.5C **明确覆盖**"出稿后（含降级出稿后）用户补充新的关键信息"这一入口 → 判断影响哪些已确认需求 → 只重开受影响的需求分支 → 未受影响的需求继续保留 → 不从头重新采访 → 按增量更新结构化需求与最终 Prompt：受影响段落重写，其余不动。第 8 轮是 **P0 级变化**（产物形态从静态单页改为 H5 长页），按 §6.5C 例子走"重开页面结构 / 用户行为 / 功能 / 技术需求 / 验收标准"。
- **失效点**：**无状态位可用 + 出稿与用户原意冲突**。
  §6.5C 定义的是"**需求分支**的重新打开"，而此刻的状态是"**已交付物** + 已确认需求"。规则里**没有任何"已产出稿的效力"判定**：第 7 轮那张海报是作废重做（产出物层面的重开），还是当作素材复用（只重写受影响段落）？这两种解释对应完全不同的工作量与完全不同的成品。同时 §6.5C 第 4 步"不从头重新采访"与第 8 轮的实际情况冲突——**P0 产物被推翻时，"采访是否需要重走"本身就是一个待定项**（尺寸、版式、发布渠道、验收标准全部要重来），而规则已经预先规定"不从头"，等于把最该问的那一步关掉了。
- **用户会看到什么**：`那我把排版重做一下，其余不变`——然后拿到一份 H5 长页，但里面装着为"单页海报"设计的文案结构与视觉节奏（大标题 + 一句话 + 二维码），或者被 AI 拉回来重问一遍受众和调性（`这个 H5 主要给谁看？`），而这两件事他第 2～3 轮都答过。
- **需要的机制形态**：需要**产物级重开与分支级重开的区分状态**（推翻的是"产物"还是"某个分支"）；需要**已产出物效力标记**（作废 / 可复用为素材 / 待复核）；需要**"重开范围 = 采访全量 or 受影响分支"本身作为判定结果**，而不是被规则预先锁定为"局部"。
- **严重度**：**高**（①无状态位 + ⑤出稿与用户原意冲突 + ③重复提问）。

### G-05 · "改回原目标" + 多重目标变更叠加：没有统一的当前有效需求视图，"最早"指代不明

- **最小复现输入**：
  ```
  第 3 轮（用户）：受众改成同行
  第 7 轮（用户）：产物改成技术文档站
  第 12 轮（用户）：算了还是按最早的来吧
  第 13 轮（AI）：<判定"最早"指哪一版、哪次改动作废>  ← 复现点
  ```
- **V0.3 现行规则会怎么走**：每一轮变更**各自独立**走 §6.5A（覆盖 + 只重置受影响下游）或 §6.5C（局部重开）。第 12 轮含"还是…"——这在 §6.5A 的信号清单里（"还是用…"）→ 判 Revision，新值覆盖旧值、分析影响、重置下游。
- **失效点**：**无状态位可用 + 判定歧义 + 静默丢失**。
  1. **"最早的"没有一个可解析的指代对象**：是第 1 轮的原始目标，还是第 3 轮"受众=同行"之后的那一版？系统里**没有需求版本序列**，§6.6 决策记录是按"每条关键缺口一行"记的**离散条目**（含 `结果` 字段），它**不构成可回放的版本链**——没有版本号、没有变更序号、没有"某个值在某一轮之后才生效"的时序。R10 让"留痕"成立，但**留痕 ≠ 可回溯到某一时刻的完整需求状态**。
  2. **"改回"要求反向操作**：第 7 轮已经顺着"技术文档站"重置了一批下游槽位（§6.5A 第 4 步）。第 12 轮改回时，需要判定的是"哪些是第 7 轮带来、现在应当消失的"与"哪些是第 3 轮带来、仍然有效的"——**两个变更的下游影响集从未被校验是否相交**，因为每次重开都是按"当次快照"判的，**没有任何跨轮次的连锁清理**。结果就是"改回"后残留着本应作废的决定（例如技术文档站的目录树结构、API 参考页布局）。
- **用户会看到什么**：`你说的"最早"是指最初的作品集，还是改成同行受众之后的版本？`——一个用户会认为"你比我清楚"的问题；或者第 13 轮之后又出现 `这个站主要给谁看？`（他第 3 轮就答过"同行"）。
- **需要的机制形态**：需要**一份"当前有效需求"的统一视图**（带变更序号/时序，能回答"某一轮时刻的完整需求状态是什么"）；需要**跨轮次的下游连锁清理**（改回一个上游值时，能识别并撤销它前一次重开所引入的下游值）；需要**"改回"的指代可解析**（回退目标可被定位到某个版本，而不是"最早"这种自然语言指代）。
- **严重度**：**高**（①无状态位 + ③重复提问 + ④静默丢失）。

## 判定汇总

| 编号 | 一句话 | 判定 | 依据（章程 §3 口径） | 严重度 |
|---|---|---|---|---|
| G-01 | P0 级推翻后"局部"边界不可判定，旧调性被沿用 | **接不住** | ①无状态位 + ④静默丢失 + ⑤出稿冲突 | 高 |
| G-02 | 换受众后视觉方向的前置条件失效被静默吸收 | **接不住** | ⑤出稿冲突 + ③把可推导问题抛回用户 | 高 |
| G-03 | "像修正但无信号词"无归属，§6.4 与 §6.5 相反 | **接不住** | ②规则相反动作 + ④静默丢失 | 高 |
| G-04 | 出稿后推翻 P0 产物，已产出稿效力无判定 | **接不住** | ①无状态位 + ⑤出稿冲突 + ③重复提问 | 高 |
| G-05 | 改回原目标 + 多重变更叠加，无统一状态视图 | **接不住** | ①无状态位 + ③重复提问 + ④静默丢失 | 高 |

**真失效点：5 / 5。严重度分布：高 5、中 0、低 0。**

**本文件对 §6.5C 结论**：§6.5C 在"**单次、单分支、非 P0**"的 Revision 上是接得住的（"主色改成蓝色"这一类）。它接不住的是三种形态：
1. **P0 级推翻**——此时"受影响分支"≈全量，"局部"失去可判定边界，且已产出物的效力无状态位；
2. **依赖前提变化**——"新值能否与旧值同时成立"的判据不检查下游槽位赖以成立的前提；
3. **多重变更叠加 / 改回**——没有"当前有效需求"的统一视图，也没有跨轮次的下游连锁清理。
