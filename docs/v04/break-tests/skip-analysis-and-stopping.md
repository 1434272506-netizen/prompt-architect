# 破坏测试 · 跳过分析 + 主动停止（Skip Analysis & Stopping）

> **所属方向**：V0.4 章程 §2.1 方向 **E**（要求跳过分析直接执行）＋ §1 表中 **F5**（何时主动停止）
> **被测规则**：`SKILL.md` §6.1（信息足够的判据）、§6.2（停止动作）、**§6.3（降级与授权默认，含例外块与同句优先级）**、§6.4（禁止）、§6.5C（局部重开）、`core/uncertainty-classifier.md` 契约 R6（阻塞项必须拍板 / 不可 DISCOVER）、§2.5 规则 2（能选不追）。
> **两个攻击点**：
> ① **"别问了直接做"与 §6.3 授权默认的边界**——检验"**授权默认 ≠ 允许跳过阻塞项**"这条边界是否真的划得清；
> ② **§6.1 面对"用户持续追加"有无主动收口机制**——还是只能无限跟下去。
> **案例数**：5 例（S-01 ～ S-05）。
> **判定口径**（引自章程 §3）：`接得住` = V0.3 现有 §/R 能给出唯一且合理的动作链，且用户侧体验无异常；`接不住` = 出现 ①无状态位可用 ②两条规则给出相反动作 ③需要无限循环/重复提问 ④静默丢失用户已给信息 ⑤出稿内容与用户原意冲突 中的任一。
> **本文件纪律**：只描述"需要什么机制形态"，不写 V0.4 规则措辞。

### S-01 · "别问了直接做" + P0 修饰槽位缺失：§6.1 说不能停，§6.3 说立刻出稿

- **最小复现输入**：
  ```
  第 1 轮（用户）：别问了直接做，做个公司官网，这周五要上线
  第 2 轮（AI）：<判定：授权默认 → 立即出稿？还是仍缺 P0 受众？>  ← 复现点
  ```
- **V0.3 现行规则会怎么走**：
  - **§6.3 这一侧**："直接给"出现在授权默认的完整清单里（§3.2 末段：`随便 / 你决定 / 按你想的来 / 按你认为好的来 / 你看着办 / 直接给`）→ 不计 unresolved、不再为走完采访流程而追问、非阻塞缺口用合理默认值、所有 AI 自行决定但未经用户确认的内容进「待确认假设」区、**立即进入可交付阶段**。
  - **§6.1 这一侧**：停止判据要求"同时满足"三项，其中第 1 项是"能回答：**谁用** / 要什么产物 / 怎么算成功 / 有哪些硬约束"。本例只知道产物（公司官网）和硬约束（周五上线），**受众与成功标准都答不出来**。按 P0 分级（§11.0 规则 8、契约 R11 分级），受众属 **P0 修饰槽位**（"缺失不单独触发 R11 例外，只补缺项"），**但规则从未说过"修饰槽位缺失不影响出稿"**——§6.1 第 2 项仍写着"P0 全部明确"。
  - **契约 R6 这一侧**：R6 闭集（目标 / 范围 / 权限 / 费用 / 数据用途 / 不可逆操作）与"受众"无关（§3.1 典型对照表明确列出"受众不在 R6 闭集"），所以"受众"**不算阻塞项**，无法用 §6.3 例外块把它拦住。
- **失效点**：**两条规则给出相反动作（②）**，而且 P0 分级**只定义了"谁先被 SHOW 挡位"，从未定义"谁挡住出稿"**。
  §6.3 说"立即进入可交付阶段"；§6.1 说"P0 全部明确"才算够（本例 P0 两项缺失）。§6.3 例外块拦的是"真冲突 / 不可行条件 / 完成任务所必需的缺失信息 / 法律安全边界 / 会根本改变用户目标的阻塞项"——**"给谁看"不在这五类里**，因此例外块管不住它。两条规则谁优先，**没有任何适用顺序条款**。执行者于是二选一：
  - 选 §6.1 → 违抗用户"别问了"的明确指令，用户看到 AI 在他说完"别问了"之后**仍然问了一个问题**；
  - 选 §6.3 → 出一份没有受众依据的公司官网方案。**P0 锚点"公司官网"带着"给谁看"的隐含默认**（给客户看 / 给求职者看 / 给招标方看，页面结构与内容重心完全不同），这个默认是 AI 自己填的，一旦不符就是整稿返工。
- **用户会看到什么**：`行，我按"给潜在客户看"来做，这周五上线的静态官网。`——一份全篇 AI 假设的产品；或者在他明说"别问了"之后仍然收到的 `就一个问题：这个站主要给谁看？`
- **需要的机制形态**：需要**"授权默认"与"停止判据"之间的覆盖关系位**：明确哪些 P0 槽位在授权默认下可以由 AI 取值并进假设区、哪些必须先拿到；需要一个**授权默认生效前的阻塞项清单核对点**（现有 §6.3 例外块只列了五类，与 P0 分级、契约 R6 闭集三者的关系没有被定义）。
- **严重度**：**高**（②规则相反动作 + ⑤出稿与用户原意冲突）。

### S-02 · "先出个版本再说"被归进授权默认：Type B 的"说不清但能判断"被跳过

- **最小复现输入**：
  ```
  第 1 轮（用户）：帮我做个产品落地页，要那种一眼就想点进去的感觉
  第 2 轮（AI）：你希望是 A 克制 / B 高密度 / C 强对比 哪一种？
  第 3 轮（用户）：先出个版本再说，我看着改
  第 4 轮（AI）：<判定这是不是授权默认>  ← 复现点
  ```
- **V0.3 现行规则会怎么走**：§6.3 的授权默认清单里有"**直接给我**"（"先出个版本再说"在语用上属同类），且 §6.3「同句优先级」的口径是"用户已明确放弃回答并交给我决定"→ 立即出稿。契约 R8 的失败语义里，"SHOW 无反应按未答处理"，而本例是**有反应但反应内容不是选择**（要求先出版本）——**这个形态在两处都没有归属**：它既不是"随便/你决定"（用户没说放弃判断），也不是"不知道"（§3.2 的四种 unresolved 形态：不知道 / 不确定 / 答非所问 / 明显回避——"先出个版本"更像"要更具体的草案"）。契约 R7 规定"SHOW 一轮后用户仍无法判断 → **提高保真度再 SHOW 一次**"。
- **失效点**：**判定歧义 + 出稿与用户原意冲突**。
  §6.3 的清单是按**字面短语**匹配的（"直接给""不用问了"），而本例是**按意图**表达的同一件事——"先做出来我再判断"是 Type B 用户的**典型行为**（§1 触发信号 4："用户主动说……你看着办"；契约 §1 核心命题："用户能判断但不能描述 → 连续追问是伤害"）。把它归进授权默认，就等于把"**能判断**"的用户当成"**不想投入精力**"的用户，跳过 §2.5 规则 2「能选不追」里真正的出路——**用更高保真的 SHOW 换他的判断**。V0.3 的处境正是章程 §1 表里 **F2** 的原话："'授权'与'不想投入精力'与'真的不知道'是三件事"，而 §6.3 把三者归为一类。
- **用户会看到什么**：一份完整成品。他的反应是"不对"——但**说不出哪里不对**（这正是 Type B 的定义）；接下来他能给的只有"再高级一点""看着不太对"这类形容词，采访退回起点。
- **需要的机制形态**：需要一个**"要更具体的东西来判断"的反馈类型位**，与"授权默认（AI 替我决定）"分离；该位默认应接到"提高保真度的下一次 SHOW"这条既有出路上，而不是直通成品出稿。
- **严重度**：**高**（判定歧义 + ⑤出稿与用户原意冲突，且消耗了 Type B 唯一有效的消解手段）。

### S-03 · 拒答但要求马上交付：§6.3 末尾一行的路径是"请补最关键的一个信息"，用户已经拒答 → 循环

- **最小复现输入**：
  ```
  第 2 轮（AI）：这个站主要给谁看？
  第 3 轮（用户）：我不想填这些，你直接做，我急
  第 4 轮（AI）：<按 §6.3 末行：出部分稿 + 只请其补最关键的一个信息>  ← 复现点
  第 5 轮（AI）：<同一件事——受众仍缺，其余已齐，没有别的槽位可补>
  ```
- **V0.3 现行规则会怎么走**：§6.3 末行："用户明确表示**不提供信息**、且未授权默认 → 出**部分稿** + 列出阻塞缺口，只请其补**最关键的一个**信息。"本例用户说的是"我不想填这些，你直接做"——**"你直接做"是否构成授权默认**？它是 §6.3 清单里"直接给我"的变体，按「同句优先级」似乎应算授权默认。但若**不算**（例如判为"不提供信息"），就走末行：出部分稿 + 请他补受众。
- **失效点**：**需要无限循环（③）+ 两条路径都不成立**。
  1. 走末行 → 那个"最关键的信息"就是受众，而用户**刚刚明确拒答**。§6.3 的"只请其补最关键的一个信息"**没有配套的计数**（它不计 unresolved——§3.2 的 unresolved 是给"不知道/不确定/答非所问/明显回避"的，"拒答"不在其中）；没有 exit；也没有"用户第二次拒答后怎么办"。用户拒绝的是"回答问题"这件事本身，所以**请求他补一个信息，和他已经拒绝的动作是同一件事**——这是一个结构上无法收敛的循环。
  2. 走"同句优先级"判为授权默认 → 撞上 S-01 的同一个缺口（受众缺失 vs §6.1），且用户**没有说"你决定"**，他把决定权留给了自己（"我急"≠"你定"）。§6.3「同句优先级」只规定了"不知道 + 随便"这类**同句双信号**的裁法，对"拒答 + 催交付"**没有口径**。
- **用户会看到什么**：`我先按最常见的情况做了一版，你只需要告诉我它是给客户还是给同行看的。`——在他已经说过"我不想填这些，我急"之后，**同一个问题又回来了**；他再拒一次，同一句话第三次出现。这正是 §6.4 想禁止的"重复询问"形态，但因为路径绕过了 unresolved 计数，**规则本身抓不住它**。
- **需要的机制形态**：需要**"用户拒绝提供信息"作为独立反馈类型的状态位**（与"不知道""回避"分开），并配一个**该状态的终态**（AI 全量取默认 + 全部进待确认假设 + 明确告知"以下是假设，不符请指出"）；需要**"关键信息请求次数"的计数**，使"请补最关键的一个信息"不是一个可以无限重复的动作。
- **严重度**：**高**（③无限循环 + ④用户的拒绝这一事实本身没有被记录成任何状态）。

### S-04 · 用户持续追加新需求（第 8、12、20 轮各加一条）：§6.1 永远不触发，无主动收口机制

- **最小复现输入**：
  ```
  第 1 轮（用户）：做个作品集站
  第 8 轮（用户）：对了，要能放视频
  第 12 轮（用户）：还要能中英切换
  第 18 轮（AI）：<仍在追问某一轮新增项的实现细节>
  第 20 轮（用户）：再加一个功能：访客能直接提交合作意向
  第 21 轮（AI）：<接收 → 局部重开 → 继续问>  ← 复现点
  ```
- **V0.3 现行规则会怎么走**：每次追加都走 §6.5C（局部重开：判断影响哪些已确认需求 → 只重开受影响分支 → 其余保留 → 不从头采访）。**§6.1 的停止判据要求"同时满足"三项**，其中第 3 项是"剩余缺口**只影响措辞，不影响结构**"。每加一条需求就引入新的结构性缺口（"能放视频"→ 存储与加载；"中英切换"→ 内容模型；"提交合作意向"→ 表单与数据用途），第 3 项于是**永远不满足**。
- **失效点**：**无状态位可用（无收口机制）+ ③无限跟下去**。
  §6.1 只在"某一轮结束时刚好满足三项"才触发停止；**没有任何机制能主动宣布"信息已经够了，再追加会破坏已经确定的方案"**。§6.2 的"立即出稿、不再追加任何'以防万一'的问题"约束的是 **AI 不许多问**，管不到"用户不停地给"。§3.2 的 unresolved 计数只统计**被回避**的情况，管不到"源源不断的新信息"。于是：
  1. **轮次无上限**——每一次追加都合法地产生新一轮采访，且每次"只重开受影响分支"都可能**扩大**下一轮的工作面；
  2. **目标漂移无检测**——第 20 轮那条"访客提交合作意向"只影响产品形态，**没有任何检查点问过"这是不是变成另一个产品了"**。第 8 轮时其实已经不满足 §6.1 的任何一版，但第 12 轮的新增让系统始终觉得"还有活干"，**没有东西把"需求集已经越出原目标"标出来**。
- **用户会看到什么**：`"中英切换"这块，是只切换界面文字，还是项目和截图里的文字也要切？`（第 12 轮提出、第 18 轮还在问）；最终拿到的东西与他第 1 轮说的"作品集"已经不是一回事，**中途没有任何人提示过这一点**。
- **需要的机制形态**：需要**需求追加的次数/预算计数**与**"目标漂移"检测位**（判断累积追加是否已改变产物类型或验收标准）；需要**主动收口的状态**——AI 能发起"到此为止，先出一版"的判定，而不是只能等 §6.1 自然满足；需要把"新信息不断到达"这件事本身作为**停止判据的输入**，而不是被排除在停止判据之外。
- **严重度**：**高**（①无状态位 + ③无限跟下去 + ⑤累积出稿与原目标冲突）。

### S-05 · 信息已足够但用户还在加：§6.1 判停与"继续接收新信息"在同一时刻重叠，无优先级

- **最小复现输入**：
  ```
  第 1～5 轮（用户）：<P0 齐、硬约束齐、剩余只影响措辞>
  第 6 轮（AI）：够了，我这就出稿（按 §6.2 立即进入 §8）
  第 6 轮（用户）：等一下，再加一点：要能按行业筛选案例
  第 7 轮（AI）：<已启动的出稿 vs 新增的结构性要求>  ← 复现点
  ```
- **V0.3 现行规则会怎么走**：§6.1 三项同时满足 → §6.2"**立即**进入 §8 出稿，**不再追加任何'以防万一'的问题**"。§6.3 末注："**停止主动追问 ≠ 停止接收用户新信息**。出稿后用户补充关键信息 → 走 §6.5C 局部重开。"两句话分别成立于不同时点，但本例把它们**压在同一轮**：AI 正在按"信息已足够"出稿，用户在出稿过程中又追加了结构性要求。
- **失效点**：**两条规则衔接处无优先级（②形态）+ 静默丢失**。
  "信息已足够"是 AI 的判定，用户并不知道这个判定已经生效——§2.1 禁止向用户外露"停止规则/采访循环"这类机制词，所以用户**看不到"你再加就要重来"的信号**，他会继续加。而系统这边：
  - §6.2 要求"立即出稿"，等价于**冻结当前需求集**；
  - §6.3 末注要求"不停止接收"；
  - §6.5C 的触发条件是"出稿后补充**关键**信息"——**"关键"由谁判、按什么口径判，规则未定义**。于是同一条新要求，可能被判为"关键 → 重开"，也可能被判为"不关键 → 只记下"，**完全靠自由裁量**；如果判为"不关键"，这条用户**已经说出口**的要求就静默丢了（违反 §6.4 末行"不得把停止追问理解为拒绝接收后续新信息"，但该条只写了"要接收"，**没写"接收后要做什么"**）。
- **用户会看到什么**：`按这个来了——`（随即发出一份不含行业筛选的稿子），或者第 6 轮与第 7 轮之间**连续出现两个版本**，AI 也没说清哪一版作废。
- **需要的机制形态**：需要**"冻结出稿"这一刻的状态位**（冻结时刻之后到达的信息，其归属是可判定的：进增量更新 / 进下一版 / 标注为超出本轮范围）；需要**"关键信息"的可判定口径**（是否改变结构、是否改变 P0 取值），使"接不接、重开不重开"有唯一答案。
- **严重度**：**高**（②衔接处无优先级 + ④静默丢失）。

## 判定汇总

| 编号 | 一句话 | 判定 | 依据（章程 §3 口径） | 严重度 |
|---|---|---|---|---|
| S-01 | "别问了直接做"：§6.1 判不能停 vs §6.3 判立即出稿 | **接不住** | ②规则相反动作 + ⑤出稿冲突 | 高 |
| S-02 | "先出个版本再说"被当授权默认，跳过 Type B 的 SHOW | **接不住** | 判定歧义 + ⑤出稿冲突 | 高 |
| S-03 | 拒答但催交付：§6.3 末行要求"补一个信息"= 用户刚拒绝的事 | **接不住** | ③无限循环 | 高 |
| S-04 | 持续追加（第 8/12/20 轮）：§6.1 永不触发，无主动收口 | **接不住** | ①无状态位 + ③无限跟下去 + ⑤漂移 | 高 |
| S-05 | 信息够了但用户还在加：§6.2 冻结 vs §6.3 继续接收 | **接不住** | ②衔接无优先级 + ④静默丢失 | 高 |

**真失效点：5 / 5。严重度分布：高 5、中 0、低 0。**
