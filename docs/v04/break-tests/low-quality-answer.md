# 破坏测试 · F2：ASK 得到低质量回答

> **所属方向**：V0.4 章程（`docs/v04/README.md`）§1 表 **F2** ＋ §2.1 方向 **E**（跳过分析直接执行）中的"授权"一侧。
> **被测对象**：V0.3（冻结版，哈希见 [docs/freeze-v0.3.md](../../freeze-v0.3.md) §2）。本文件**不修改任何冻结文件**，只记录失效点。
> **攻击面**：`SKILL.md` **§6.3**（降级与授权默认：清单、"同句优先级"、例外块、末行）、**§3.2**（unresolved 计数与分流）、**§6.4**（禁止清单）、**§6.1 / §6.2**（停止判据与停止动作）、**§6.5**（兼容更新）、**§6.6**（决策记录六条填写约束）、**§7**（双轨标记铁律 1–4）、**§8**（5 段出口 + 待确认假设区）、**§11.2**（高价值缺口难回答）；`strategies/ask.md` 前置条件 7 与失败/降级路径表；`core/uncertainty-classifier.md` 契约 **R2 / R6 / R8 / R9**、**§6 决策记录字段与约束 1–6**、**§2 Type 归属表**。
> **本文件焦点**：`§6.3` 把 **随便 / 你决定就行 / 按你想的来 / 看着办 / 直接给 / 都行别问了** 一律归为**授权默认**——不计 unresolved、不再追问、取合理默认值、立即进入可交付阶段。本文件逐例检验这条归并是否成立：
> - **真授权**（我不在乎，你定）
> - **不想投入精力**（我懒得想／我不想填，但我在乎结果）
> - **真的不知道**（我想说但说不出来，且这本身就是缺口）
>
> 三态被压进同一个桶之后，用户的反馈就不再携带可恢复的信息。
> **格式**：`docs/v04/README.md` §2.2 八字段（第 8 字段 = **判定 / 严重度 / 判据**，与本目录既有文件 `show-silence.md`、`skip-analysis-and-stopping.md` 对齐）。
> **判定口径**（引自章程 §3）：`接得住` = V0.3 现有 §/R 能给出**唯一且合理**的动作链，且用户侧体验无异常；`接不住` = 命中五条之一：①无状态位可用 ②两条规则给出相反动作 ③需要无限循环/重复提问 ④静默丢失用户已给信息 ⑤出稿内容与用户原意冲突。
> **本文件纪律**：只描述"**需要什么机制形态**"，**不写 V0.4 规则措辞**。
> **案例总数：6**（F2-01 – F2-06，逐一覆盖：随便 / 你决定就行 / 我不懂你看着办 / 都行别问了 / 答非所问 / 只答一半）。**真失效点 5 个**（F2-02 / F2-03 / F2-04 / F2-05 / F2-06），**接得住 1 例**（F2-01）。

### F2-01 · 用户先"随便"、下一轮才补出真实关切："随便"这一笔已经结账，用户侧的在乎无处安放

- **最小复现输入**：
  - 第 1 轮：`帮我做一个给客户报名用的活动页，下个月要用`
  - 第 2 轮（收到"这个页面的报名表单收哪些字段？"）：`随便，你定就行`
  - 第 3 轮：`对了，别让客户填太多东西，超过三个空他们就不填了`
- **V0.3 现行规则会怎么走**：第 2 轮落 `§6.3` 授权默认行（"随便"在完整清单内）→ 不计 unresolved、**不再为走完采访流程而追问**、非阻塞缺口取合理默认值、AI 自定内容进「待确认假设」、进入可交付阶段。第 3 轮用户补出的是**一条能与授权默认同时成立的约束**（"字段不超过三个"＋"取默认值"可并存）→ `§6.5` 兼容更新段明写"直接更新槽位、无需追问"。`§6.4` 禁止项同时挡住两条退路：不得换措辞追问同一个点，也不得把"随便"记作 unresolved。决策记录按 `§6.6` 记为 `asked` + 状态 `待决定` 或 `用户已确认`。
- **失效点**：**判定歧义（态度不可恢复）+ 无状态位**。第 3 轮这句话在语用上是"我在乎结果、但我不想投入精力想细节"，而它到达时，授权默认已经把该槽位结账；`§6.6` 的六个状态值里，**没有一个能表达"用户授权了但他在乎"**——记录只能落在 `AI 建议` 或 `待决定`，与"他真不在乎"这一情形**写成同一行**。V0.3 没有任何办法在事后区分这两态，也没有"授权后补充的关切"该挂到哪个账本的规定。
- **用户会看到什么**：`好，表单我按最常见的三项来做，其余我先按经验定了，都写在最后那份待确认里。`——用户那句"别让客户填太多"被折进了一份他自己没看过的假设清单，而他接下来的反馈只能以"不对"的形式出现。
- **需要的机制形态**：需要**授权与关切并存的记录形态**（同一槽位允许同时存在"已授权取值"与"用户后来追加的关切/硬约束"两个字段），并需要一个**授权后补充信息的归属判定位**——判定它是覆盖授权、叠在授权之上、还是标为超出本次授权范围。
- **严重度**：低（不丢需求、不循环；`§6.5` 兼容更新能兜住新信息本身，但"用户在乎却不想说"这一事实既未记录也无出口，用户侧只能靠多轮"不对"来逼近）
- **判定**：**接得住**——动作链唯一：采纳"字段≤3"（`§6.5` 兼容更新）＋ 其余按 `§6.3` 授权默认取值 ＋ 全部进「待确认假设」（`§7` 铁律 1）→ 出稿（`§8`）。用户侧无异常，仅体验上多一轮返工。

### F2-02 · "你决定就行"授权的是一个用户不了解后果的选项：授权默认不比它要替代的那个问题更安全

- **最小复现输入**：
  - 第 1 轮：`给我做一个内部用的资产管理页，大概 200 台设备`
  - 第 2 轮（收到"两种计费方式，你倾向于哪一种？① 一次性买断（推荐）② 按量付费"）：`你决定就行，我不懂这个`
  - 第 3 轮：`哦对，这东西只用两个月，做完就归档了`
- **V0.3 现行规则会怎么走**：第 2 轮同时命中两条——`§3.2` 的"不知道 / 不确定"记一次 unresolved 与 `§6.3` 授权默认行（"你决定就行"在清单内）→ 由 `§6.3`**「同句优先级」**裁定："一句话里同时出现…与'随便 / 直接给'这类授权默认时，**授权默认优先**"→ 不计 unresolved、取推荐默认值（买断）、进「待确认假设」、进入可交付阶段。唯一可能的纠错口是 `§6.3` 例外块，但它枚举的是"真冲突 / 不可行条件 / 完成任务的必需缺失信息 / 法律安全技术边界 / 会根本改变用户目标的阻塞项"——**"用户不了解这个选项的后果"不在其中**。第 3 轮"只用两个月"是 `§6.5` 兼容更新，只改归档范围。
- **失效点**：**判定歧义 + 出稿与用户原意冲突**。"你决定就行"被按字面读成"我不在乎"，而用户同句给出的另一半是"**我不懂这个**"——那是认知缺口（契约 §2 Type C 的定义："用户未意识到该缺口存在；踩空会造成返工、风险或不可逆后果"）。`§6.3`「同句优先级」用 **AI 放弃提问** 的方式处理了 **用户的认知不足**，于是"先教再问"（契约 R3 / `strategies/teach.md`）这条唯一能让他知情决定的出路被封死；而它取默认值时所依据的"合理默认"，恰好就是那个用户看不懂的选项本身——**授权默认不比它替代的那个问题更安全**。
- **用户会看到什么**：`计费我按"一次性买断"定了，这样以后不用再管费用；这个我写进待确认里。`——用户得到的是一笔他自己不会算、也没人给他算过的钱。
- **需要的机制形态**：需要一个**授权有效性前提位**：区分"用户知情地放弃决定"与"用户在不了解可选项后果时放弃决定"；并需要一个**授权范围与已说明范围的对应关系**——AI 取默认值不得超出"已向用户说明过其后果"的选项集合（超出的部分必须回到 ASK 或先补认知）。
- **严重度**：高（⑤出稿内容与用户原意冲突，且这类授权的默认值一旦取错就是**成本/不可逆**方向；用户的"不在乎"是被误读出来的）
- **判定**：**接不住**——`§6.3`「同句优先级」明令授权默认优先于"不知道"，`§6.3` 例外块五类不含"用户不了解后果"，`§6.3` 末行"请其补最关键的一个信息"又被用户当场拒绝（他就是不知道才让你定）。三条路给出**相反或不适用**的动作，无唯一动作链。

### F2-03 · "我不懂你看着办"把认知缺口关在门外：`§11.2` 的"先降低问法难度"被授权默认的"不再追问"直接封死

- **最小复现输入**：
  - 第 1 轮：`帮我做一个客户投诉自动回复的小工具，接在公司公众号上`
  - 第 2 轮（收到"客户问到答不上来的问题怎么处理？① 转人工 ② 兜底话术 ③ 先记录待人工跟进"）：`我不懂这些，你看着办吧`
- **V0.3 现行规则会怎么走**：`§6.3` 授权默认（"你看着办"在完整清单内）→ 不计 unresolved、不再追问、非阻塞项取合理默认、进「待确认假设」、立即进入可交付阶段。**同时**：`§3.2` 要求把"不知道 / 不确定"记一次 unresolved 并**继续处理当前最高优先级缺口**——这与"不再追问、立即进入可交付阶段"是两个动作。`§11.2`（高价值缺口难回答）本应接管：①**先降低问法难度**（同一缺口换表述）②降维后仍答不出 → 回 `§3.2` 判断阻塞性（非阻塞 → 默认值 + 假设区；阻塞 → 部分稿 + 说明缺哪一个决定）③高影响但答不出的问题**不计为已完成**。但 `§11.2` 的触发词是"答不出"，而本例用户给出的是**授权**——`strategies/ask.md` 前置条件 7 明写"授权默认后不问"，`§6.4` 明写不得把"随便 / 你决定"记作 unresolved 或据此继续追问。于是 `§11.2` 第 1 步（唯一能给用户留出"说出来"通道的动作）在本例中**被禁止执行**。
- **失效点**：**规则冲突（`§11.2` vs `§6.3`/`§6.4`）+ 无状态位**。三件事判别：本例用户的"我不懂"是**真的不知道**——缺口不是"他不想选"，而是"他不知道有这个岔路口、也不知道选项的后果"（契约 §2 Type C / Type A 的边界）。V0.3 的处境是：**要不要把知识缺口当缺口，取决于用户那句话里有没有'你看着办'四个字**；有则整个缺口生涯结束，无则 `§11.2` 还会降维再问一次。而按 `§3.2` 的排除条款，这次"不懂"连 unresolved 都不计——**该缺口的失败计数永远是 0**，也就永远触发不了"2 次后分流"。`§11.2` 第 3 条"不得因为它'理论上价值高'就跳过降维直接使用"因此被静默绕过。
- **用户会看到什么**：`转人工这块我按最常见的方式设了，先让它记录、由人跟进；到时候不行再调。`——用户明确说过"我不懂"，收到的却是一个既没跟他解释、也没有变化余地的既成事实；他下一次也只能重复"我不懂"。
- **需要的机制形态**：需要一个**"用户不知情地放弃决定"的独立反馈类型位**（与"授权"、"回避"分开），并规定该位与缺口计数的关系（它算不算一次未解决）；需要一个**认知缺口的可判定入口**——把"用户说不出"与"用户不在乎"在分类阶段分开，而不是在语用层合并；并需要 `§11.2` 降维与 `§6.3` 不再追问之间的**适用顺序位**。
- **严重度**：高（②规则相反动作 + ①无状态位：认知缺口既不计数也不消解，用户被永久锁在"我告诉你我不懂了"的位置上）
- **判定**：**接不住**——`§11.2`（先降维、不得因难答而跳过）与 `§6.3`/`§6.4`/`strategies/ask.md` 前置条件 7（授权默认后不问、且不得据此继续追问）对同一句话给出相反动作，无优先级条款。

### F2-04 · "都行，别问了"之后用户回来推翻：授权了却没有任何"他被告知过什么"的记录

- **最小复现输入**：
  - 第 1 轮：`给我做个公司年会的抽奖页面，投影上用的，要热闹`
  - 第 2 轮（收到"抽奖过程的节奏和视觉风格你更想要哪种？"）：`都行，别问了，你看着办`
  - 第 3 轮（出稿后）：`这颜色太素了，跟我们年会的调性不搭`
- **V0.3 现行规则会怎么走**：第 2 轮落 `§6.3` 授权默认 → 不复述选项、不追问、取默认值、把 AI 自定内容放进「待确认假设」、进入可交付阶段（`§6.3` + `§6.2` + `§8`）。`§6.4` 明写"把'随便 / 你决定 / 直接给'记作 unresolved 或据此继续追问"属禁止行为，因此"别问了"这四个字**不得触发任何后续核对**。第 3 轮用户否定已交付内容 → 按 `§6.5` A（Explicit Revision："跟…不搭"属对旧值的否定）只重开视觉分支，其余保留。
- **失效点**：**无状态位（告知留痕缺席）+ 判定歧义**。"授权默认"与"用户已知情"被记成同一件事：`§6.3` 只要求把 AI 自定内容"进「待确认假设」区"，而 `§8` 的假设区格式是**一条一行、注明"若不符请指出"**——它既没有"这是在你明确说别问了之后由我决定的"这一事实标记，也没有"我当时给过你哪些选项、你跳过了哪几个"的对照。于是第 3 轮用户可以说"我又没同意过这个"，系统只能重复"我写在假设区了"，**无权**说明"这是在你说'别问了'的情况下我取得的最小授权"。`§6.6` 的状态值里同样没有区分"用户确认的取值"与"用户授权后 AI 取的默认值"这一层。
- **用户会看到什么**：`视觉我按'暖色调、强对比'来定了，抽奖节奏也调快了，这些都写在最后的待确认里。`——他当时只说了一句"都行，别问了"，拿到的是一份**没有任何取舍痕迹**的稿子；不满意时，他无从知道哪些部分是自己"放弃过"的。
- **需要的机制形态**：需要一个**授权事件的记录位**（记下"用户在跳过哪一个缺口时给出了授权"以及"授权时 AI 摆在台面上的选项/后果"），并需要一个**与"用户已确认"并列但不同的可见层级**（出稿时能让用户区分"这是你说的"与"这是你说随便之后我定的"）。另需一个**授权被事后否定时的处理位**（算 Revision、算默认值失效、还是算再次授权）。
- **严重度**：中（不丢需求、不循环；`§6.5` 局部重开能收敛，但授权事实与告知内容不可复原，任何一次事后否定都退化为"你说过/我没说过"的争论）
- **判定**：**接不住**——V0.3 没有记录"用户授权时被告知了什么"的状态位；`§6.3` 只要求把自定内容写进假设区，`§8` 的假设区格式（一条一行 + "若不符请指出"）无字段承载该事实，`§6.6` 的六状态也无该层，因此第 3 轮起不存在唯一动作链。

### F2-05 · 多子问题只答一半："未回答"被当成"已授权"，`§6.4` 禁止换措辞追问，但**没禁**换措辞采纳

- **最小复现输入**：
  - 第 1 轮：`做个给老客户用的对账单导出功能`
  - 第 2 轮（一问两组：① 数据保留多久？② 导出格式？）：`导出就 CSV 就行`
  - 第 3 轮：`导出的文件要能直接发给客户，别带内部字段`
- **V0.3 现行规则会怎么走**：`strategies/ask.md` 执行步骤 7 要求一题一组选项、步骤 4 允许在 `§11.7` 六项条件下合并提问——本例两组子问题分别提问（保留期 / 导出格式），**用户只答了第二组**。第一组的处理没有规定：`§3.2` 的四种 unresolved 形态是"不知道 / 不确定 / 答非所问 / 明显回避"，**"只答了别的一半"不在这四种之内**；`§6.3` 授权默认清单是字面短语表（随便 / 你决定 / 按你想的来 / 按你认为好的来 / 你看着办 / 直接给 / 不用问了），**不含"沉默地跳过某一题"**。于是执行者二选一：把它当"未答"（但 `§6.4` 禁止重复询问、禁止换措辞追问，且 `§3.2` 的分流要等 2 次计数）或当"授权默认"（取默认值 + 进假设区）。第 3 轮"别带内部字段"是 `§6.5` 兼容更新。
- **失效点**：**判定歧义（两种读法都合规）+ 静默丢失**。`§6.3` 的"同句优先级"只覆盖"同一句话里两个信号"（不知道＋随便），**不覆盖"一句话只覆盖了一半的问题"**：用户答的那一半与跳过的那一半在决策记录里都只能写成"asked + 取默认值/待决定"，两者的可信度被压成同一层。更麻烦的是 `§6.4` 只禁止"换一种措辞**追问**同一个点"，**没有禁止**"换一种措辞**采纳**"——执行者可以合法地把"你倾向哪种"悄悄变成"那我按 CSV 那个思路把保留期也定了"，全程不违规。静默丢失的正是"用户从未就保留期表过态"这一事实。
- **用户会看到什么**：`保留期我按"长期保留、只增不删"处理了，格式按你说的 CSV。`——他跳过的那一题被以"你说过 CSV"的语气一并填上了，两件事在出稿里看不出区别。
- **需要的机制形态**：需要一个**缺口级的"部分回答"状态位**（同一轮多个子问题中，哪些被答、哪些被跳过、跳过的是沉默还是授权），并需要一个**"换措辞采纳"与"换措辞追问"同等受限**的判定位——未表态的槽位不得借已被回答的相邻槽位获得可信度。
- **严重度**：高（④静默丢失用户未表态的信息；且因为两种读法都合规，任何一次执行都不算违规，失效**不可复现、不可复盘**）
- **判定**：**接不住**——`§3.2` 的四种 unresolved 形态与 `§6.3` 的字面授权清单**都不覆盖"只答一半"**，两条规则给不出唯一动作，`§6.4` 的禁令又只作用于"追问"一侧，无路可走。

### F2-06 · "按你想的来"被读成正向授权，但它实际是一句**否定式约束**：授权默认按字面生效，用户真正给出的约束进了假设区

- **最小复现输入**：
  - 第 1 轮：`做一个产品展示页，图片多，要好看`
  - 第 2 轮（收到"你更希望访客先看到什么？① 产品大图 ② 使用场景 ③ 价格"）：`按你想的来，我不在乎这些`
  - 第 3 轮：`只要别太重就行，我这边网慢，加载别超过两秒`
- **V0.3 现行规则会怎么走**：`§6.3` 授权默认 → 不复述、不追问、取合理默认、**所有 AI 自行决定但未经用户确认的内容进「待确认假设」区**、立即进入可交付阶段。第 3 轮"加载别超过两秒"是一条**能与授权默认同时成立**的新约束 → `§6.5` 兼容更新段"直接更新槽位、无需追问"，同时它本身属 Type D（用户已明确说清且无冲突）→ 契约 §4 Step 1 短路：不动作，进规划。表面看全链顺畅。
- **失效点**：**判定歧义（授权颗粒度无判据）+ 静默丢失**。第 2 轮那句话里有两半：**授权**（"按你想的来"）＋**一句真否定式约束**（"我不在乎**这些**"——"这些"指 AI 摆出的那一组选项，不是"我不在乎加载性能"）。而第 3 轮证明用户**非常在乎**结果指标：他给的是一个**可判定的硬约束**（性能预算），这条约束与第 2 轮被取默认的那些结构性选择**互相决定**（图片多 + 加载≤2 秒 ⇒ 图片格式与数量上限必须先定，否则默认值的组合直接违反硬约束）。V0.3 缺失的判定位：**授权默认取的值是否与用户后来给出的硬约束相容**——`§6.3` 没有任何"取值前先对照已确认约束"的动作，`§6.5` 兼容更新只看新旧两条信息**彼此**能否同时成立，不看新约束与**此前由 AI 默认填入的值**是否打架，`§3.1` Conflict/Tension 的判定对象是"两条**用户**要求"，管不到"用户约束 vs AI 默认值"。
- **用户会看到什么**：`方向我按大图首屏来定了，加载这块我按需加载优化了一下。`——两句都合规，但"大图首屏 + 加载≤2 秒"这组合本身可能不成立；而这个问题不会以"冲突"的形式暴露，只会以"页面很慢"的形式在交付后出现。
- **需要的机制形态**：需要一个**授权颗粒度判定位**（授权覆盖的是"AI 摆出来的那组选项"还是"该槽位的全部取值空间"），并需要**默认值与已确认约束的相容性检查点**（取值前对照已确认硬约束；不相容时默认值必须失效回退，而不是两条各写各的）。
- **严重度**：高（⑤出稿内容与用户原意冲突：用户说的"不在乎"被读成"全槽位不在乎"，而他在乎的恰好是能推翻默认值的那一条）
- **判定**：**接不住**——`§6.3` 只处理"授权→取默认值→进假设区"这条正向链，`§6.5` 兼容更新的判据是"新信息与旧要求**彼此**可否同时成立"，`§3.1` 的判定对象是用户的两条要求；**没有任何条款管辖"AI 默认取值 vs 用户后来给出的硬约束"**，因此第 3 轮该不该推翻第 2 轮的默认值，无唯一答案。

### 三态区分能力的结论（F2 焦点）

| 三态 | 在 V0.3 下的证据形态 | 能否被识别 | 识别失败的直接代价 |
|---|---|---|---|
| **真授权**（我不在乎，你定） | `§6.3` 字面清单命中 → 不计 unresolved、取默认值 | 能，但**只有字面命中才算**；"按你想的来 + 我不在乎这些（这一组）"这类**带范围的授权**一律被读成全槽位授权（F2-06） | 授权颗粒度失控，默认值可能与用户硬约束互斥（F2-06） |
| **不想投入精力**（我懒得想，但我在乎结果） | 与真授权**同形**：同样落 `§6.3` 清单 | **不能**。`§6.6` 六状态里没有"用户授权但他在乎"这一值，`§8` 假设区只有"一条一行 + 若不符请指出"（F2-01 / F2-04） | 用户只能以"不对 / 太素了"反复否定；且"他当时被告知过什么"不可复原（F2-04） |
| **真的不知道**（我想说但说不出来） | 与真授权**同句**出现：`§6.3`「同句优先级」判授权默认优先 | **不能，且被规则主动压掉**。"不知道"既不计 unresolved（F2-03），`§11.2` 的降维通道又被"授权默认后不问"封死（F2-02 / F2-03） | 认知缺口永远不计数、不消解；AI 在用户看不懂的选项上取默认值（F2-02） |

**一句话结论**：V0.3 对三态**只有"字面授权默认"这一个桶**——真授权能进桶，另两态被误收进桶，而 `§6.3`「同句优先级」与 `strategies/ask.md` 前置条件 7 使"同句暴露的不知道"**在规则层面被明确判给对方**。因此"不想投入精力"与"真的不知道"在 V0.3 下**确实无法区分，也不可事后恢复**：区分它们所需的字段（谁授权、授权覆盖到哪、授权时 AI 说明了什么、用户是否知情）在 `§6.6` 决策记录里一个都没有。
