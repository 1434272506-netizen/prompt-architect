# Prompt Architect

> 把"我想要那种高级的感觉"变成一份可以直接执行的专业 Prompt。

绝大多数人和 AI 协作失败，不是因为 AI 不行，而是因为**需求根本没被说清楚**：用户给的是一句感受，AI 只能猜，猜完照着字面抄进 Prompt，第一版就跑偏。

Prompt Architect 是一个**需求消解协议**：在动手写 Prompt 之前，先判断你缺的是哪种信息，再用**正确的方式**把它补上——该问的才问，能查的自己去查，说不清的给方向让你挑，你不知道的风险先告诉你。

一句话总纲：**先判断这是哪种未知，再决定要不要问。**（协议定义见 [`SKILL.md`](SKILL.md) §2.5 与 §11.0）

---

## 它解决什么

同一个缺口，消解方式不同，成功率差一个数量级。**"该不该问、怎么问"本身就是这个协议的产物。**

| 缺口性质 | 你的话可能长这样 | 常见错误做法 | 本协议的动作 |
|---|---|---|---|
| 你知道缺什么 | "数据库选 MySQL 还是 PG" | — | **ASK** 直接问 |
| 你判断得了、但说不清 | "要高级感""要电影感" | 连续追问"高级具体指什么" | **SHOW** 3 个差异明显的方向让你选/改/混 |
| 你根本不知道有这个缺口 | "我要做个 AI 客服" | 直接开始设计功能 | **TEACH** 先讲隐藏风险和后果 |
| 答案客观存在于环境里 | "项目用哪个 Python 版本" | 反过来问你 | **INSPECT** 只读查证，不打扰你 |
| 只能由执行结果回答 | "这个库会不会自动分页" | 需求阶段反复追问 | **DISCOVER** 写进 Prompt，执行时验证 |

五种类型与五种动作的完整判定树、优先级与契约规则 **R1–R14** 见 [`core/uncertainty-classifier.md`](core/uncertainty-classifier.md)；每种动作的独立规范见 [`strategies/`](strategies/)。

需求已经说得清清楚楚时它**不启动采访**——该直接干活就干活，这本身是规则的一部分（[`SKILL.md`](SKILL.md) §1 触发信号）。

## 安装

这是一个纯 Markdown 协议，**零依赖、无脚本、无外部服务**。

**方式一 · 作为 Skill 使用（推荐）**

把整个仓库目录放进你所用宿主的 skills 目录，宿主会在需求模糊时自动按 `SKILL.md` 的协议处理：

```
<你的 skills 目录>/prompt-architect/
├── SKILL.md          ← 协议主体（入口）
├── core/             ← 接口契约（与正文冲突时以它为准）
├── strategies/       ← 五种消解动作的规范
├── examples/         ← 完整对话样例
└── tests/            ← 验收用例与对抗测试
```

**方式二 · 直接把协议喂给模型**

把 [`SKILL.md`](SKILL.md) 全文粘进系统提示词或项目说明即可；`core/` 与 `strategies/` 作为补充上下文按需追加。

## 触发条件

满足任一即进入协议（[`SKILL.md`](SKILL.md) §1）：

1. 缺「要什么产物 / 给谁用 / 怎么算成功」中的任意一项
2. 只有形容词，没有可执行约束
3. 有多个方向，靠上下文消歧不了
4. 你主动说"我不知道怎么表达""你帮我问""你看着办"
5. 存在你**未意识到**、踩空会造成返工或不可逆损失的缺口
6. 存在答案**本可从环境查明**、却会被误当成问题来问你的缺口

触发后**不是立刻提问**：先分类（§2.5），再选动作（§11.0）。提问只是五种动作之一。

## 工作流

```
你的需求（模糊/不完整）
   │
   ▼
[触发判定] ── 信息已足够 ──▶ 直接执行，不追问
   │ 存在缺口
   ▼
[§2.5 未知类型分类]   A 已知未知｜B 说不清但可判断｜C 未意识到的风险｜E 环境可查
   │
   ▼
[§11.0 动作选择]  能查不问 · 能选不追 · 先教再问 · 阻塞项必问
   │
   ├─ E ─▶ INSPECT   只读查证 → 不转问用户
   ├─ B ─▶ SHOW      3 个正交方向让你选/改/混（不是交付）
   ├─ C ─▶ TEACH     ≤3 条隐藏缺口 + 后果 → 重跑决策树
   ├─ A ─▶ ASK       每轮 ≤3 题，按 §3 优先级排序
   └─ 只能执行期回答 ─▶ DISCOVER  写进 Prompt：执行前先验证 X
   │
   ▼
[停止判定] 谁用/要什么/怎么算成功/硬约束 都明确？
   │ 是，或你连续 2 轮"随便"，或你说"直接给"
   ▼
[极简 5 段 Prompt]  角色与目标 / 输入 / 约束 / 输出格式 / 验收标准
                    + [待确认假设]（AI 的推测全部在这里，绝不混进需求区）
                    + [决策记录]（§6.6：每条关键缺口记 类型/动作/状态/依据/结果）
```

## 一个完整例子

**你**：帮我做个咖啡店的宣传海报，要高级一点。

**① 第 1 轮采访（2 问，先问目标）**

> 好，不过在出稿之前，有两件事会直接决定海报怎么做：
>
> 1. 这张海报用在哪？（这决定了尺寸、信息密度和阅读距离）
>    例如：门店外立牌 / 手机朋友圈 / 外卖平台头图 —— 也可以直接用自己的话说。
> 2. 看完你希望别人做什么？（这决定了信息怎么排优先级）
>    例如：到店 / 下单 / 只是记住品牌。
>
> 你可以只回答现在最确定的部分，其余的先跳过。

**你**：朋友圈发，想让附近的人来店里。

**② 第 2 轮采访（2 问：核心对象 + 模糊词）**

> 明白了。还剩两件：
>
> 1. 店里最想让别人记住的是哪一样？（这决定了画面的核心是什么）
>    —— 单品 / 空间氛围 / 店主本人
> 2. 你说的"高级"，更接近哪种？（这决定了配色和质感往哪走）
>    例：① 极简克制：大面积留白、少字、单色调 ② 材质做工：强调豆子纹理、器具金属质感 ③ 稀缺感：暗场、低调光、拒绝热闹元素
>    —— 也可以完全不按这些，直接描述你想要的

**你**：手冲单品。高级……像那种日式喫茶店，安静、暗一点。

**③ 停止判定**：谁看（附近人）、要什么（单品海报）、怎么算成功（到店）、硬约束（朋友圈竖版）、核心对象与质感（手冲 + 日式暗调）——**全明确，不再追问**。

**④ 出口**

```
# 任务 Prompt
1. 角色与目标：为社区手冲咖啡店设计朋友圈竖版宣传海报，目标是让附近的人产生到店冲动
2. 输入：手冲单品（手冲壶/滤杯/咖啡液面）、日式喫茶店氛围参考
3. 约束：暗调低调光；安静克制，不用促销爆炸元素；文案极简（主标题 ≤8 字 + 店名）
4. 输出格式：1080×1920 竖版，1 张主视觉 + 2 个文案备选
5. 验收标准：0.5 秒内能看出是"手冲咖啡"；整体为暗调；不出现"特价/限时"字样

## 待确认假设
- 主色为深褐 + 暖黄光（源自"日式喫茶店、暗一点"，若不符请指出）
```

注意最后那段：**"日式暗调"是你自己说的，可以进需求区；"深褐 + 暖黄"是 AI 推的，只能进假设区。**（规则见 [`SKILL.md`](SKILL.md) §6.6 与 §2.1）

## 设计原则

> 以下是 [`SKILL.md`](SKILL.md) 规则的面向使用者摘要；判据以协议正文与契约为准。

1. **少问 > 多问**：一轮最多 3 个问题；能默认的不问。
2. **问结构 > 问措辞**：只问答案会改变方案的，不问只影响字面的。
3. **澄清 > 照抄**：模糊词必须被拆成可执行约束。
4. **建议 ≠ 需求**：AI 的所有推测只进「待确认假设」。
5. **知止**：信息够了就停；你说"随便"就降级；你说"直接给"就立刻出稿。
6. **对外说人话**：机制只存在于内部；你只看见"还差什么信息、为什么这几个"（§2.1）。
7. **选对动作 > 多问几个**：能查的别问，能让你看一眼就选的别追问，你不知道自己缺什么就先教，只有真需要你拍板的才问（§11.0）。
8. **消解要留痕**：每条关键缺口记录 `类型 / 动作 / 状态 / 依据 / 结果`；只写"已澄清"不算（§6.6 / 契约 R10）。

已知非目标不在本节展开，权威清单见 [docs/v04/README.md](docs/v04/README.md) 的 **Known Non-goals**。
