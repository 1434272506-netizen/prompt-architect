# Case 04 · 停止规则实战：降级与"别问了"

**演示目标**：规则 8 的下半段——**知道什么时候必须停止提问**。三个片段分别对应 §6.3 的三条降级规则。

---

## 片段 A · 用户连续两轮"随便 / 你决定" → 降级

### 用户

> 帮我做个健身 App 的界面配色。

### 第 1 轮（2 问）

> 还差 2 个：
> 1. 这个 App 主要给谁用？（影响：配色的年龄感与刺激强度）
> 2. 你希望传达什么感觉？（影响：主色与明度关系）

### 用户

> 随便吧，你决定。

### 第 2 轮（只剩 1 问，且改为给方向）

> 那我换个方式：不用你描述，**从下面挑一个最接近的就行**，或者说"都不对"：
>
> - A **清爽运动型**：白底 + 高饱和亮蓝，大量留白，数字放大
> - B **力量训练型**：深灰底 + 高亮橙，重色块，强对比
> - C **温和陪伴型**：米白 + 低饱和绿，圆角，弱对比
>
> 如果这三个都不对，你也可以只说"我想要 A 的底 + B 的强调色"这种混搭。

### 用户

> 都行，你看着办吧。

### 判定：连续 2 轮模糊回应 → 触发 §6.3 降级

**必须停止提问**，直接出稿，并把所有选择明示为**我的假设**：

```
# 任务 Prompt
1. 角色与目标
   为一款健身 App 设计界面配色方案，用于内部评审第一版视觉稿。
2. 输入
   仅已知：产品类别为健身 App；无用户画像、无品牌色、无竞品参考
3. 约束
   - 交付可直接落地的配色表（主色/辅助色/背景/文字/强调/状态色）
   - 同时给出深色模式对应色值
   - 保证文字对比度满足可读性要求
4. 输出格式
   表格：用途 / 色值 / 使用场景说明，并附一句整体风格描述
5. 验收标准
   - 任一界面元素都有指定色值，不存在"待定"
   - 深色与浅色模式逻辑一致

## 待确认假设（用户未回应，均为我的默认选择）
- 目标用户：18～35 岁城市健身人群（未确认）
- 风格：选 C 温和陪伴型为主、以 B 的高亮橙作强调（用户两次回答"都行"，由我代为选择）
- 品牌色：无既有品牌色，按上述风格新拟（未确认）
```

**关键**：降级 ≠ 放弃。是**停止提问**，不是**放弃产出**；但产出里必须看得见哪些是我替用户定的。

## 片段 B · 用户说"别问了，直接给" → 立即出稿

### 用户

> 别问了，直接给我一个清理邮箱的提示词。

### 正确反应（不再问任何问题）

```
# 任务 Prompt
1. 角色与目标
   扮演一位邮件管理助手，帮我把堆积的收件箱清理到"只剩需要我行动的邮件"。
2. 输入
   我将分批粘贴邮件列表（发件人 / 主题 / 日期 / 是否已读）。
3. 约束
   - 不臆测邮件内容，只依据我提供的信息
   - 不确定的邮件一律归入"待我确认"，不得直接建议删除
   - 不得建议退订或回复任何邮件（除非我明确要求）
4. 输出格式
   分四组列表：①立即处理 ②可归档 ③可批量删除 ④待我确认；每组给出判断理由
5. 验收标准
   - 每封邮件都落在某一组里，无遗漏
   - ④组的数量不为零（不确定的必须暴露出来，而不是替我拍板）

## 待确认假设
- 邮箱平台与邮件语言未提供，按通用情况处理（若不符请指出）
- "需要行动的邮件"定义为：来自真人、需要回复或需在 7 天内处理的事项（未确认）
```

**关键**：用户拒绝采访是他的权利。此时**停止提问是义务，标注假设也是义务**——两者不冲突。

## 片段 C · 用户拒答且不授权默认 → 出部分稿 + 只讨一个最小信息

### 用户

> 我要做个员工手册，具体内容我没想好，你先别问那么多。

### 正确反应（给部分稿，只留 1 个阻塞问题）

```
# 任务 Prompt（部分稿）
1. 角色与目标
   起草一份员工手册框架，用于后续填充具体条款。
2. 输入
   暂缺（尚未提供公司规模、行业、已有制度）
3. 约束
   - 只产出结构，不虚构具体制度条款与数值
   - 涉及法定事项（工时、休假、解雇流程）标注"须经专业确认"
4. 输出格式
   目录层级 + 每章一句写作要点
5. 验收标准
   - 框架覆盖：入职 / 考勤 / 薪酬 / 休假 / 行为规范 / 离职 / 申诉
   - 无任何编造的数字或法条

## 阻塞项（只有这 1 个，其余我按默认推进）
- 公司规模（<20 人 / 20～200 人 / >200 人）：它决定手册是"简版"还是需要完整分级制度。
  这一条不确认，框架颗粒度无法定；其余部分我已按通用版起草。
```

**关键**：不做"10 问澄清"，也不假装信息足够。**把阻塞项压缩到 1 个**，其余全部以假设形式给出。

---

## 三条降级规则的边界对照

| 情形 | 能不能继续提问 | 能不能出稿 | 假设要不要标注 |
|---|---|---|---|
| 用户连续 2 轮"随便" | ❌ 停止 | ✅ 出稿 | ✅ 必须 |
| 用户说"别问了" | ❌ 立即停止 | ✅ 出稿 | ✅ 必须 |
| 用户拒答且不授权默认 | ⚠️ 只留 1 个阻塞问题 | ✅ 出部分稿 | ✅ 必须 |

**共同底线**（§7 铁律）：我替用户做的每一个决定，都必须出现在「待确认假设」里。降级出稿的合法性来自"标注透明"，而不是来自"用户没反对"。
