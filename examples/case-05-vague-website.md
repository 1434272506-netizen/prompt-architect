# Case 05 · 用户侧表达基准（"做一个高级的网站"）

**地位：V0.1 黄金样例（Golden Case）**——用户侧表达的冻结基线；今后无论 `SKILL.md` 怎么改，本案例必须持续通过。（本行及下文所有"内部盘点/示范"文字均为**案例元信息**，不在用户可见范围内；用户可见文本仅指以 `>` 引出的对话。）

**演示目标**：内部机制照跑，**用户可见的每一句都是人话**——不出现规则编号、触发信号、七问、P0、工具/环境状态；不预告后续内部步骤；"高级"在用途明确前不解释。

---

## 用户（第 1 句）

> 做一个高级的网站。

## 内部盘点（用户不可见）

```
目标产物:     网站 [? 类型未定]      使用者/场景: [?]
成功标准:     [?]                   硬约束:       [?]
核心对象:     网站 [?]
风格质感:     高级[模糊]  ← 暂不澄清：用途未定
用户状态:     仅形容词，无任何可执行约束
```

**内部判定**：缺「产物/受众/成功标准」→ 启动采访；风格词虽然最显眼，但先问目标。本轮 3 问，全为最高影响项。

---

## 第 1 轮（3 问，用户可见原文）

> 可以，不过"高级网站"现在还缺几个会直接改变方案的信息，我先不急着写最终 Prompt。
> 先确定三个最关键的问题：
>
> 1. 这个网站是做什么的，主要给谁看？
>    例如：产品官网、个人作品集、品牌展示页、工具型 Web 应用。也可以直接用自己的话描述。
> 2. 你希望它最终达到什么效果？
>    比如让访客咨询你、展示作品、完成某个工具操作，或者只是做一个高完成度演示。
> 3. 有没有必须遵守的限制？
>    比如指定技术栈、必须能上线、必须单文件、不能使用外部资源、截止时间等。
>
> 你可以只回答你现在最确定的部分。
> 等用途明确后，我再帮你把"高级"拆成具体、可执行的视觉方向，而不是只停留在一个形容词。

## 用户

> 服务官网，给我潜在客户看的。做完能直接发链接给他们，越简单越好，下周就要。纯静态就行，不用后端。

## 内部盘点（用户不可见）

```
目标产物:     纯静态服务官网 [✓]     使用者/场景: 潜在客户（收到链接后浏览）[✓]
成功标准:     能直接发链接、不丢人 [✓]  硬约束: 纯静态[✓] 不用后端[✓] 一周内[✓]
核心对象:     网站              七问: 是什么[✓ 服务官网] 在哪[✓ 浏览器/手机] 状态[?]
                                   行为[?] 触发[✓ 客户收到链接打开] 影响[✓] 恢复[~ 一次性产物，跳过]
风格质感:     高级[模糊]  ← 用途已明确，本轮可澄清
缺口:         访客的最终动作（行为）+ "高级"方向
```

**内部判定**：信息够问最后 2 问，之后即可出稿。

---

## 第 2 轮（2 问）

> 好，那这个站就按"纯静态 + 能直接发链接"来做。还剩两件：
>
> 1. 访客看完，你最希望他做什么？（这决定第一屏放什么、联系方式怎么摆）
>    例如：加你微信咨询 / 填个表单留下联系方式 / 直接打电话 / 先看看再自己联系。
> 2. 你说的"高级"，更接近哪种？（这决定配色、留白和字量）
>    例：① **极简克制**：大面积留白、字很少、单色调 ② **材质做工**：细腻纹理、金属/哑光质感、细节特写 ③ **稀缺感**：暗场、低饱和、拒绝装饰元素
>    —— 也可以完全不按这些，直接描述你想要的。

## 用户

> 加微信咨询吧。高级就是……干净，留白多，字别太多，别花里胡哨。

## 内部盘点（用户不可见）

```
核心对象: 网站  行为[✓ 引导访客加微信]  状态[~ 默认：常态展示]
风格质感: 高级[✓ 极简克制：大面积留白 + 少字 + 单色调]
未确认项（我推的，必须进假设区）: 单页结构、深色还是浅色、是否放案例图
停止判定: 谁用[✓] 要什么[✓] 怎么算成功[✓] 硬约束[✓] → 足够，不再追问
```

---

## 出口

```
# 任务 Prompt

1. 角色与目标
   做一个纯静态的单页服务官网，发给潜在客户后在手机/电脑上打开，30 秒内看懂"你能提供什么"，并愿意加微信咨询。

2. 输入
   文案素材：服务内容 2～3 项、每项 1～2 句说明（用户提供）
   联系方式：微信号 / 微信二维码
   技术条件：纯静态、无后端、无需登录与数据库

3. 约束
   - 极简克制：大面积留白、每屏文字尽量少（单屏正文 ≤ 2 行）
   - 单色调，不出现高饱和装饰色、渐变爆炸、动效堆砌
   - 视觉层级靠留白与字号，不靠边框、阴影堆叠
   - 不使用外部资源（字体/图床/CDN 依赖尽量自包含），保证打开即可看
   - 一周内可交付；不做后台、不做表单提交接口

4. 输出格式
   单页结构：第一屏（一句话定位 + 一个主行动按钮"加微信咨询"）→ 服务 2～3 项 → 为什么选你（≤3 条）→ 微信二维码 + 一句加好友说明
   交付：可直接双击打开的静态页面（含移动端适配）

5. 验收标准
   - 手机上打开 10 秒内能看清"做什么、怎么联系"
   - 全站无花哨动效、无多色装饰；留白占比明显
   - 微信入口在第一屏和页尾各出现一次
   - 断网/无 CDN 情况下仍能正常显示（不依赖外部资源）

## 待确认假设
- 结构为单页（未与你确认；若你想要多页请指出）
- 主色为浅底深字（"干净、留白多"的常见解读，若你想要暗色请指出）
- 服务项数量暂定 2～3 项，等你给文案后按实际调整
```

---

## 这个例子示范了什么

| 行为 | 对应规则 |
|---|---|
| 用户只说"高级"，首轮仍先问用途/效果/限制，不解释"高级" | §3 优先级、§4 时机 |
| 第 1 轮用户可见文本中**无**"触发信号/P0/七问/SKILL.md"等字样 | §2.1 对外表达 |
| 不预告"下一轮做七问"，只承诺"等用途明确后再拆'高级'" | §2.1、§4 时机 |
| 每轮 ≤3 问，问题后只跟一句重要性说明，不写推理链 | §2 上限、§2.1 |
| 每个问题给示例方向 + 保留"也可以直接用自己的话描述" | §4 硬约束 2 |
| "干净/留白多"被拆成可执行约束（留白占比、单屏字量、单色调、去动效） | §4 模糊词不照抄 |
| 单页结构、浅底深字、服务项数量是我推的 → 只进「待确认假设」 | §7 双轨标记 |
| 全程 2 轮 5 问后即出稿，未追问预算/域名/服务器 | §6.2 停止规则 |
