# Case 02 · 信息已足够 → 不追问，直接出口

**演示目标**：规则 8 的另一面——**不该问的时候一句都不问**。采访机制的价值包含"知道何时不需要采访"。

---

## 用户

> 帮我写一封给客户的道歉邮件。客户是「宏远物流」，我们上周的一批货延迟了 3 天到仓，原因是承运商爆仓。语气要正式，但别太卑微。控制在 300 字以内，中文。

## 内部盘点（用户不可见）

```
目标产物:     道歉邮件 [✓]
使用者/场景:  发给客户「宏远物流」[✓]
成功标准:     正式但不卑微，300 字内 [✓]
硬约束:       中文 [✓] 300 字 [✓]
核心对象:     邮件正文 [✓ 是什么、在哪（邮件正文）、状态（首次道歉）]
              行为[✓ 说明延迟原因 + 致歉] 触发[✓ 延迟 3 天到仓] 影响[✓ 客户关系]
              恢复[~ 默认：提供后续补救口径，无需追问]
风险:         无结构性缺口
待确认建议:   []
```

## 停止判定（§6.1）

| 判据 | 结果 |
|---|---|
| 谁用 / 要什么 / 怎么算成功 / 硬约束 | 全部明确 |
| P0 | 全明确 |
| P1 中会改变结构的维度 | 明确（是什么、行为、触发、影响），"恢复"可默认 |
| 剩余缺口是否只影响措辞 | 是（措辞由"正式但不卑微"约束，属可执行要求） |

→ **足够。不启动采访。**

## 输出（直接出口，0 个问题）

```
# 任务 Prompt
1. 角色与目标
   作为我方对接人，向客户「宏远物流」发一封正式道歉邮件，就上周一批货延迟 3 天到仓致歉，维护合作关系。
2. 输入
   事实：延迟 3 天到仓；原因：承运商爆仓（客观、非我方主观疏忽）
3. 约束
   - 中文；全文 ≤300 字
   - 语气正式，但不卑微：承担沟通责任，不反复自责、不夸张赔罪
   - 说明客观原因，但不把责任全推给承运商
   - 不承诺未确认的赔偿条件
4. 输出格式
   邮件正文（含称呼与署名占位符），无额外解释文字
5. 验收标准
   - 字数 ≤300
   - 读完不觉得"低三下四"，也不觉得"在甩锅"
   - 给出一个可执行的后续动作（如：后续批次节点提前同步）

## 待确认假设
- 后续补救口径按"提前同步后续批次节点"处理（未与你确认，若不符请指出）
- 我方对接人姓名与联系方式以占位符保留（未提供）
```

---

## 对照：如果这封信的用户只说了"帮我写个道歉邮件"

那就**必须**启动采访，1～3 问即可：

> 还差 2 个：
> 1. 这封信是发给谁的、因为什么事？（影响：措辞分寸与责任边界）
> 2. 你希望对方读完做什么？（影响：结尾是"致歉"还是"致歉 + 补救方案"）

**边界就在这里**：采访不是流程表演。信息足够的请求，采访轮次 = 0。
