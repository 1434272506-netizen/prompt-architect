# 测试用例 · Prompt Architect V0.1

> **V0.3 适用性说明（2026-10-01 裁定）**：本文件诞生于 V0.1，用例中的「关联规则 R1–R8」是 **`SKILL.md` 核心规则 R1–R8**（采访层）。
> V0.3 引入了另一套独立命名空间 **契约 R1–R13**（`core/uncertainty-classifier.md` 的 Type/动作层规则），**两套恰好与旧编号重号**。
> 因此：本文件裸写的 `R1`–`R8` **一律指核心规则**；引用契约规则时必须写全"契约 Rn"。相关警示见 `docs/failure-map.md`。
> **T-05 已在 V0.3 下加注**（P0 语义例外，契约 R11 / `SKILL.md` §11.0 规则 8）；其余用例在 V0.3 下是否需要重跑，见 `docs/failure-map.md` 的测试盲区 B13。

**性质**：纯手工/agent 可执行的判定用例，**不依赖任何测试框架**（V0.1 不引入依赖）。
**执行方式**：

1. 把用例的「输入」原样发给一个**已装载 `SKILL.md`** 的 agent（新会话，避免上下文污染）
2. 如需多轮，则按用例标注继续发送「用户后续」
3. 收集：轮次数 / 每轮问题数 / 最终输出全文
4. 按「通过判据」逐条打勾；**命中任一「失败判据」即整例失败**

**记录模板**：

```
用例 ID:        轮次数:        每轮问题数:
通过判据命中:   __/__         失败判据命中: __
判定: ☐ PASS ☐ FAIL       证据摘录:
```

## 一、正向用例（期望规范行为）

### T-01 · 明显不完整 → 启动采访，不首轮出稿
- **关联规则**：R1
- **输入**：`帮我做个高级的咖啡店海报`
- **通过判据**：
  1. 首轮不出现 5 段组装中的 ≥2 段
  2. 首轮说明"还缺什么"
  3. 首轮问题数 1～3
- **失败判据**：首轮直接给出完整 Prompt / 未说明缺什么

---

### T-02 · 信息完整 → 0 问直接出口
- **关联规则**：R8、机制完整性
- **输入**：`帮我写一封给客户"宏远物流"的道歉邮件：上周一批货延迟3天到仓，原因是承运商爆仓；语气正式但别太卑微；300字以内；中文。`
- **通过判据**：
  1. 提问数 = 0
  2. 直接输出 5 段 + 假设区
- **失败判据**：出现任何追问（例如"请问客户名称是？"这类已知信息）

---

### T-03 · 用户说"别问了直接给" → 立即出稿
- **关联规则**：R8
- **输入**：`别问了，直接给我一个清理邮箱的提示词`
- **通过判据**：
  1. 0 个提问
  2. 输出含「待确认假设」区
  3. 缺省信息以假设形式出现，未编造为事实
- **失败判据**：任何形式的"为了更准确，能否告诉我…"

---

### T-04 · 每轮 ≤3 问
- **关联规则**：R2
- **输入**：`帮我做一个介绍我们公司的短视频，要科技感`
- **通过判据**：每一轮问题数均 ≤3 且 ≥1（含 2～4 轮）
- **失败判据**：任一轮 ≥4 问，或首轮抛出 6～7 个"七问清单"

---

### T-05 · 风格词与目标同缺时，优先问目标
- **关联规则**：核心规则 R3；**V0.3 追加：契约 R11（P0 语义例外）**
- **输入**：`我要一个电影感的方案`（无产物、无受众、无场景）
- **通过判据**：首轮问题主要集中在**要什么产物 / 给谁用 / 怎么算成功**；风格澄清排在后面
- **失败判据**：首轮就问"你说的电影感是指调色还是运镜"而未问目标
- **V0.3 加注（2026-10-01 裁定）**：本例在 V0.3 下**仍然有效，且不可被 §2.5 Step 3 短路掉**。
  "电影感"命中 Type B 的**分类**不变（§2.5 Step 3 只判定该缺口的 Type，**不决定整轮的先后顺序**），
  但因 **P0 语义整类缺失**，按 **契约 R11 / §11.0 规则 8**：目标缺口先走 ASK，**SHOW 让位**。
  拿到目标后再对该模糊词执行 SHOW（§4 模糊词协议）。**失败判据不变**：先追问风格细节、不问目标 = FAIL。

---

### T-06 · 模糊词不被照抄进需求区
- **关联规则**：R5
- **输入**：`帮我写个产品文案，要自然一点，别太 AI`
- **通过判据**：
  1. 采访中对"自然"做了澄清（目的反推 / 参照物 / 方向择选任一）
  2. 最终「约束」区不含未澄清的"自然"二字，或含但已附澄清定义
- **失败判据**：约束区原样出现"要自然一点"且无任何澄清

---

### T-07 · 方向正交性
- **关联规则**：R6
- **输入**：`我想做个人网站，但不知道该怎么描述，你看着办`
- **通过判据**：
  1. 给出 2～4 个方向
  2. 每个方向可归入不同维度（如用途/形态），无"同一维度仅程度差异"的对
  3. 明确允许不按选项、自由描述
- **失败判据**：出现"很高级 / 更高级 / 超级高级"这类程度阶梯；或只给选项不给自由通道

---

### T-08 · 用户给出选项之外的路 → 直接采用
- **关联规则**：R6、R4
- **输入**：T-07 的后续：`都不太像……我想要那种别人加我微信前能大概了解我，但我不想天天更新，也不要像简历那么正式`
- **通过判据**：
  1. 不把用户拉回原选项、不辩解
  2. 用户自述原样进入需求/约束区（如"不做博客模块""不用简历排版"）
- **失败判据**：回复中出现"那你要不要考虑一下 A 或 B？"这类回拉

---

### T-09 · AI 建议只进假设区
- **关联规则**：R4、R7
- **输入**：`帮我做个儿童绘本的插画方案，主角是小狐狸`
- **通过判据**：所有我推的内容（配色、画风、页数）都在「待确认假设」区；需求区仅含用户确认信息
- **失败判据**：需求区出现任何用户未说过的具体选择

---

### T-10 · 七问按需，不机械问满
- **关联规则**：R7
- **输入**：`帮我设计一个线下店的会员卡`
- **通过判据**：
  1. 问到与"卡"结构相关的维度（是什么/在哪用/何时触发/影响什么）
  2. **未**出现"动作结束后如何恢复？"这类对一次性实体卡无意义的问题
- **失败判据**：把 7 问逐条列成清单抛出；或对一次性产物强行追问"恢复"

---

### T-11 · 信息足够即停
- **关联规则**：R8
- **输入**（第 2 轮后信息已齐）：`就这些了，够了`
- **通过判据**：下一轮直接出口，无追加问题
- **失败判据**：出现"为了更稳妥，还想确认一下预算/风格/交期"

---

### T-12 · 授权默认 → 立即停止追问
- **关联规则**：§6.3（授权默认）、§3.2
- **输入**：`帮我做个健身 App 的界面配色`
- **用户后续**：`随便吧，你决定` → （若仍被追问）`都行，你看着办吧`
- **通过判据**：
  1. 出现授权默认的**那一轮**即停止追问并出稿
  2. 所有 AI 自定的选择全部在「待确认假设」区
  3. "随便/你决定"**不被记作** unresolved
- **失败判据**：把授权默认当 unresolved 继续追问；或出稿但不标注假设

---

### T-12b · unresolved 计数（"不知道"与"答非所问"同口径）
- **关联规则**：§3.2、§6.3
- **输入**：`帮我做个网站` → 问受众 → 答 `我想要深色的` → 再问受众 → 答 `这个我不知道`
- **通过判据**：
  1. "深色"被吸收保存
  2. 受众缺口 unresolved = 2
  3. 若该缺口阻塞 → 输出可完成部分 + 说明仍缺哪个决定；若为非阻塞 → 默认值进假设区
- **失败判据**：第三次换措辞追问；或把"不知道"与"随便"混为一类处理

---

### T-13 · 拒答且不授权默认 → 部分稿 + 只留 1 个阻塞问题
- **关联规则**：R8、R4
- **输入**：`我要做个员工手册，内容我没想好，你先别问那么多`
- **通过判据**：
  1. 给出可用框架（部分稿）
  2. 阻塞问题 ≤1 个
  3. 未编造具体数值或法条
- **失败判据**：抛出 4 个以上问题；或编造具体制度数字

---

### T-14 · 出口结构完整
- **关联规则**：机制完整性
- **输入**：任一信息完整的请求（如 T-02 输入）
- **通过判据**：5 段齐全 + 「待确认假设」独立成区 + 结尾确认句（"哪一条不对告诉我编号"）
- **失败判据**：缺任一段；假设混在需求区；结尾无确认邀请

---

### T-15 · 不重复提问
- **关联规则**：R8
- **输入**（多轮，用户已答"用于抖音投放"）：后续再问时长与平台
- **通过判据**：任何已给信息不再被问第二次，也不换措辞再问
- **失败判据**：第二次询问同一信息

---

### T-16 · 用户侧不泄露内部机制
- **关联规则**：§2.1 对外表达
- **输入**：`做一个高级的网站`
- **通过判据**：
  1. 首轮回复中**不含**机制词：`SKILL.md`、`触发信号`、`P0/P1/P2/P3`、`七问`、`采访循环`、`槽位`、`停止规则`
  2. 回复中**不含**工具/环境状态（文件挂载、服务、引擎、日志），除非该状态改变交付结果（此时须用业务语言表述）
  3. **不预告**后续内部步骤；不解释"高级"，但可以承诺"用途明确后再拆成具体方向"
  4. 问题 ≤3，每个问题至多跟一句重要性说明，且不出现推理链（"因为优先级要求…所以…"）
- **失败判据**：命中上述任一项
- **参照基线**：[case-05-vague-website.md](../examples/case-05-vague-website.md)
