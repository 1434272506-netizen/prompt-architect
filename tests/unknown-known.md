# 专项测试 · Type B（Unknown Known）→ SHOW

> **被测契约**：[core/uncertainty-classifier.md](../core/uncertainty-classifier.md) §2（Type B 判据）、§3（SHOW 动作与硬边界）、§4（决策树 Step 3，逐条短路）、§5（契约 R2 / 契约 R5 / 契约 R7）、§7（§6.3 挂接行）、§8（反模式）。
> **正文挂接**：`SKILL.md` §2.5（三条规定：能查不问 / 能选不追 / 先教再问）、§2.1（对外表达）、§4（模糊词协议，V0.3 下降级为 SHOW 的方向素材库）、§11.0（动作选择优先于问题排序）、§11.4（Q4 选项质量）。
> **案例总数：11**（Test 01–03 为用户指定的三个强制接口案例 + UB-04–UB-11）。
>
> **命名空间警示**：本文所有 `R n` 一律指**契约 Rn**（[core/uncertainty-classifier.md](../core/uncertainty-classifier.md) 的契约 R1–R13），与 `tests/acceptance.md` / `tests/cases.md` 的 V0.1 **核心规则 R1–R8** 是两套独立编号，恰好重号。
>
> **三个强制案例的类型分布**：Test 01 = Type B / SHOW；Test 02 = Type E / INSPECT（验 契约 R1）；Test 03 = Type C / TEACH。它们被放在本文件首位，是因为三者共用同一条判定链——**动作由 Type 决定，不由"用户说了什么词"决定**；放在一起才能验出"动作优先级被颠倒"这一类失败。
>
> **裁定口径**：`唯一` = 依现行契约只能得出同一动作；`有判断余量` = 动作唯一、取值靠判断（不算缺口）；`不唯一` = 两种读法都自洽（**必须报告，不得自行补规则**）。

**执行方式**（与 `tests/cases.md` 一致）：

1. 把用例的「输入」原样发给一个**已装载 `SKILL.md` 的** agent（新会话，避免上下文污染）
2. 如需多轮，按用例标注继续发送「用户后续」；「环境/前置」为执行测试前必须准备好的只读环境事实
3. 收集：轮次数 / 每轮动作块（SHOW 方向数、ASK 题数、TEACH 条数）/ 最终输出全文 / 内部决策记录
4. 按「通过判据」逐条打勾；**命中任一「失败判据」即整例失败**

**记录模板**：

```
用例 ID:        轮次数:        本轮动作: SHOW__ ASK__ TEACH__
通过判据命中:   __/__         失败判据命中: __
判定: ☐ PASS ☐ FAIL       证据摘录:
```

## 一、三个强制接口案例

### Test 01 · 模糊审美：连续追问 = 失败（强制）
- **输入**：`做一个高级官网`
- **环境/前置**：全新项目，无可读代码库（排除 Type E，保证 Type B 是首个命中的分支）
- **唯一正确动作**：**Type B → SHOW**（3 个差异明显的方向）
- **通过判据**：
  1. 首轮给出**恰好 3 个**方向，且方向按**不同维度**切分（如：极简科技 / 编辑杂志 / 暗色沉浸），不是同一维度的程度差异
  2. 首轮**不产出完整 5 段 Prompt**（SHOW 不是交付，只给"够判断"的粗略草案）
  3. 保留自由描述通道（"也可以直接说你的想法，或给我一个你觉得'高级'的例子"）
  4. 首轮问题数 0～1（若附 1 个非模糊词问题，只允许是用途/受众这类结构性缺口，且不得与方向选择混成同一问）
  5. 用户可见文本不含机制词（§2.1）
- **失败判据**：
  1. **连续追问"高级是什么 / 喜欢什么颜色 / 什么风格" = 失败**（契约 R2、SHOW 硬边界）
  2. 以"你说的'高级'具体指什么？"作为首问 = 失败（把 Type B 当 Type A 处理）
  3. 3 个方向写成"①很高级 ②更高级 ③极致高级" = 失败
  4. 首轮直接交付成品或完整 Prompt = 失败
- **为何契约 R11（P0 语义例外）不触发**：本案例 P0 **不是整类缺失**——"官网"已给出产物类别，受众与成功标准缺失属"部分依据"。按 契约 R11 边界（`SKILL.md` §11.0 规则 8）"只补缺项，**不冻结 SHOW 直到 P0 全齐**"，故 Type B → SHOW 仍然成立；缺的 P0 项按 契约 R4 / §11.0 规则 7 排在 SHOW 结果处理完之后。对照见 UB-11（P0 整类缺失 → 反而必须 ASK 让位）。
- **关联规则**：契约 §2 Type B、§3 SHOW 硬边界、§4 Step 3、契约 R2、契约 R7、契约 R11（边界，不触发）、§8 反模式第 1 行；`SKILL.md` §2.5 规则 2、§2.1、§4、§11.0 规则 8
- **唯一裁定**：**唯一**

### Test 02 · 可读取信息：环境已有 requirements.txt（强制，验证 契约 R1）
- **输入**：`帮我升级这个 Python 项目`
- **环境/前置**：项目根目录存在且只读可读：`requirements.txt`（含 `django==3.2.5`、`requests==2.28.1`）、`runtime.txt`（`python-3.9.18`）
- **唯一正确动作**：**Type E → INSPECT**（先读环境，输出事实 + 出处）
- **通过判据**：
  1. 首轮动作 = INSPECT：读取 `requirements.txt` 与 `runtime.txt`
  2. 结论以**事实 + 证据出处**给出（"当前锁定 Django 3.2.5、Python 3.9.18 —— `requirements.txt` / `runtime.txt`"）
  3. 若仍需用户拍板的升级目标（是否跨大版本、能否停机）→ 属 Type A，可 ASK；但**已能读到的事实一律不问**
  4. INSPECT 全程只读：未修改任何文件、未执行 `pip install` / 升级 / 构建命令
- **失败判据**：
  1. **问"Python 版本是多少？"= 失败**（契约 R1）
  2. 问"你们用 Django 哪个版本？"= 失败（同一失败模式，换个字段）
  3. 未读环境就直接给升级步骤或升级建议 = 失败（跳过 Step 2）
  4. 执行任何改变仓库或环境状态的命令 = 失败（INSPECT 只读硬边界）
- **关联规则**：契约 §2 Type E、§3 INSPECT 硬边界、§4 Step 2、契约 R1、§8 反模式第 2 行；`SKILL.md` §1 触发信号 6、§2.5 规则 1、§11.0 规则 2
- **唯一裁定**：**唯一**

### Test 03 · 用户不知道风险：自动交易机器人（强制）
- **输入**：`我要做一个自动交易机器人`
- **环境/前置**：无（此案例不依赖环境；TEACH 的触发不要求任何文件）
- **唯一正确动作**：**Type C → TEACH**（≤3 条，每条讲后果）→ **随后重跑决策树（契约 R9）**
- **通过判据**：
  1. 首轮是一个 TEACH 块，条目 **≤3**
  2. 覆盖用户未意识到的四个风险点，且**合并进 3 条**：资金风险与最大回撤 / 行情数据来源与时延（回测 ≠ 实盘）/ 下单权限与不可逆操作
  3. **每条都讲后果**（"回测里赚钱的策略常在上线后因为滑点和时延亏钱，先小资金验证"），不是只报名词
  4. 不要求用户立即回答、不制造焦虑（契约 R3：只需知晓）
  5. TEACH 之后按 Step 1–4 **重新分类**该缺口，不沿用旧分类（契约 R9）；记录为 `动作：taught`，且不改变任何需求状态（§6.6 约束 4）
  6. 首轮**不产出功能设计、模块结构、技术选型或代码**
- **失败判据**：
  1. **直接设计功能 = 失败**（"先给你一个均线策略的模块结构"）
  2. 跳过 TEACH 直接问"你用哪家券商的 API？""准备多少本金？" = 失败（问用户答不出的问题，契约 R3）
  3. TEACH 条目 ≥4 = 失败；只列风险名词不讲后果 = 失败
  4. TEACH 后直接出 5 段 Prompt 而未重分类 = 失败（契约 R9）
- **关联规则**：契约 §2 Type C、§3 TEACH 硬边界、§4 Step 5、契约 R3、契约 R4、契约 R9、§8 反模式第 3 行；`SKILL.md` §1 触发信号 5、§2.5 规则 3、§6.6
- **唯一裁定**：**唯一**

## 二、Type B 边界案例（UB）

### UB-04 · 参照物型目标（"像苹果官网那种简洁"）
- **输入**：`帮我做个产品页，像苹果官网那种简洁`
- **唯一正确动作**：**Type B → SHOW**
- **通过判据**：
  1. 判为 Type B（参照物是 Type B 判据明文列举的三种证据形态之一）
  2. 给出 3 个方向，且方向**从参照物派生到不同维度**（如：大图留白叙事 / 参数表密集 / 单屏一句断言）
  3. 允许并鼓励用户改选或混搭
- **失败判据**：
  1. 以"你说的'简洁'是指留白多还是字体少？"作首问 = 失败（契约 R2）
  2. 追问"苹果官网你最喜欢哪一部分？"并以此**替代** SHOW = 失败（参照物法是方向素材来源，不是追问许可）
  3. 把参照物当 Type A 待定项记录（"视觉方向待定，需用户澄清"）= 失败
- **关联规则**：契约 §2 Type B、§3 SHOW、§4 Step 3、契约 R2；`SKILL.md` §2.5 规则 2、§4（参照物法）
- **唯一裁定**：**唯一**

### UB-05 · 同轮 B + A：先 SHOW，本轮不塞 ASK（依改写后的契约 R4）
- **输入**：`做一个高级官网，另外后端用 MySQL 还是 PostgreSQL？`
- **环境/前置**：全新项目，无可读代码库（排除 Type E，保证技术选型缺口成立为 Type A）
- **唯一正确动作**：**Type B → SHOW**（本轮只做 SHOW）；技术选型缺口 **Type A → ASK 延后到下一轮**（拿到方向选择后再单独问，1 题）
- **通过判据**：
  1. 本轮只执行 SHOW：给出 3 个差异明显的方向；"高级"未被当作待定项追问
  2. **本轮 0 个 ASK 题**——数据库问题**不得**塞进同一轮（契约 R4 改写版 + `SKILL.md` §11.0 规则 7："SHOW 与 ASK 同轮时，SHOW 的结果必须先处理完"；本轮 SHOW 尚未拿到选择）
  3. 明确进入等待用户对方向的选择 / 修改 / 混搭（契约 R2：SHOW 之后只接收选择、修改、混搭）
  4. 拿到方向选择后重跑决策树（契约 R9），下一轮单独问数据库：1 题 + 一句影响说明
  5. 同轮容量不超上限：≤1 个 TEACH 块 + 1 组 SHOW + 1 组 ASK（本轮实际只用 1 组 SHOW）
- **失败判据**：
  1. 把"高级"当 Type A 追问 = 失败（契约 R2）
  2. **本轮同时出现 SHOW 与数据库 ASK = 失败**（违反 §11.0 规则 7）
  3. 以数据库问题开场、把 SHOW 推到后面 = 失败（§11.0 层级顺序不可颠倒）
  4. 只 ASK 不 SHOW = 失败；因为要处理数据库问题而**跳过** SHOW = 失败
- **为何契约 R11 不触发**：产物（官网）已知，P0 非整类缺失，契约 R11 边界禁止扩大解释
- **关联规则**：契约 R4（改写版："同轮有容量、且有顺序"：`INSPECT → SHOW → TEACH → ASK`）、契约 R2、契约 R9、契约 R11（边界）、§3 动作优先级；`SKILL.md` §11.0 规则 1–2、5–8 与示例
- **唯一裁定**：**唯一**（动作唯一：本轮 SHOW，ASK 排下一轮）

### UB-06 · "随便你定"是授权默认，不是 Type B
- **输入**：`配色你随便定吧，这块我不挑`
- **环境/前置**：P0（目标 / 产物 / 成功标准）已齐；配色属**非阻塞项**
- **唯一正确动作**：**§6.3 授权默认 → 不 SHOW、不 ASK** → 合理默认值 + 显式进「待确认假设」
- **通过判据**：
  1. 本轮 **0 个问题、0 组方向**
  2. 默认配色写入「待确认假设」区，并注明"若不符请指出"（§7 铁律 2）
  3. "随便"**不计** unresolved（§3.2）
  4. 直接进入可交付阶段
- **失败判据**：
  1. 把"随便"判成 Type B，SHOW 3 个配色方案让用户挑 = 失败
  2. 记一次 unresolved 并继续追问配色 = 失败
- **关联规则**：契约 §7 挂接表（§6.3 行："随便/你决定"= 授权默认，**不是 Type B**）、契约 R8；`SKILL.md` §6.3、§3.2、§7
- **唯一裁定**：**唯一**

### UB-07 · SHOW 不是交付
- **输入**：`帮我做一个产品落地页，要有高级感`
- **唯一正确动作**：**Type B → SHOW**（只给"够判断"的粗略草案）
- **通过判据**：
  1. 3 个方向，每个方向是**草图级**描述（结构 + 调性 + 一句话说明），足以让用户判断取舍
  2. 输出中**不含**编号 1～5 的完整 5 段组装内容
  3. 不把 SHOW 当交付：SHOW 之后仍需完成采访与组装
- **失败判据**：
  1. 首轮直接输出完整 5 段 Prompt = 失败（把 SHOW 当交付）
  2. 以"方向都给你了，直接拿去做吧"结束且未进入后续采访/组装 = 失败
  3. 方向描述细到可直接施工（完整文案 + 完整样式规范）= 失败（越界成成品）
- **关联规则**：契约 §3 SHOW 硬边界（"SHOW 不是交付"）、§8 反模式第 6 行；`SKILL.md` §2.5、§8
- **唯一裁定**：**唯一**

### UB-08 · 两轮 SHOW 仍无法判断 → 契约 R7 升级路径
- **输入（多轮）**：
  - 第 1 轮：`做一个高级官网`
  - 第 2 轮（收到 3 个方向后）：`都差不多，我说不上来`
  - 第 3 轮（收到提高保真度的第二组方向后）：`还是不知道，你看着办`
- **环境/前置**：同 Test 01
- **唯一正确动作**：第 2 轮 → **提高保真度再 SHOW 一次**；第 3 轮 → **不再 SHOW**，走默认值 + 写入「待确认假设」
- **通过判据**：
  1. 第 2 轮产出第二组方向，保真度高于第 1 轮（更具体的草案 / 示意 / 对比度说明），而**不是**换措辞追问模糊词
  2. 第 3 轮 0 个新方向、0 个模糊词追问；默认值进假设区并注明"若不符请指出"
  3. 决策记录中 `shown` 两次之后状态仍为「待决定」，默认项另起一行记录（§6.6 约束 3）
  4. 两轮 SHOW 的上限被尊重：第 3 轮**不得**第三次 SHOW
- **失败判据**：
  1. 第 2 轮就放弃 SHOW、直接采用默认值 = 失败（契约 R7：必须先提高保真度再试一轮）
  2. 第 2 轮换措辞追问"你到底偏好哪种感觉？" = 失败（契约 R2）
  3. 第 3 轮第三次 SHOW = 失败（超出 契约 R7 的两轮上限）
  4. 把 `shown` 提前写成「用户已确认」= 失败（§6.6 约束 3）
- **关联规则**：契约 R7、契约 R2、§6 填写约束 3；`SKILL.md` §2.5 规则 2、§3.2、§6.3
- **唯一裁定**：**唯一**

### UB-09 · SHOW 方向正交 + 保留自由通道
- **输入**：`帮我写个短视频脚本，要有电影感`
- **环境/前置**：P0 基本齐（竖版 30 秒、投放抖音）
- **唯一正确动作**：**Type B → SHOW**（3 个正交方向）
- **通过判据**：
  1. 方向按**维度**切分（如：光影叙事 / 手持纪实 / 冷调定格），无"同一维度仅程度差异"的对
  2. 明确保留自由描述通道（"也可以直接用自己的话描述，或给一个参考片段"）
  3. 选项质量：允许把带依据的「（推荐）」**置首**，但依据必须来自**用户已说信息**或**成本/风险事实**（如"你投抖音竖版，竖版更合适（推荐）"）；禁止"最新 / 最好 / 最流行"这类价值判断
- **失败判据**：
  1. 方向写成"①很电影感 ②非常电影感 ③极致电影感" = 失败
  2. 只给选项、不给自由描述通道 = 失败
  3. 「（推荐）」的依据不是用户已说信息或成本/风险事实（如"最新方案（推荐）""最好的一种"）= 失败
- **关联规则**：契约 §3 SHOW（"差异明显"是硬要求）、§11.4（Q4 中立 / 正交 / 代表性 / 自由通道）；`SKILL.md` §4、§11.4
- **残留待同步（已上报 lead）**：本判据依 **lead 裁定**（允许有依据的推荐）编写；`SKILL.md` §11.4 第 1 条当前正文仍写"禁止'最新方案（推荐）'这类写法"，两条口径需对齐，否则又会产生一处正文与裁定不一致。
- **唯一裁定**：**唯一**

### UB-10 · SHOW 的用户可见文本不得出现机制词
- **输入**：`做一个高级官网`
- **环境/前置**：同 Test 01
- **唯一正确动作**：**Type B → SHOW**，且用户可见文本使用日常语言
- **通过判据**：
  1. 回复中**不含**机制词：`Type B`、`unknown known`、`SHOW`、`决策树`、`契约 R2`、`§2.5`、`分类`
  2. 不预告内部步骤（不写"我先对你的需求做一次分类""下一轮我会执行 SHOW"）
  3. 需要解释时只说影响（"这几个方向会影响整体调性和信息密度"），不写推理链
- **失败判据**：
  1. 出现任一机制词 = 失败
  2. 出现"我先分类一下你的问题" = 失败（§11.0 规则 3：分类不得成为外露的拖延借口）
  3. 解释方向时写"因为契约要求 3 个正交方向，所以…" = 失败
- **关联规则**：契约 §7（§2.1 挂接行）、§8 反模式；`SKILL.md` §2.1、§2.5 用户侧语言、§11.0 规则 3
- **唯一裁定**：**唯一**

### UB-11 · 契约 R11：P0 整类缺失 → ASK 目标，SHOW 让位
- **输入**：`我要一个电影感的方案`
- **环境/前置**：无产物、无受众、无场景、无成功标准 —— P0 三类语义槽位**整类缺失**
- **唯一正确动作**：**先按 Type A 走 ASK**，问 P0 目标缺口（1–3 题）；**SHOW 让位**（本轮不给方向扇）
- **通过判据**：
  1. 分类**仍是 Type B**（"电影感"= 形容词 / 感受，契约 §2 Type B 判据不变，**不违反 契约 R2**）
  2. 但**整轮顺序由契约 R11 接管**：本轮只问 P0（要什么产物 / 给谁用 / 怎么算成功，≤3 题），**不出现方向扇**
  3. 说明承诺：拿到目标后再对"电影感"执行 SHOW（契约 R11："拿到目标后对同一模糊词执行 SHOW 即可"）；不预告内部流程（§2.1）
  4. 判定可复述为：**§2.5 Step 3 只判定"该缺口是什么 Type"，不决定"整轮先做哪个动作"**
- **失败判据**：
  1. **先追问风格细节 = 失败**（"你说的电影感是指调色还是运镜？"）—— 这既是契约 R2 禁止的连续追问，也是 契约 R11 要求让位的对象
  2. 直接 SHOW 3 个风格方向 = 失败（目标未定，方向可能整体不适用，违反 契约 R11）
  3. 本轮既问 P0 又给方向扇 = 失败（同轮铺开，违反契约 R4）
  4. 因为 契约 R11 就不再把它记为 Type B、或直接当 Type D 出稿 = 失败（**分类与动作时序是两件事**）
- **关联规则**：契约 R11（P0 语义例外）、§3 例外块（"不冲突：Type B 仍被正确分类，只是动作时序让位"）、契约 R2、契约 R4、契约 R9；`SKILL.md` §11.0 规则 8；既有案例 `tests/cases.md` T-05（lead 已加 V0.3 加注）
- **唯一裁定**：**唯一**
- **与 Test 01 的对照（契约 R11 边界的两侧）**：Test 01（"做一个高级官网"）P0 仅**部分**缺失 → 契约 R11 **不**触发 → SHOW；UB-11 P0 **整类**缺失 → 契约 R11 触发 → ASK。两例合起来界定 契约 R11：**不得被扩大成"任何情况下都先问目标"**。
