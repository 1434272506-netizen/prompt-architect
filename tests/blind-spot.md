# 专项测试 · Type C（Unknown Unknown）→ TEACH

> **被测契约**：[core/uncertainty-classifier.md](../core/uncertainty-classifier.md) §2（Type C 判据："用户未意识到该缺口存在；踩空会造成返工、风险或不可逆后果"）、§3（TEACH 硬边界："一次 ≤3 条；不制造焦虑、不要求用户立即回答；只讲后果与最低必要知识"）、§4（决策树 Step 5，**输出后按 Step 2–4 重新分类**）、§5（契约 R3 先教再问、契约 R4 一次只推进一步、契约 R5 混合处理、契约 R6 阻塞项不可 DISCOVER、契约 R9 发现即重分类、**契约 R12 备注中的 Type C 不得永久搁置**）、§6 填写约束 4、§8 反模式。
> **正文挂接**：`SKILL.md` §1（触发信号 5：用户未意识到且踩空会返工或不可逆的缺口）、§2.5（规则 3 先教再问）、§3.1（Conflict/Tension）、§6.3、§6.6、§11.0（规则 5 同轮容量）。
> **案例总数：9**（BS-01–BS-09；BS-01 AI 客服与 BS-02 自动交易机器人为用户指定的强制案例；BS-07 / BS-09 为契约 R12 专项）。
>
> **命名空间警示**：本文所有 `R n` 一律指**契约 Rn**（[core/uncertainty-classifier.md](../core/uncertainty-classifier.md) 的契约 R1–R13），与 `tests/acceptance.md` / `tests/cases.md` 的 V0.1 **核心规则 R1–R8** 是两套独立编号，恰好重号。
>
> **三条贯穿全部案例的判据**（任一命中即该例失败）：
> 1. **TEACH 条目 >3 = 失败**；把多个风险点塞成 4 条以上同样失败（要求合并，不要求舍弃）。
> 2. **只列风险名词、不讲后果 = 失败**（TEACH 的产出是"会发生什么"，不是清单）。
> 3. **跳过 TEACH 直接问用户答不出的问题、或直接开始设计 = 失败**（契约 R3）。
>
> **裁定口径**：`唯一` = 依现行契约只能得出同一动作；`有判断余量` = 动作唯一、取值靠判断（不算缺口）；`不唯一` = 两种读法都自洽（**必须报告，不得自行补规则**）。

**执行方式**（与 `tests/cases.md` 一致）：

1. 把「输入」原样发给**已装载 `SKILL.md` 的** agent（新会话）
2. 按用例标注继续发送「用户后续」
3. 收集：首轮动作块与顺序 / TEACH 条目数 / 每条是否含后果 / 是否出现设计或技术选型 / 是否重跑分类 / 内部决策记录
4. 按「通过判据」逐条打勾；**命中任一「失败判据」即整例失败**

**记录模板**：

```
用例 ID:        轮次数:        TEACH 条数: __ /3
每条是否含后果: __/__         是否跳过 TEACH: ☐ 否 ☐ 是
TEACH 后是否重分类: ☐ 是 ☐ 否
判定: ☐ PASS ☐ FAIL       证据摘录:
```

## 一、两个强制案例

### BS-01 · AI 客服（强制）
- **输入**：`我要做一个 AI 客服`
- **环境/前置**：无（TEACH 不需要任何环境事实；本案例不得走 INSPECT 代替 TEACH）
- **唯一正确动作**：**Type C → TEACH**（≤3 条）→ 随后按 Step 1–4 **重新分类**（契约 R9）
- **通过判据**：
  1. 首轮是**一个** TEACH 块，条目 **≤3**
  2. 覆盖用户未意识到的四个风险点，且**合并进 3 条**：
     - 数据来源与知识边界（知识库里没有的，模型会自己编）
     - 权限与越权动作（客服能查/能改/能赔到什么程度）
     - 答错兜底与人工接管（错答谁负责、什么情况必须转人工）
  3. **每条都讲后果**，例如："如果知识库没覆盖到，它会给一个看起来非常确定的错误答案，客户照着做，最后要你和人工一起收拾。"
  4. 不要求用户立即回答、不制造焦虑（契约 R3）
  5. TEACH 之后重新跑决策树：此时"知识库在哪、有没有现成文档"可能变成 Type E → INSPECT，而不是继续教
  6. 决策记录：`动作：taught`，本身**不改变任何需求状态**，后续动作另起一行（§6.6 约束 4）
  7. 首轮**不产出**对话流程设计、技术栈、接口清单
- **失败判据**：
  1. **跳过 TEACH 直接问"你想接哪些数据源？"= 失败**（契约 R3：问用户答不出的问题）
  2. 直接开始设计对话流程或系统架构 = 失败
  3. TEACH 条目 ≥4 = 失败（"数据来源/权限/幻觉/人工接管"四点必须合并为 3 条）
  4. 只列名词不讲后果 = 失败
  5. TEACH 后不重跑分类、直接出 5 段 Prompt = 失败（契约 R9）
- **关联规则**：契约 §2 Type C、§3 TEACH 硬边界、§4 Step 5、契约 R3、契约 R4、契约 R9、§6 约束 4、§8 反模式第 3 行；`SKILL.md` §1 触发信号 5、§2.5 规则 3
- **唯一裁定**：**唯一**

### BS-02 · 自动交易机器人（强制）
- **输入**：`我要做一个自动交易机器人，帮我设计一下`
- **环境/前置**：无
- **唯一正确动作**：**Type C → TEACH**（≤3 条）→ 随后重跑决策树（契约 R9）
- **通过判据**：
  1. 首轮是**一个** TEACH 块，条目 **≤3**
  2. 覆盖四个风险点，且**合并进 3 条**：
     - 资金风险与最大回撤（亏到什么程度停）
     - 行情数据来源与时延、数据质量（复权 / 停牌 / 缺失值；回测 ≠ 实盘）
     - 下单权限与不可逆操作（谁授权下单、能不能撤、误单后果）
  3. 每条带**后果**，例如："回测里赚钱的策略，上线后往往因为滑点和数据时延亏钱——先用小资金跑一段时间再放大。"
  4. 不要求用户立即回答；TEACH 后再决定该缺口走 ASK / SHOW / INSPECT / DISCOVER
  5. 首轮不产出策略设计、模块结构、代码或券商选型
- **失败判据**：
  1. **直接设计功能 = 失败**（"先给你一个均线策略的模块设计"）
  2. 跳过 TEACH 直接问"你用哪家券商的 API？""准备多少本金？" = 失败
  3. 条目 ≥4 或只讲名词 = 失败
  4. 把"资金与权限"这类阻塞项写进"执行阶段验证" = 失败（契约 R6）
- **关联规则**：契约 §2 Type C、§3 TEACH 硬边界、§4 Step 5、契约 R3、契约 R6、契约 R9；`SKILL.md` §1 触发信号 5、§2.5 规则 3、§6.3（授权默认不得绕过真阻塞项）
- **唯一裁定**：**唯一**

## 二、TEACH 边界案例（BS）

### BS-03 · 健康类小程序（认知缺口 + 后续阻塞项）
- **输入**：`帮我做个症状自查的小程序`
- **唯一正确动作**：**Type C → TEACH**（≤3 条）→ 之后对"范围/定位"走 ASK（阻塞项）
- **通过判据**：
  1. TEACH ≤3，覆盖：不能给诊断结论（只做分诊建议）/ 健康数据属敏感信息 / 紧急症状必须引导线下就医
  2. 每条带后果（"用户按小程序结论自行用药出事，责任在你"）
  3. TEACH 之后对"只做建议不做诊断"这一范围决定走 ASK（阻塞项必须拍板，契约 R6）
- **失败判据**：
  1. 直接设计诊断逻辑，或问"要支持多少种症状？" = 失败（跳过 TEACH）
  2. 条目 ≥4 或只讲名词 = 失败
  3. 把"能不能给诊断结论"这个范围项写进执行阶段验证 = 失败（契约 R6）
- **关联规则**：契约 §2 Type C、§3 TEACH、契约 R3、契约 R6；`SKILL.md` §1 触发信号 5、§6.3
- **唯一裁定**：**唯一**

### BS-04 · 权限与不可逆操作：TEACH 后必须 ASK（不得 DISCOVER）
- **输入**：`帮我写个脚本，把我邮箱里的邮件都自动整理分类`
- **唯一正确动作**：**Type C → TEACH**（≤3 条）→ 对"授权范围"走 **ASK**（权限 / 数据用途 = 阻塞项）
- **通过判据**：
  1. TEACH ≤3，覆盖：最小读取范围 / 归档与删除不可逆 / 凭据保管与误操作
  2. 每条带后果（"删掉的邮件找不回来，误删只能从备份恢复"）
  3. TEACH 后**独立** ASK 1 题（只读 / 可标记 / 可删除，哪种授权范围），并附一句影响说明
  4. 权限范围**不得**落入 DISCOVER（契约 R6：权限是阻塞项）
- **失败判据**：
  1. 跳过 TEACH 直接索要邮箱授权并开始写脚本 = 失败
  2. 把"给多大权限"写成"执行阶段再确认" = 失败（契约 R6）
  3. 同一条 TEACH 里夹带"你希望给多大权限？"（把教与问混成一块，契约 R4） = 失败
- **关联规则**：契约 §3 TEACH / DISCOVER 硬边界、契约 R3、契约 R4、契约 R6；`SKILL.md` §6.3、§6.5（权限类变更）
- **唯一裁定**：**唯一**

### BS-05 · TEACH 之后立即重分类（契约 R3 / 契约 R9）
- **输入（多轮）**：
  - 第 1 轮：`我要做一个 AI 客服`
  - 第 2 轮（收到 BS-01 式 TEACH 后）：`先接我们自己的帮助文档就行，人工接管这块暂时不做`
- **环境/前置**：仓库存在 `docs/help/*.md`（只读可读）
- **唯一正确动作**：**契约 R9 重跑决策树** → "帮助文档内容" = **Type E → INSPECT**；"人工接管暂不做" = **Type D → 不动作**，仅记录；**不得重复 TEACH**
- **通过判据**：
  1. 第 2 轮**不再出现**同类 TEACH（同一缺口不重复教，契约 R3/契约 R9）
  2. 对帮助文档走 INSPECT：给出目录、条数、结构等事实与出处
  3. "人工接管暂时不做"记为**用户已确认的范围决定**，不追问、不计 unresolved
  4. 决策记录：`taught` 行独立保留；新缺口按新类型另起一行（§6.6 约束 4）
- **失败判据**：
  1. 沿用旧 Type C 分类再教一遍 = 失败（契约 R3：已教过不重复；契约 R9：须重分类）
  2. 因为用户说"暂时不做"就把它当 unresolved 继续追问 = 失败
  3. 未读 `docs/help/` 就问"你们的帮助文档在哪、有多少篇？" = 失败（契约 R1）
- **关联规则**：契约 R3、契约 R9、契约 R1、§6 约束 4；`SKILL.md` §6.5C（局部重开）、§6.6
- **唯一裁定**：**唯一**
- **备注**：本例前提是"企业内部助手、无监管强制人工兜底"，故"暂不做人工接管"不与风险条款冲突；若属受监管场景（如金融/医疗），则该决定应转 §3.1 Conflict 处理，本案例不覆盖该分支。

### BS-06 · 内容合规类：跳过 TEACH 直接问 = 失败
- **输入**：`我要做一个自动给客户发催款短信的系统，逾期就发`
- **唯一正确动作**：**Type C → TEACH**（≤3 条）
- **通过判据**：
  1. TEACH ≤3，覆盖：发送时段的合规限制 / 误发与不可撤回 / 催收口径与投诉风险
  2. 每条带后果（"半夜群发催款短信会被投诉，甚至触犯通信管理规定"）
  3. 不要求用户立即回答；TEACH 后再分类该缺口的后续动作
- **失败判据**：
  1. 直接问"短信模板要什么语气？"或直接设计发送流程 = 失败（跳过 TEACH）
  2. 条目 ≥4 或只讲名词 = 失败
  3. 首轮直接交付完整的发送系统设计 = 失败
- **关联规则**：契约 §2 Type C、§3 TEACH 硬边界、§4 Step 5、契约 R3；`SKILL.md` §1 触发信号 5
- **唯一裁定**：**唯一**

### BS-07 · 契约 R5 混合性质 + 契约 R12 时效：先 SHOW，风险必须在 1–2 轮内补教
- **输入（多轮）**：
  - 第 1 轮：`我要让 AI 自动回复客户的差评，越像真人越好`
  - 第 2 轮（收到 3 个方向后）：`真诚认错型可以`（用户已作出选择）
- **唯一正确动作**：第 1 轮 → 决策树 **Step 3 先命中**（"越像真人"= 感受 / 参照物）→ 主导类型 **Type B → SHOW**；"冒充真人 / 平台规则"的 Type C 性质**只作备注**。第 2 轮 → **必须按契约 R12 在随后 1–2 轮内以 TEACH 处理该备注**（不得静默丢弃）
- **通过判据**：
  1. 第 1 轮给出 SHOW：3 个**正交**的回复风格方向（如：真诚认错型 / 事实澄清型 / 补偿导向型）
  2. Type C 性质只写入决策记录的**备注**（如"备注（Type C，待 契约 R12 处理）：平台规则与冒充真人风险"），**不构成第 1 轮第二个动作块**
  3. 第 1 轮只展开一套动作（契约 R5：不得同时展开两套；契约 R4：一次只推进一步）
  4. **第 2 轮按 契约 R12 补 TEACH**（≤3 条、每条讲后果）：冒充真人违反平台规则 / 自动回复的态度与赔偿边界 / 差评升级为舆情的兜底
  5. 契约 R12 的两条出口**二选一且必须留痕**：要么在该 1–2 轮内 TEACH，要么在决策记录显式标「暂不做」并写明原因；高风险类（本例涉平台规则与对外发言）优先 TEACH
- **失败判据**：
  1. 第 1 轮既 SHOW 又列 TEACH 风险清单 = 失败（契约 R5 / 契约 R4）
  2. 跳过 SHOW、直接列"冒充真人的合规风险"清单 = 失败（违反 Step 3 短路顺序）
  3. 把主导类型判成 Type C 而动作记为 TEACH = 失败（决策树顺序不可自选）
  4. **备注被静默丢弃**：后续 1–2 轮内既没有 TEACH、决策记录里也没有标「暂不做」+ 原因 = 失败（**契约 R12**）
  5. 用"下一轮再说"无限推迟、超过 2 轮仍无 TEACH 也无「暂不做」记录 = 失败（契约 R12 的时效）
- **关联规则**：契约 §4（Step 3 排在 Step 5 前，逐条短路）、§2.5 混合性质、**契约 R12**（备注中的 Type C 不得永久搁置，1–2 轮内 TEACH 或标「暂不做」+ 原因）、契约 R5、契约 R4、契约 R3、§6.6；`SKILL.md` §2.5 混合性质段、§11.0 规则 5
- **唯一裁定**：**唯一**
- **原契约空白已补**：本案例最初暴露的缺口是"契约未规定备注性质的 Type C 是否必须补做 TEACH"（本测试上报 lead 后）；现由**契约 R12** 正式覆盖，**不再是待裁决项**。

### BS-08 · 人脸识别门禁：数据用途必须当场拍板
- **输入**：`帮我做一个用小区门禁数据刷脸开门的 App`
- **唯一正确动作**：**Type C → TEACH**（≤3 条）→ 对"数据用途与留存期限"走 **ASK**（契约 R6 阻塞项）
- **通过判据**：
  1. TEACH ≤3，覆盖：生物特征属敏感个人信息（需单独同意）/ 误识别的不可逆后果 / 数据泄露责任
  2. 每条带后果（"别人被误放进门，事后无法'收回'这一次开门"）
  3. TEACH 后 ASK：数据用途与存储期限（存哪、存多久、谁能看），附一句影响说明
  4. 在数据用途未拍板前**不设计存储方案**、不选 SDK
- **失败判据**：
  1. 直接问"用哪家的 SDK？"并设计技术方案而不提数据合规 = 失败（跳过 TEACH）
  2. 把"存多久 / 谁能看"写成执行阶段验证 = 失败（契约 R6：数据用途是阻塞项）
  3. 条目 ≥4 或只讲名词 = 失败
- **关联规则**：契约 §2 Type C、§3 TEACH / DISCOVER 硬边界、契约 R3、契约 R6；`SKILL.md` §6.3、§1 触发信号 5
- **唯一裁定**：**唯一**

### BS-09 · 契约 R12 的另一条出口：「暂不做」必须显式记录并写明原因
- **输入（多轮）**：
  - 第 1 轮：`我要做一个自动交易机器人`
  - 第 2 轮（收到 BS-02 式 TEACH 后）：`风险我知道了，但我现在只要一个能跑的原型，风控和资金这块先不管`
- **唯一正确动作**：**决策记录显式标「暂不做」并写明原因**（契约 R12 的第二条出口），同时在产物中保留"上线前必须补"的显式提示；**不重复 TEACH**
- **通过判据**：
  1. 决策记录中该风险项 = `类型：C` + 状态**「暂不做」** + **原因**（"用户已知晓，原型阶段显式推迟"）；条目**不得删除、不得留空**
  2. 因属**高风险类**（资金 / 权限 / 不可逆），产物中保留一行显式提示（如"原型阶段不含风控与资金保护，上线前必须补"）——契约 R12："高风险类优先于其他待办"
  3. 不再重复第二次 TEACH（契约 R3：已教过不重复；契约 R9：已重分类）
  4. 继续推进用户明确要的部分（可跑原型），不因风险项未决而拒绝出稿；但产出属**部分稿**，缺口可见
- **失败判据**：
  1. **静默丢弃**风险项：记录中删除、不写或只字不提 = 失败（契约 R12 的核心禁止项）
  2. 只写"用户说先不管"而不写**原因** = 失败（契约 R12 要求"写明原因"）
  3. 无视用户的明确表态、重复第三次 TEACH = 失败（契约 R3）
  4. 把"先不管"当成授权默认，因此连记录都不留 = 失败（`SKILL.md` §6.3：授权默认不覆盖法律 / 安全 / 技术边界，也不免除留痕）
- **关联规则**：契约 **R12**（第二条出口：显式标「暂不做」+ 原因）、契约 R3、契约 R6、§6.6；`SKILL.md` §6.3（授权默认的例外）、§6.6 约束 4
- **唯一裁定**：**唯一**
