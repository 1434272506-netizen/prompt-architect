# 对抗测试 · 问题选择（V0.2 Question Selection · 第 1 轮：破坏性测试）

> **状态**：本节记录**规则落盘前**的破坏性测试结果（23 例，12 唯一 / 11 不唯一），是 §11 的立规证据，**不改写、不覆盖**。落盘后的重跑复核见文末「复核：V0.2 §11 落盘后的裁定重跑」。

**目的**：打坏现有"问什么"的能力，找出问题选择策略的失败点。**本轮不写规则、不设计评分公式、不改任何冻结章节。**
**被测现状**：§3（P0→P3 层级 + "只问答案会改变方案结构的" + "同层优先信息增益最大"）、§3.1（冲突优先）、§3.2（unresolved）、§4（模糊词协议：时机、正交方向、自由描述通道、复述确认）、§5（七问按需）、§6（停止/降级/授权默认）、§2.1（对外语言）。

**裁定口径**：
- `唯一` = 现行规则只能选出同一个优先问题；
- `不唯一` = 同层候选无法区分、或规则未覆盖该维度（两种选法都能自称合规）。

**观察标签**（仅用于整理，不得写成新规则）：上下游顺序错误／问题信息增益不足／重复询问已知信息／问题对用户不可回答／选项诱导／选项不正交／过早询问实现细节／未根据上一轮回答改变问题／一个问题本可覆盖多个缺口却被拆碎／对新手过于专业／对专业用户解释过度／风格问题抢在产品问题之前。本轮新增：**同层无裁界**、**选项不完备**、**提问形式无判据**、**答案依赖未确认项**。

## 一、网站（W）

### W1 · "帮我做一个 AI 网站"
- **用户输入**：`帮我做一个 AI 网站。`
- **已知**：产物＝网站；"AI" 是领域，不是用户类型
- **缺失**：产品形态（消费者官网 vs 专业工作台）、受众、成功标准、技术栈、视觉方向
- **候选问题**：
  1. 你喜欢黑色还是白色？（P3）
  2. 这是面向普通消费者的产品官网，还是专业用户使用的 AI 工作台？（P0）
  3. 域名和部署用哪家？（P2）
- **应优先**：2
- **信息价值更高**：答案会改变页面结构、内容、交互、技术方案与视觉方向；1 只是局部决策
- **低价值/过早**：1（P3 抢在产品问题之前）、3（P2，且依赖产品形态）
- **现行规则裁定**：**唯一**（层级 P0 > P2 > P3 直接决出）

### W2 · 上游 vs 下游
- **用户输入**：`做一个企业官网。`
- **已知**：产物＝企业官网
- **缺失**：目标受众、页面数量、配色偏好
- **候选问题**：1 给谁看？（P0）　2 需要几个页面？（P1/结构）　3 主色偏冷还是偏暖？（P3）
- **应优先**：1
- **信息价值更高**：受众决定内容与页面结构，进而决定页数；配色是局部
- **低价值/过早**：3
- **现行规则裁定**：**唯一**（P0 先于 P1 先于 P3）

### W3 · 同层两个 P0 缺口
- **用户输入**：`做一个内部工具型 Web App。`
- **已知**：产物＝内部工具；受众＝公司内部（已隐含）
- **缺失**：具体的**谁用**（岗位）、**怎样算成功**（效率？合规？）
- **候选问题**：1 主要给哪个岗位用？（P0）　2 上线后你们用什么指标判断它有用？（P0）　3 要不要深色模式？（P3）
- **应优先**：1 或 2 **都说得通**——若岗位已由"内部"限定，则 2 价值更高；反之 1 更高
- **信息价值更高**：无法先验判断；规则既未定义"信息增益"，也未给出同层打破平局的口径
- **低价值/过早**：3（P3，但排除它无助于在 1 与 2 之间选择）
- **现行规则裁定**：**不唯一**
- **失败标签**：同层无裁界；问题信息增益不足（"信息增益最大"无判据）

### W4 · 用户专业度不同（新手 vs 设计师）
- **用户输入**：新手：`我想做个作品集网站，但我不太懂这些。` ／ 专业：`我要一个作品集站，单页滚动，需要响应式断点和暗色主题，内容按项目分集。`
- **已知**：产物＝作品集；两种用户的表达水平差异极大
- **缺失**：成功标准、内容结构、技术方案
- **候选问题**：
  1. 你希望访客看完做什么？（P0）
  2. 内容按项目集还是按时间线组织？（P1）
  3. 用哪套栅格与断点方案？（P2/P3，专业用户才答得上）
- **应优先**：两人都应先问 1，但**表述层级必须不同**：新手要给"展示作品／找工作／接单／写文章"这类可理解选项；设计师应直接问内容组织与断点，不必解释基础概念
- **信息价值更高**：缺口相同，但"可回答性"决定了同一缺口该用哪种问法
- **低价值/过早**：对新手问 3（无法回答）；对设计师重复解释"什么是响应式"（解释过度）
- **现行规则裁定**：**不唯一**（§4 只规定给正交方向与自由通道，没有任何"按用户专业度调整表述"的规则；§3 只比较缺口层级）
- **失败标签**：对新手过于专业；对专业用户解释过度

### W5 · 成功标准 vs 视觉风格
- **用户输入**：`给我们的牙科诊所做个官网。`
- **已知**：产物＝诊所官网
- **缺失**：成功标准（是否以预约/来电为核心）、页面数量、视觉方向
- **候选问题**：1 你更希望访客打电预约，还是先了解医生和项目？（P0）　2 喜欢玻璃拟态还是极简？（P3）　3 需要几个页面？（P1/结构）
- **应优先**：1
- **信息价值更高**：成功标准决定第一屏、导航与页面数量；风格是局部
- **低价值/过早**：2
- **现行规则裁定**：**唯一**（P0 > P1 > P3）

### W6 · 选项诱导 / 选项质量
- **用户输入**：`帮我做个设计工作室的网站。`
- **已知**：产物＝工作室网站
- **缺失**：视觉方向（且用户答"要高级"）
- **候选问题（同一缺口的三种问法）**：
  1. `你更喜欢哪种？A. 专业高级　B. 普通简单　C. 老旧传统`
  2. `哪种更接近？A. 极简克制　B. 材质做工　C. 稀缺暗场　D. 以上都不是，我描述给你`
  3. `你要什么颜色？`
- **应优先**：2
- **信息价值更高**：1 的选项带价值判断且按程度而非维度切分，会把用户推向 AI 偏好；3 属 P3 局部；2 正交、中立、且留了自由通道
- **低价值/过早**：1（诱导）、3（局部且无约束力）
- **现行规则裁定**：**不唯一**
  - 若把"高级"当作模糊词 → §4 硬约束 1/2 可裁定（正交 + 自由通道）→ 选 2
  - 若不把它归入模糊词场景 → 规则集中**没有任何通用**的"选项中立性 / 完备性"约束 → 1 也能自称合规
  - 判定依赖"这个问题是否恰好命中模糊词协议"，规则本身不保证
- **失败标签**：选项诱导；选项不正交；**新增：选项不完备**（1 无"以上都不是"通道）

### W7 · 开放题 vs 选择题
- **用户输入**：`给我们的健身房做个官网。`
- **已知**：产物＝健身房官网，受众＝附近居民
- **缺失**：访客最终动作（购买会员？预约体验？看课表？）
- **候选问题（同一缺口的不同形式）**：
  1. 开放：`访客进来之后，你最希望他做的第一件事是什么？`
  2. 选择：`访客进来后最重要的是？A 买会员　B 预约体验　C 看课表　D 联系教练`
  3. 选择：`最重要的目标是"卖卡"还是"让人了解"？`
- **应优先**：1（该缺口的答案空间发散，且用户往往能一句话说清自己的期待；选项中可能没有他的真实答案）
- **信息价值更高**：形式决定了能否收到"选项之外"的真实答案；但若用户表达水平低，2 反而更易回答
- **低价值/过早**：3（选项不完全覆盖且带隐含价值判断）
- **现行规则裁定**：**不唯一**（现行规则只在 §4 模糊词场景规定"给方向 + 自由通道"，**没有任何"何时该开放问、何时该给选项"的判据**）
- **失败标签**：**新增：提问形式无判据**

## 二、图片生成（I）

### I1 · 重复询问已知信息
- **用户输入**：`给专业剪辑师用的桌面端视频工具，做一张产品配图，16:9、深色。`
- **已知**：受众＝专业剪辑师；载体＝桌面端视频工具；比例＝16:9；色调＝深色
- **缺失**：画面主体、构图、是否含 UI 界面
- **候选问题**：1 目标用户是谁？（P0，已答）　2 画面主体放什么？（P1）　3 具体用什么深色？（P3）
- **应优先**：2
- **信息价值更高**：1 已答，问它零增益；3 过细
- **低价值/过早**：1（重复询问）、3
- **现行规则裁定**：**唯一**（§6.4 禁止重复询问已答问题 + 层级）

### I2 · 上游 vs 下游
- **用户输入**：`帮我生成一张海报图。`
- **已知**：产物＝海报图
- **缺失**：用途/投放场景、比例尺寸、风格
- **候选问题**：1 这张图用在哪（门店立牌／朋友圈／外卖头图）？（P0）　2 要什么比例？（P2，取决于 1）　3 喜欢什么风格？（P3）
- **应优先**：1
- **信息价值更高**：用途同时决定比例、信息密度与风格上限
- **低价值/过早**：3；2 属下游（答案依赖 1）
- **现行规则裁定**：**唯一**

### I3 · 高影响但用户难以回答
- **用户输入**：`给我们的养生品牌做一张宣传图。`
- **已知**：产物＝宣传图；领域＝养生
- **缺失**：目标人群、投放渠道、画面主体、风格
- **候选问题**：
  1. `你们目标用户的审美偏好分层和消费者画像是什么？`（P0，影响极大，但普通用户答不出）
  2. `这张图主要给谁看、发在哪？`（P0，用户能答）
  3. `喜欢暖色还是冷色？`（P3）
- **应优先**：2
- **信息价值更高**：1 与 2 命中的是**同一缺口**（受众/场景），但 2 可回答；1 的"高影响"无法兑现，因为用户答不出精确答案，只会得到沉默或敷衍（进而触发 §3.2 的 unresolved）
- **低价值/过早**：3；1 属"高影响但不可回答"，不能因为影响大就优先
- **现行规则裁定**：**不唯一**（§3 选取原则只问"答案是否改变结构"，**没有"可回答性/回答成本"这一维度**；1 与 2 同层，规则无法在两者间裁定）
- **失败标签**：问题对用户不可回答

## 三、视频（V）

### V1 · 上游优先，风格不抢跑
- **用户输入**：`我们公司做智能门锁的，帮我写个短视频脚本，要电影感、震撼。`
- **已知**：产物＝短视频脚本；领域＝智能门锁
- **缺失**：投放平台与时长、观看后动作、核心对象、风格解读
- **候选问题**：1 发在哪、多长？（P0）　2 "电影感"更接近哪种？（P3）　3 配什么音乐？（P3）
- **应优先**：1
- **信息价值更高**：平台与时长决定信息密度、结构与叙事；风格必须在用途明确后才澄清（§4 时机）
- **低价值/过早**：2、3（风格抢在产品问题之前）
- **现行规则裁定**：**唯一**

### V2 · 一问覆盖多缺口，与"反规避"口径冲突
- **用户输入**：`帮我做一条产品宣传视频。`
- **已知**：产物＝宣传视频
- **缺失**：平台、时长、观看后动作、核心卖点
- **候选问题**：
  1. `这条片子发在哪、大概多长、看完你希望观众做什么？`（一句覆盖 3 个缺口）
  2. 分三轮各问一个（平台 → 时长 → 观看动作）
  3. `要不要加字幕？`（P3）
- **应优先**：1（一次拿到能同时约束结构、节奏与卖点排序的信息）
- **信息价值更高**：这 3 个缺口属于**同一个决策簇**，同时给出才能让用户自我一致地权衡；拆开问会得到互相矛盾的答案（先答"30 秒"后答"要讲 5 个卖点"）
- **低价值/过早**：3
- **现行规则裁定**：**不唯一／内部口径冲突**
  - §2 上限是"1～3 个问题"，形式 1 若按子问题计就是 3 个（合规），若按"一句话"计就是 1 个（也合规）——但 `tests/acceptance.md` R2 明确把"尺寸、时长、平台分别是？"这类写法判为**规避写法、仍计 3 个**，即规则倾向**否定合并提问**；
  - 现行规则**没有任何"优先选择能同时消除多个缺口的问法"的条款**，1 与 2 都能自称合规
- **失败标签**：一个问题本可覆盖多个缺口却被拆碎；**新增：合并提问与 R2 反规避口径冲突**

### V3 · 对专业用户解释过度
- **用户输入**：专业导演：`给这支产品片写分镜，一镜到底，我需要 24fps、浅景深、三幕结构。`
- **已知**：产物＝分镜脚本；用户已给出运镜、帧率、景深、结构
- **缺失**：投放平台、品牌露出约束、声音设计
- **候选问题**：
  1. `这条片子主要用在哪？结尾要不要品牌露出？`（P0/P2）
  2. `你知道什么是"一镜到底"吗？需要我给你几个镜头方案参考吗？`（重复解释基础概念）
  3. `你要暖调还是冷调？`（P3）
- **应优先**：1
- **信息价值更高**：用户已用专业术语锁定结构，剩余缺口是投放与合规；2 是无效确认，消耗问题额度
- **低价值/过早**：2（解释过度）、3
- **现行规则裁定**：**不唯一**（§4 只规定"给方向 + 自由通道 + 复述确认"，**没有"根据用户专业度决定是否给方向/是否复述"的规则**；§6.4 只禁止重复询问**已答**问题，2 问的是"要不要参考"，形式上不违规）
- **失败标签**：对专业用户解释过度

### V4 · 过早进入技术实现
- **用户输入**：`帮我做个短视频。`
- **已知**：产物＝短视频（其余全缺）
- **缺失**：平台/时长/动作/卖点/风格/工具
- **候选问题**：1 用剪映还是 Premiere？（P2 实现细节）　2 发在哪、多长、看完做什么？（P0）　3 卖点排序怎么定？（P1，依赖 2）
- **应优先**：2
- **信息价值更高**：P0 决定后续一切；工具选择在《平台/时长/受众》未定前毫无意义
- **低价值/过早**：1（过早询问实现细节）
- **现行规则裁定**：**唯一**（P2 晚于 P0）

## 四、3D 场景（T）

### T1 · 上游优先
- **用户输入**：`做一个 3D 产品展示场景。`
- **已知**：产物＝3D 展示场景
- **缺失**：用途（电商详情页／展会大屏／VR 演示）、渲染引擎、光照风格
- **候选问题**：1 这个场景最终放在哪用？（P0）　2 用 Three.js 还是 UE？（P2）　3 暖光还是冷光？（P3）
- **应优先**：1
- **信息价值更高**：用途决定性能预算、交互方式、精度与光照策略
- **低价值/过早**：2、3
- **现行规则裁定**：**唯一**

### T2 · 两个候选项互相依赖（同层）
- **用户输入**：`网页里嵌一个 3D 产品展示。`
- **已知**：产物＝网页内嵌 3D；用途＝网页展示
- **缺失**：单场景还是多场景切换、目标设备性能档位（手机/桌面）、加载策略
- **候选问题**：1 需要单场景还是多场景切换？（P1/结构）　2 主要给手机看还是桌面看？（P2/硬约束）　3 环境光照用 HDR 贴图吗？（P2/P3）
- **应优先**：**无法先验决定**——1 的答案会改变 2 的严重程度（多场景 + 手机 → 性能约束极强），2 的答案又会改变 1 的可行区间
- **信息价值更高**：两者互相是对方的条件，单独看"哪个影响更大"没有意义；必须**先问上游的那个**（此处是 2：设备档位先约束规模），但规则没有任何依赖顺序概念
- **低价值/过早**：3
- **现行规则裁定**：**不唯一**（1 与 2 分属 P1/P2，层级可裁出 2；但若把"多场景"也算硬约束（同为 P2），规则即失效。规则没有"答案会改变另一个问题的选项集 → 必须先问"的概念）
- **失败标签**：**新增：答案依赖未确认项**（依赖顺序未建模）

## 五、软件 / Web App（S）

### S1 · 同层 + 用户不可回答
- **用户输入**：`做一个内部审批 Web App。`
- **已知**：产物＝内部审批工具；用户＝公司员工（隐含）
- **缺失**：权限模型、日常核心操作、视觉偏好

- **应优先**：2
- **信息价值更高**：1 零增益；3 属实现细节且依赖核心任务
- **低价值/过早**：1、3
- **现行规则裁定**：**唯一**（§6.4 + 层级）

### S3 · 上一轮回答应改变下一问
- **用户输入**：第 1 轮 `做个软件。` → 用户：`给医生查看医学影像的专业系统，要在医院内网跑。`
- **已知**：产物＝医学影像查看系统；受众＝医生；环境＝院内内网

- **信息价值更高**：用户的回答已经把问题域从"软件"收窄到"临床阅片"，下一问必须落在工作流与安全约束上
- **低价值/过早**：2（风格抢在产品问题之前）、3（依赖 1）
- **现行规则裁定**：**唯一**（层级 P1 > P3 恰好实现了"跟随上一轮收窄"的效果；§5"按需查表、不机械七连问"也支持不回头问通用问题）

- **现行规则裁定**：**唯一**（层级 P0/P1 早于 P2）

## 失败收敛：7 类缺口

| 缺口 | 说明 | 由哪些案例证明 |
|---|---|---|
| **Q1 同层无裁界** | "同层优先信息增益最大"未定义"信息增益"，两个同层候选无法比较 | W3、S1、A3（T2 部分） |

## 核心假设检验：「问题价值 = 对最终方案的影响程度」是否足够？

**结论：不充分。** 它既缺少"如何比较"的定义，也漏掉三个独立维度。反例（均已在本轮案例中出现）：

| 反例类型 | 案例 | 说明 |
|---|---|---|
| 影响大但**用户无法回答** | I3、S1、A3 | 用户答不出 → 只会得到沉默/敷衍，价值无法兑现（还会消耗 unresolved 额度） |
| 影响大但**回答成本过高** | S1（需问 IT）、A3（需问财务） | 组织内部信息，用户需要跨部门取证 |
| 影响大但**时机不合适** | V4、A4 的候选项 1、W1 的候选项 3 | 上游未定，答案随时会作废 |
| 影响大但**依赖另一个未确认项** | T2、A3 | 不先问上游，问题的候选答案集都无法确定 |
| **同样影响大但无法比较** | W3、S1 | 只看"影响程度"在同层内也裁不出来——缺少"影响如何度量"的定义 |

因此，替换性的最小假设至少需要：**价值 ≈ 影响程度 × 可兑现性（用户能否回答）× 时机有效性（上游是否已定）**，且需要一条独立的**同层打破平局**口径。本轮不写公式、不设权重。

## 可能的最小补丁方向（**未写入 SKILL.md**）

1. **同层裁界（Q1）**：同层多个缺口时，优先选"答案会**排除更多下游分支**"的那个；若无法比较，优先可回答性更高的。
2. **可回答性（Q2）**：高影响但用户明显答不出时，**不换问题，换问法**——把同一缺口降维成用户凭经历能回答的形式（如"你们目标用户的审美分层"→"这图发在哪个平台、谁看"）。
3. **专业度适配（Q3）**：缺口优先级不变，只调整**表述层级**：新手给可理解选项，专业用户直接用其已使用的术语、不做基础解释、不重复复述。
4. **选项质量通用化（Q4）**：把"正交 / 中立 / 完备 / 必须留自由通道"从模糊词场景**提升为所有选择题**的约束，并明确禁止把 AI 偏好写进选项。
5. **提问形式判据（Q5）**：答案空间发散（用途、目标、期待）→ 开放问 + 举例；答案空间可枚举且用户认知浅 → 给正交选项 + 自由通道。
6. **合并提问（Q6）**：明确"同一决策簇的多个缺口可以合并成一问"，判据是"用户是否需要分别权衡多件事"，而非句子里的子问题个数；此条与冻结的 R2 口径冲突，需另行裁决。
7. **依赖顺序（Q7）**：若 B 的答案会改变 A 的选项集或严重程度，则 **B 优先于 A**，即使 A 名义影响更大。

## 更正：关于冻结 R2 的一处过强解读

本文件 V2 案例与分析中曾写"`tests/acceptance.md` R2 把'一句话含多个子问题'判为规避写法，即规则倾向**否定合并提问**"。经 Q6 专项测试复核（12 例），该表述**过强**，应更正为：
