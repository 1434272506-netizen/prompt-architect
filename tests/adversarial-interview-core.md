# 对抗测试 · 采访核心（§3 优先级梯级 + §6 停止规则）

**被测规则**：§3（P0→P3、信息增益）、§3.1（Conflict vs Tension）、§3.2（unresolved 计数）、§4（模糊词协议）、§6.1～§6.2（停止判据）、§6.3（降级 / 授权默认）、§6.4（禁止）、§6.5（Revision 与局部重开）。

**案例总数：21 个固定案例**（原 16 个全部重跑 + 用户指定的 4 个微型判例 + 1 个补充非阻塞 unresolved 案例 B4）。

**裁定口径**：`唯一` = 依现行规则只能得出一致答案；`有判断余量` = 方向唯一但取值靠判断（不算缺口）；`不唯一` = 两种解释都自洽（须报告，不得自行补规则）。

## 一、答非所问与 unresolved（B）

### B1 · 问 P0，用户答了 P3
- **用户输入**：问"网站给谁看" → 答 `我想要深色的，看起来很酷`
- **当前状态**：偏好"深色"入风格槽位；**用途 unresolved = 1**
- **规则裁定**：吸收旁支信息 → 用途 unresolved +1 → 继续问当前最高优先级缺口（用途）
- **用户侧正确行为**：`深色这条我记下了。还差一件更关键的：这个站主要给谁看？`
- **错误行为**：丢弃"深色"重复问颜色／指责用户没回答问题
- **规则依据**：§3.2（吸收旁支 + unresolved+1 + 继续最高优先级缺口）、§6.4
- **唯一裁定**：**唯一**

### B2 · 同一阻塞缺口连续 2 次 unresolved
- **用户输入**：第 1 轮问受众 → 答配色；第 2 轮再问受众 → 答 `反正高级一点就对了`
- **当前状态**：受众（P0，**阻塞项**）unresolved = 2
- **规则裁定**：不再换措辞追问 → 输出目前可完成的部分 → 简洁说明仍缺哪一个决定
- **用户侧正确行为**：`我先按"给潜在客户看"这一版往下做。要更准的话，只需要你告诉我它是给客户还是给同行看的。`
- **错误行为**：第 3 次换措辞问同一个点
- **规则依据**：§3.2（连续 2 次 unresolved → 阻塞项处理）、§6.3
- **唯一裁定**：**唯一**

### B3 · 用户顺带授权默认
- **用户输入**：`这些细节你定吧，按你想的来就行`
- **当前状态**：P0 已齐，P2 部分缺失；属授权默认
- **规则裁定**：不计 unresolved；不再为走完流程而追问；非阻塞缺口用合理默认；未确认内容进「待确认假设」；进入可交付阶段
- **用户侧正确行为**：`行，剩下的细节我按专业判断填，写进待确认假设里，你扫一眼就知道我替你定了什么。`
- **错误行为**：把"你定"记作 unresolved 并继续追问细节
- **规则依据**：§6.3（授权默认行）、§7
- **唯一裁定**：**唯一**

### B4 · 非阻塞缺口连续 2 次 unresolved
- **用户输入**：P0 已齐；问"希望什么节奏感" → 答别的；再问 → 仍未答
- **当前状态**：节奏感（非阻塞项）unresolved = 2
- **规则裁定**：停止重复追问 → 采用合理默认值 → **显式进入「待确认假设」区**
- **用户侧正确行为**：正文不再问；假设区写 `- 节奏按平稳克制处理（你没给偏好，我按默认填，若不符请指出）`
- **错误行为**：第三次追问／静默采用默认却不写进假设区
- **规则依据**：§3.2（非阻塞项处理）、§7 铁律 2
- **唯一裁定**：**唯一**

## 二、信息过载、冲突与张力（C）

### C1 · "极简 + 信息给满"
- **用户输入**：`要极简、留白多，但每一屏信息要尽量给满，别有空白`
- **当前状态**：两条要求同时存在，表面上矛盾
- **规则裁定**：**先按 Tension 试解**（信息层级、折叠、渐进披露、分区、多页面、侧栏、详情视图）→ 不打断采访、两条都保留、不要求二选一
- **用户侧正确行为**：`这两条我用信息层级来兼顾：主视觉保持留白，密集信息收进可展开的详情里。继续问下一个问题……`
- **错误行为**：判为冲突让用户二选一／把矛盾悄悄丢掉一条
- **规则依据**：§3.1（判定顺序：先 Tension 后 Conflict）
- **唯一裁定**：**唯一**

### C2 · 一轮把 P0+P1+P2 全给齐
- **用户输入**：`做个 3 页的公司官网，给投资人和客户看，纯静态，下周上线，风格干净`
- **当前状态**：谁用[✓] 产物[✓] 成功标准[~ 可推] 硬约束[✓]
- **规则裁定**：不出提问，直接进 §8 出稿
- **用户侧正确行为**：直接给 5 段 Prompt
- **错误行为**：`为了更稳妥，还想确认一下预算/域名/字体`
- **规则依据**：§6.1、§6.2、§6.4
- **唯一裁定**：**唯一**

### C3 · 大量无关信息 + P0 仍缺
- **用户输入**：`我最近很忙，公司刚搬办公室，预算还没批……你帮我做个网站吧`
- **当前状态**：只有模糊产物方向，P0 实际仍缺
- **规则裁定**：忽略无关信息，只问最影响结构的 1～3 个 P0
- **用户侧正确行为**：`先问三个会影响做法的……`
- **错误行为**：回应搬办公室、追问预算审批
- **规则依据**：§3 选取原则
- **唯一裁定**：**唯一**

### C4 · 用户提前回答了我还没问的问题
- **用户输入**：问受众 → 答 `给客户看。顺便说，别用真人照片，纯静态就行`
- **当前状态**：受众[✓] + 两条硬约束[✓]
- **规则裁定**：全部入槽位，后续不再问这三项
- **用户侧正确行为**：`收到，纯静态、不放真人照片我记下了。还差一个：看完你希望客户做什么？`
- **错误行为**：后面又单独问"要不要放真人照片"
- **规则依据**：§6.4（不重复询问已答过的）
- **唯一裁定**：**唯一**

## 三、修正、冲突与兼容更新（D）

### D1 · 明确修正（Explicit Revision）
- **用户输入**：第 1 轮 `不要真人照片` → 第 3 轮 `我改主意了，首页放我的照片`
- **当前状态**：已确认需求被主动修改
- **规则裁定**：Revision → 新值覆盖旧值；不算重复询问；只把受影响的下游槽位（视觉主体、素材需求）设为未确认；其余保留
- **用户侧正确行为**：`好，那首页换成真人照片，素材那部分我重新排一下，其余不变。`
- **错误行为**：`你之前说过不要真人照片。`（当矛盾质问）／整轮采访重来
- **规则依据**：§6.5A、§6.4
- **唯一裁定**：**唯一**

### D2 · 兼容更新（无明确修正语）
- **用户输入**：先 `下周必须上线` → 后 `不着急了，三个月内都行`
- **当前状态**：新要求与旧要求**可以同时成立**（放宽）
- **规则裁定**：既不是 Revision 也不算 Conflict → 直接更新槽位，无需追问
- **用户侧正确行为**：（不再提时间）继续问剩下的结构性问题
- **错误行为**：判为冲突要求二选一／把旧值与新值同时保留
- **规则依据**：§6.5「兼容更新」、§6.4（禁止的是"无法同时成立"的新值静默覆盖）
- **唯一裁定**：**唯一**

### D3 · 修正高层需求（P0 级）
- **用户输入**：一路聊海报细节 → `其实我想要的不是海报，是一条短视频`
- **当前状态**：对旧产物的**明确否定** → Revision，且是 P0 级变化
- **规则裁定**：Revision → 重开产物 / 成功标准 / 及受影响的下游（尺寸、视觉方向、输出格式）；品牌、受众等未受影响信息继续保留
- **用户侧正确行为**：`那方向要换：先说清这条视频发在哪、多长；刚才聊过的品牌调性我保留。`
- **错误行为**：继续用海报的尺寸与文案约束出短视频稿
- **规则依据**：§6.5A（含"对旧值的明确否定"）、§3
- **唯一裁定**：**唯一**

## 四、用户给出选项外的第四条路（E）

### E1 · 第四条路与已确认硬约束互斥
- **用户输入**：已确认 `不要花哨动效` → `我看别人那种炫酷的动效挺好的，加上吧`
- **当前状态**：两条落在同一维度且取值互斥，**无法通过设计手段同时满足** → Conflict
- **规则裁定**：该冲突组暂停、不写入需求区；优先于其他普通缺口；只提一个最小澄清问题；**不自动覆盖**旧值
- **用户侧正确行为**：`动效和"不花哨"只能选一个方向：你要"几乎无动效的克制过渡"，还是要"明显的动画效果"？`
- **错误行为**：把"炫酷动效"写进约束区同时保留"不要花哨动效"／默默采用新的
- **规则依据**：§3.1、§6.4（未声明修正时不得自动覆盖）
- **唯一裁定**：**唯一**（判定说明：同维度取值互斥 → Tension 试解失败 → Conflict）

### E2 · 第四条路清晰且不与既有约束冲突
- **用户输入**：四个方向都不像 → `我想要那种一页到底、上下滑动的`
- **当前状态**：自述明确、无冲突
- **规则裁定**：立即采用，不拉回选项
- **用户侧正确行为**：`明白，就按一页到底来做。`
- **错误行为**：`你要不要再看看 A/B/C/D 哪个更接近？`
- **规则依据**：§4 注意（四条路优先采用）
- **唯一裁定**：**唯一**

### E3 · 第四条路非常模糊
- **用户输入**：`就那种感觉吧，你懂的那种高级`
- **当前状态**：仍是模糊词，且用户拒绝了全部选项
- **规则裁定**：复述确认 + 换一组维度重给正交方向
- **用户侧正确行为**：`我理解成"安静、不热闹"那种，对吗？如果对，我按这个方向继续。`
- **错误行为**：直接按自己的理解写进需求区且不确认
- **规则依据**：§4 硬约束 3、§7
- **唯一裁定**：**唯一**

## 五、降级出稿之后又来了新信息（F）

### F1 · 降级出稿后补充关键信息
- **用户输入**：`随便/你决定` ×2 → 我出稿 → `对了，这个主要在手机上用`
- **当前状态**：已（降级）出稿；新信息影响布局/交互/导航/响应式/信息密度
- **规则裁定**：**局部重开**——只重开受影响分支，其余保留；不重开整轮采访
- **用户侧正确行为**：`那我把移动端这一版重排一下，其余保持不变。`
- **错误行为**：`你早说啊，我们重新来一遍。`／装作没听见继续原稿
- **规则依据**：§6.5C、§6.3 末注（停止追问 ≠ 拒收新信息）
- **唯一裁定**：**唯一**

### F2 · 第 1 轮"随便"、第 2 轮给出具体信息
- **用户输入**：第 1 轮 `随便` → 我按授权默认出稿 → 第 2 轮 `还是给同行看，要能放项目截图`
- **当前状态**：授权默认已出稿；新信息只影响受众与内容分支
- **规则裁定**：授权默认（第 1 轮）+ 局部重开（第 2 轮）
- **用户侧正确行为**：`好，那这个站改成"同行看 + 项目截图"，我更新受众和内容这两块，其余不动。`
- **错误行为**：因为出现过一次"随便"就永远不再接收信息／整轮重来
- **规则依据**：§6.3（授权默认）、§6.5C
- **唯一裁定**：**唯一**

### F3 · "别问了我也不知道，直接给吧"
- **用户输入**：`别问了我也不知道，直接给吧`
- **当前状态**：P0 全缺；同句里同时含"不知道"与授权信号
- **规则裁定**：**授权默认优先**（§6.3 同句优先级）→ 不计 unresolved；立即出稿；未确认项全部进「待确认假设」区；不得编造事实写入需求区；若存在真正阻塞项才降为"可完成部分 + 最小关键决定"
- **用户侧正确行为**：给出一版带假设的稿子 + `以上只要哪条不对，告诉我编号我改`
- **错误行为**：把"不知道"记成 unresolved 后继续提问／编造受众、平台、截止时间写进需求区
- **规则依据**：§6.3（授权默认 + 同句优先级 + 例外汇总）、§7
- **唯一裁定**：**唯一**

## 六、用户指定的 4 个微型判例

### Case A · "页面要极简，但信息要非常丰富"
- **用户输入**：`页面要极简，但信息要非常丰富。`
- **当前状态**：两条要求同时存在
- **规则裁定**：**Tension**（首先判定），不得自动判定为 Conflict；可通过信息架构解决
- **用户侧正确行为**：保留两条，按信息层级/折叠/分区兼容，继续采访，**不要求二选一**
- **错误行为**：`这两条冲突，你选一个。`
- **规则依据**：§3.1
- **唯一裁定**：**唯一**

### Case B · 明确修正
- **用户输入**：已确认 `不要真人照片` → `我改主意了，首页放我的照片。`
- **当前状态**：含明确修正信号
- **规则裁定**：**Revision**，新值覆盖旧值，只重置受影响下游
- **用户侧正确行为**：`好，换成真人照片，我只重新对齐视觉与素材部分。`
- **错误行为**：判为 Conflict 要求二选一／保留两条互斥要求
- **规则依据**：§6.5A
- **唯一裁定**：**唯一**

### Case C · 无修正声明的互斥新要求
- **用户输入**：已确认 `不要真人照片` → `首页放我的照片。`
- **当前状态**：无修正信号，两值互斥
- **规则裁定**：**Conflict**，不得自动覆盖旧值；暂停该组、优先处理、只问一个最小澄清
- **用户侧正确行为**：`这条和之前"不放真人照片"冲突了：你确定改成放真人照片吗？`
- **错误行为**：静默用新值覆盖旧值
- **规则依据**：§6.5B、§3.1、§6.4
- **唯一裁定**：**唯一**

### Case D · "随便，你决定"
- **用户输入**：AI 问 `你希望 A、B 还是 C？` → `随便，你决定。`
- **当前状态**：出现授权信号
- **规则裁定**：**default authorization**，不是 unresolved；不计 unresolved、不再追问该缺口、按默认填入并进「待确认假设」
- **用户侧正确行为**：`行，这块我按判断定，写进待确认假设里。`
- **错误行为**：记作 unresolved／继续追问"到底选哪个"
- **规则依据**：§6.3（授权默认行）、§3.2（不计入 unresolved）
- **唯一裁定**：**唯一**

**结论**：**21 / 21 唯一裁定**；原 6 例不唯一（B2/C1/D1/E1/F1/F3）对应的 5 个缺口全部关闭。本轮另有两处**由失败案例证明**的精度补丁（非新增功能）：§6.3「同句优先级」（F3）与 §6.5「兼容更新」（D2，避免把放宽类信息误判为 Conflict 或误判为静默覆盖）。
