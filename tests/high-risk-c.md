# 高风险 Type C 前置 · 固定回归（契约 R14 / V0.3.4）

> **性质**：纯手工/agent 可执行判定用例，不依赖任何测试框架。
> **规则源**：`core/uncertainty-classifier.md` **§3.1（R14 完整判据）** + **R3 / R4 / R11 / R12** + `SKILL.md` §2.5 规则 4 / §11.0 规则 6、8。
> **执行方式**：把「输入」原样发给已装载 `SKILL.md` 的 agent（新会话）；多轮案例按标注继续发送「用户后续」；命中任一「失败判据」即整例 FAIL。
> **本文件解决**：迁移回归发现"ASK → 轮1纯 TEACH → 轮2 ASK"这一新采访模式的顺序**缺正文级判据**（原只能靠 R3/R4 推导）。

**R14 核心口径（判例依据）**：

```
高风险 C  >  普通 A
普通 C  <  阻塞 A
高风险 C  =  阻塞 A   → 同轮并列：先 TEACH，紧接 ASK（不推迟阻塞项）
```

三闸门**必须同时满足**才前置：①高风险五类之一（重大返工 / 安全 / 合规 / 不可逆架构选择 / 用户目标可能被根本误解）②用户尚未意识到（**三信号皆无**：未提及 / 未声明相关约束 / 环境无既往表述）③本项目真实存在（**有具体载体 + 后果**）。
**适用对象**：**只适用于风险/后果类缺口**；P0/P1/P2 中用户未提及的语义槽位一律走 Type A，**不进本闸门**（契约 §3.1）。

## 一、正向用例

### HR-01 · 高风险 C 抢普通 ASK（三闸门全过 → 首轮以 TEACH 为主）

- **输入**：`我要做一个自动交易机器人。`
- **上下文**：首轮；无可读环境
- **缺口清单**：P0-产物=自动交易机器人（有）；**普通缺口=受众/成功（非阻塞，可顺延）**；**R6 必问项=费用授权（谁有权下单、单笔/总额上限）**——与"资金风险"**同域**；P3=缺；**风险维度=资金风险 / 数据来源 / 回测方式（用户完全未提及）**
- **Type 判定**：P0 缺项 → **Type A（普通，非阻塞）**；风险维度 → **Type C（高风险①安全/不可逆架构 + 目标可能被根本误解）**
- **三闸门**：①✅（资金安全、不可逆策略）②✅（三信号皆无）③✅（交易机器人 + 真实资金/回测，具体载体与后果明确）
- **通过判据**：
  1. **第 1 轮 TEACH**（≤3 条，每条讲后果），**并且紧接 ASK 费用授权**（≤1 题）——**依据 §3.1 第 2 条双条件 + V0.3.7"风险自身的 R6 槽位默认必问"**：ⓐ 费用 ∈ R6 ✅；ⓑ 不拿到费用授权，用户无法对"资金风险"作出知情拍板 ✅
  2. TEACH **≤3 条**，每条说清**后果**（如"不先定数据来源 → 回测结果不可信"）
  3. 明确表达"这些会影响……"，并为下一轮留接口；**受众/成功标准等普通 P0 不在本轮问**
- **失败判据**：
  1. 第 1 轮直接问"目标用户是谁 / 用 Python 还是 Java"等**普通** ASK 问题 → **FAIL**（普通 ASK 抢在 TEACH 前）
  2. TEACH >3 条，或只罗列风险名词、不讲后果 → **FAIL**
  3. 第 1 轮把 TEACH 与**普通 P0 ASK** 混装 → **FAIL**（**§3.1 第 1 条特别规定**：普通 P0 不得同轮叠加；注意 R4 本身允许同轮教学 + 提问，此处从严）
  4. **只做 TEACH、不问费用授权** → **FAIL**（V0.3.7：资金风险 ↔ 费用授权同域必问；这也是本用例此前"只做 TEACH 即可通过"的漏判修正）
- **⚠️ 与 HR-07 的分界**：本例的普通缺口（受众/成功）**即使被用户强调为阻塞，也不触发并列 —— 因为 R6 是闭集枚举，不含"受众"**。触发并列的是"资金风险 ↔ 费用授权"这一**同域**配对。真正的 HR-07 场景同样是**风险项与 R6 闭集项同域**。
- **关联规则**：契约 R14 / §3.1 闸门①②③ + 第 2 条（双条件 + 风险自身 R6 槽位）、R3、R4、R6；`SKILL.md` §2.5 规则 4、§11.0 规则 6

### HR-02 · 普通 C 不抢 P0 ASK（闸门①不满足 → 不得前置）

- **输入**：`帮我做一个公司介绍页。`
- **上下文**：首轮；无可读环境
- **缺口清单**：P0-产物=公司介绍页（有）；P0-受众=缺（**P0 项；注意：受众不属 R6 闭集枚举**，见下方说明）；P0-成功=缺；低价值视觉细节=缺
- **Type 判定**：P0 缺项 → **Type A（P0 最高层，须先问）**；"排版细节 / 加载速度 / 要不要加动画"等 → **普通 C（不属高风险五类）**
- **三闸门**：①**❌**（属实现/体验细节，非重大返工/安全/合规/不可逆架构/目标误解）
- **通过判据**：
  1. 第 1 轮直接 **ASK P0**（受众 / 成功标准），**不输出 TEACH 块**
  2. 若顺带提到体验细节，只能作为**后续待办**，不得占位
- **失败判据**：
  1. 第 1 轮先 TEACH"注意加载速度/排版规范/兼容性" → **FAIL**（普通 C 抢 P0）
  2. 把低价值细节当成 Type C 高风险前置 → **FAIL**（C 膨胀）
- **口径说明（V0.3.5 修正）**：`R6` 是**闭集枚举**（目标 / 范围 / 权限 / 费用 / 数据用途 / 不可逆操作），**不含"受众"**。本节此前的"阻塞项（R6）"标注有误 —— 受众属 **P0 最高优先级项**，按 §3 梯队先问；R6 只用于判断"该不该同轮并列"。
- **本例如遇受众确为阻塞**：**仍按本条处理**（受众不在 R6 闭集内 → 不触发 HR-07）；如需同轮 ASK，按 R4 容量即可，不适用"阻塞项不得顺延"条款。
- **关联规则**：契约 R14 闸门①、普通 C < P0 A（§3 梯队）、R6（闭集）；`SKILL.md` §2.5 规则 4

### HR-03 · TEACH 后进入 ASK（高风险项同轮并列 + 下一轮回到普通 ASK）

- **输入（第 1 轮）**：`帮我做一个客服 Agent。`
- **用户后续（第 2 轮）**：`这些我知道了，先按你说的注意。`（用户同轮也会答权限范围那 1 题）
- **缺口清单**：P0-产物=客服 Agent（有）；P0-受众/成功=缺（**普通，非 R6**）；**风险维度=幻觉处理 / 权限边界 / 人工接管**；其中"**权限边界**"与 **R6 阻塞项「权限」**耦合
- **Type 判定**：风险 → **高风险 C（①目标可能被根本误解：客服答错的责任边界）**；三闸门全过
- **通过判据**：
  1. **第 1 轮 TEACH**（≤3 条：幻觉兜底 / 权限边界 / 人工接管，各讲后果）**并且紧接 ASK 权限范围**（≤1 题）——**依据 §3.1 第 2 条"指向同一件事"双条件**：ⓐ 权限 ∈ R6 ✅；ⓑ 不拿到权限范围，用户无法对"权限边界风险"作出知情拍板 ✅
  2. **第 2 轮进入 ASK 普通 P0**（如受众：面向内部员工还是外部客户），并说明该答案会改变什么
  3. 决策记录中该风险记 `taught`，权限 ASK 与受众 ASK 各记一行 `asked`（R10）
- **失败判据**：
  1. 第 1 轮**只 TEACH、把权限范围推到下一轮** → **FAIL**（§3.1 第 2 条：阻塞项不得顺延）
  2. 第 2 轮**继续 TEACH** 同一维度 → **FAIL**（违反"同一维度 ≤1 次 / 累计 ≤2 轮"）
  3. 第 2 轮仍不提问、只重复风险提示 → **FAIL**（无限教学）
  4. 第 2 轮跳过 ASK 直接组稿出 Prompt → **FAIL**（普通 P0 未决）
- **⚠️ 粒度判定的反例（防"宽读"）**：本例如把第 1 轮被推迟的槽位换成**受众**（面向内部/外部），则**双条件 ⓐ 不成立**（受众 ∉ R6）→ **不得**触发并列，受众按 §3 梯队排后续轮次；此时"第 1 轮只 TEACH + 第 2 轮 ASK 受众"才是正确解。
- **关联规则**：契约 §3.1 第 1–2 条 + 第 4 步、R14、R6、R9、R10、R12；`SKILL.md` §6.6

### HR-08 · 用户已声明部署约束 → 该风险不再 TEACH（闸门② 信号㈡）

- **输入**：`给医生查看医学影像的专业系统，要在医院内网跑。`
- **上下文**：首轮；无可读环境
- **缺口清单**：P0-产物=医学影像系统（有）；P0-受众=医生（有）；**部署约束=内网（用户已声明）**；其余待决=P1 工作流 / P0-成功标准
- **Type 判定**："内网部署"是**用户主动声明的既有约束** → 命中**闸门② 信号㈡（部署/运行环境约束）**→ 该合规/权限风险**不算"用户未意识到"** → 按 §2 归属表走 **Type A（用户知道有约束，只是还没定细节）**
- **通过判据**：
  1. **不输出合规/权限的 TEACH 块**（用户已声明该维度）
  2. 直接 **ASK** 相关细节（如"内网是否允许外发导出""谁能看哪些片"）或按 §3 梯队问其他待决项
  3. 若确实还存在**用户未声明的**其他风险维度（如误诊责任），可对**那一项** TEACH，但不得把"内网/合规"再教一遍
- **失败判据**：
  1. 对内网/合规风险输出 TEACH 块 → **FAIL**（闸门② 信号㈡ 命中，重复教学；亦违反 `strategies/teach.md` 前置条件 7）
  2. 声称"用户没提合规" → **FAIL**（用户已声明内网部署，属环境约束，不得当作未意识到）
- **关联规则**：契约 §3.1 闸门②（信号㈡）/ §3.1 粒度对照表第 2 行、R14、R12

### HR-04 · TEACH ≤3 条且每条讲后果

- **输入**：`我要做一个医院影像系统。`
- **上下文**：首轮；无可读环境
- **缺口清单**：P0-产物=医院影像系统（有）；P0-受众=医生（有）；风险维度=合规（医疗数据）/ **权限（院内网访问，与 R6 重叠）** / 误诊责任
- **Type 判定**：合规类 → **高风险 C（①合规 + ②安全）**，三闸门全过
- **通过判据**：
  1. TEACH 条目数 **≤3**
  2. 每条都能回答"这条会影响你哪一步"（如"不先定数据留存范围 → 你无法确定能不能接入院内网"）
  3. 不出现通用风险目录式罗列（"注意安全、注意合规、注意性能"）
  4. **同轮紧接 ASK 权限边界**（与 R6「权限」重叠，不得顺延；题量上限：阻塞 ASK ≤2 题）
- **失败判据**：
  1. 条目数 ≥4 → **FAIL**
  2. 存在"只讲风险名词、不讲本项目后果"的条目 → **FAIL**（闸门③不满足仍 TEACH）
  3. 输出与用户目标无关的风险目录 → **FAIL**（禁止清单式恐吓）
  4. 讲完 TEACH 却不问权限边界、直接进入下一话题 → **FAIL**（§3.1 第 2 条）
- **关联规则**：契约 R14 防膨胀闸门第 1、4 条

### HR-05 · 同一维度不重复教学

- **输入（第 1 轮）**：`帮我做一个发票自动录入。`
- **用户后续（第 2 轮）**：`合规这块我知道了，先不管。`
- **缺口清单**：风险维度=资金/合规（第 1 轮 TEACH 过）
- **Type 判定**：该维度已 TEACH 且用户明确"暂不考虑"
- **通过判据**：
  1. 第 2 轮**不再主动** TEACH 合规，而是记录为「暂不做」/「待确认假设」并**写明原因**（R12）
  2. 转向 ASK 其他待决项（如 P1-抽取字段 / P0-受众）
- **失败判据**：
  1. 第 2 轮**再次主动**教学合规 → **FAIL**（重复教学）
  2. 用户说"先不管"后静默丢弃、决策记录无痕迹 → **FAIL**（违反 R12 不得静默丢弃）
- **边界说明（V0.3.5）**：若用户在后续轮次**主动追问**同一维度（如"你再讲讲合规那块"），允许再讲 **1 次**（`§3.1` 防膨胀：同一维度 ≤1 次优先，但用户追问可续 1 次），**累计仍 ≤2 轮**；超过则强制转 ASK 或记「暂不做」。
- **关联规则**：契约 R14 防膨胀闸门第 2 条、R12、R10

### HR-06 · 高风险 C 与 R11 同时命中 → 先 TEACH，紧接 ASK 产物（R14 > R11）

- **输入**：`帮我搞个东西，能自动帮我炒股赚钱，要那种电影感的。`
- **上下文**：首轮；无可读环境
- **缺口清单**：P0-产物=无形态（"东西"）→ **锚点缺失 → R11 触发**；P3=「电影感」→ Type B；风险维度=资金/回测/权限 → 高风险 C
- **三闸门**：①✅②✅③✅
- **通过判据**：
  1. **第 1 轮先 TEACH**（≤3 条），**不先 SHOW「电影感」**
  2. **同一轮紧接 ASK 产物**（≤1 题，R6 阻塞项"目标/范围"，同轮并列，**不推迟**）
  3. 决策记录：该风险记 `taught`，产物的 ASK 另记一行 `asked`
- **失败判据**：
  1. 第 1 轮**只 TEACH、把"做什么产物"推到下一轮** → **FAIL**（违反 §3.1 第 3 条：R14 与 R11 同时命中须同轮并列；亦违反 `strategies/teach.md` 反模式）
  2. 第 1 轮 SHOW「电影感」的三个方向 → **FAIL**（双重违规：产物锚点缺失 + 风险未教）
  3. 第 1 轮输出 TEACH + SHOW + ASK 三项全上 → **FAIL**（本例锚点缺失 → **SHOW 让位**，违反 §3.1 第 1 条与第 6 条；注意 R4 本身允许三块同轮，此处的限制来自 §3.1）
  4. ASK 里塞进多个普通 P0 问题（不止产物那 1 题）→ **FAIL**（借并列夹带）
- **关联规则**：契约 §3.1 第 3 条（R14 优先于 R11，但并列执行）、R11、R4；`SKILL.md` §11.0 规则 6、8

### HR-07 · 高风险 C 与阻塞项（R6）重叠 → 同轮并列，不得推迟阻塞项（D1 修复回归）

- **输入**：`帮我做一个客户名单表，要能导出 Excel 发给销售。`
- **上下文**：首轮；无可读环境
- **缺口清单**：P0-产物=客户名单表（有）；**R6 阻塞项=数据用途（发给销售）+ 权限（谁能看）**（共 2 项）；**风险维度=个人信息合规（用户完全未提及）**
- **Type 判定**：数据用途 / 权限 → **Type A（R6 阻塞项，2 个）**；合规风险 → **高风险 C（①合规 + ②安全）**
- **三闸门**：①✅（合规）②✅（三信号皆无）③✅（具体载体：手机号/客户姓名落库并导出 → 后果：个保法风险）
- **通过判据**：
  1. **第 1 轮先 TEACH**（≤3 条，讲后果），**同一轮紧接 ASK 阻塞项**（**阻塞项 ≤2 题**）
  2. ASK 只包含阻塞项，**不夹带普通 P0 问题**；若只问 1 题，另一项必须**同轮以一行列出并标注「本轮未拍板」**（不得静默顺延）
  3. 决策记录：`taught` + `asked` 各一行
- **失败判据**：
  1. 第 1 轮只 TEACH，把阻塞项整体推到下一轮 → **FAIL**（**推迟阻塞项**）
  2. 只 ASK 阻塞项、完全不 TEACH 合规风险 → **FAIL**（高风险 C 未前置）
  3. ASK 里混入"界面要不要分页""导出格式 CSV 还是 XLSX"等非阻塞项 → **FAIL**（借并列夹带）
  4. 两项阻塞项中有一项既未 ASK、也未标注「本轮未拍板」→ **FAIL**（静默顺延）
  5. 以"当轮容量已满"为由顺延，但同轮并未达到 §3.1 第 2 条的容量判定 → **FAIL**（后门条款）
- **本例如存在的意义**：这是 **D1（高风险 C × 阻塞项优先级为空）** 的固定回归，也是 **R3（多阻塞项 × 题量上限）** 的回归 —— 修复前，R14 与 R6 + `strategies/teach.md` 反模式对同一轮给出**相反**的唯一动作；修复后唯一正确动作 = **同轮 TEACH → ASK（阻塞项 ≤2 题，其余显式标注）**。
- **关联规则**：契约 §3.1 第 2 条、R14、R6、R4、§11.6；`strategies/teach.md` 前置条件 6 / 反模式
