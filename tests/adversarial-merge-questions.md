# 对抗测试 · 合并提问 vs 冻结 R2（V0.2 · Q6 专项）

> **状态**：Q6 已批准转正为 `SKILL.md` **§11.7**；其「补充判据（约束型依赖 vs 共同决策）」已入册。本文件的 M1～M12 为 **§11.7 固定回归案例**（M3/M5/M9 = 约束型依赖反例；M12 = 共同决策跨簇合并例）。冻结 R2 **未修改**，§11 进入**冻结候选**。

**目的**：验证"同一决策簇可以合并为一问"与冻结 R2 之间的真实分界。**本节记录规则落盘前的测试**；Q6 与 R2 原文均未被改写。
**被测文本（冻结）**——`tests/acceptance.md` R2：

> 统计每一轮的问题条目数，**全部 ≤3**，且 ≥1；不存在"一个问题里塞三个子问题"的规避写法（如"尺寸、时长、平台分别是？"算 3 个，若写成一段仍计 3 个）。

**读法澄清（本测试的前提）**：R2 规定的是**上限（1～3）**与**计数口径**（合并的子问题仍按个数计），它**并未禁止合并**。因此"合并 3 个子问题"在 R2 下是**合规**的（计 3 ≤ 3），只有在"合并后子问题数 >3"或"本轮还有其他问题导致总数 >3"时才越界。

**裁定口径**：
- `合并更优` = 同一决策簇，用户必须同时权衡才能给出一致答案；
- `拆开更优` = 跨决策簇，或合并后需要用户在一次回答里解决多个互相依赖的推理；
- `不该问` = 候选问题整体信息价值过低，合并与拆开都不是正解。

**案例数：12**

## M1 · 产品宣传片（同簇：投放目标三件套）
- **用户输入**：`帮我做一条产品宣传视频。`
- **已知**：产物＝宣传视频　**缺失**：平台、时长、观看后动作
- **合并问法**：`这条片子发在哪、大概多长、看完你希望观众做什么？`（3 子问）
- **拆开问法**：三轮各问一项
- **是否同一决策簇**：是（同属"这条片子要达成什么"）
- **子问题数 vs R2**：3 ≤ 3 → **合规**
- **认知负担**：低（用户心里通常已有成套答案）
- **裁定**：**合并更优**——拆开问会出现自相矛盾（先答"30 秒"、后答"要讲 5 个卖点"）

## M2 · 企业官网（同簇：受众 + 核心任务）
- **用户输入**：`做一个企业官网。`
- **已知**：产物＝企业官网　**缺失**：受众、访客核心任务
- **合并问法**：`这个站给谁看、他们进来最重要的一件事是什么？`（2 子问）
- **拆开问法**：先问受众，下一轮再问任务
- **是否同一决策簇**：是（受众决定任务的合理集合）
- **子问题数 vs R2**：2 ≤ 3 → 合规
- **认知负担**：低
- **裁定**：**合并更优**（一次得到受众—任务配对，避免两轮间的不一致）

## M3 · 3D 展示（同簇：运行环境）
- **用户输入**：`网页里嵌一个 3D 产品展示。`
- **已知**：产物＝网页内嵌 3D　**缺失**：设备档位、场景规模
- **合并问法**：`主要给手机看还是桌面看、单场景还是多场景切换？`（2 子问）
- **拆开问法**：先设备，再规模（两层）
- **是否同一决策簇**：是（同属"运行环境约束"）
- **子问题数 vs R2**：2 ≤ 3 → 合规
- **认知负担**：低
- **裁定**：**合并更优**（两者共同决定性能预算，分开问会各给一个"理论可行"的答案）

## M4 · 客服 Agent（同簇：服务定义）
- **用户输入**：`帮我做一个客服 Agent。`
- **已知**：产物＝客服 Agent　**缺失**：服务对象、要解决的问题、知识来源
- **合并问法**：`它先服务哪类客户、解决什么问题、知识从哪来？`（3 子问）
- **拆开问法**：三轮
- **是否同一决策簇**：是（同属"服务定义"，知识来源由服务对象决定）
- **子问题数 vs R2**：3 ≤ 3 → 合规
- **认知负担**：中低（用户能一次性描述业务）
- **裁定**：**合并更优**

## M5 · 海报（上下游同簇：用途 → 尺寸）
- **用户输入**：`帮我生成一张海报图。`
- **已知**：产物＝海报图　**缺失**：用途、尺寸、信息密度
- **合并问法**：`这张图用在哪、需要什么尺寸？`（2 子问）
- **拆开问法**：先用途，下一轮问尺寸
- **是否同一决策簇**：是（尺寸由用途推导）
- **子问题数 vs R2**：2 ≤ 3 → 合规
- **认知负担**：低（用户自己完成"用途→尺寸"的推导）
- **裁定**：**合并更优**

## M6 · 医学影像系统（跨簇 4 项）
- **用户输入**：`给医生查看医学影像的专业系统。`
- **已知**：产物、受众　**缺失**：工作流、信息密度、准确性、权限审计
- **合并问法**：`工作流、信息密度、准确性要求和权限审计分别是什么？`（4 子问）
- **拆开问法**：先问"最频繁的三个动作"（1 问覆盖工作流），后续按需
- **是否同一决策簇**：否（跨工作流／呈现／质量／合规四簇）
- **子问题数 vs R2**：4 > 3 → **越界**
- **认知负担**：高（用户需在一次回答里同时做四类决策）
- **裁定**：**拆开更优**（且合并越界）

## M7 · 新手作品集（跨簇 + 术语密集）
- **用户输入**：`我想做个作品集网站，不太懂这些。`
- **已知**：产物＝作品集；用户已声明不熟　**缺失**：内容组织、技术栈、视觉层级、成功指标
- **合并问法**：`你的内容组织方式、技术栈、视觉层级和成功指标是什么？`（4 子问，术语密集）
- **拆开问法**：1 个开放问 + 少量示例（"你最想让人先看到什么？"）
- **是否同一决策簇**：否，且对新手不可回答
- **子问题数 vs R2**：4 > 3 → 越界
- **认知负担**：极高（远超用户能力）
- **裁定**：**拆开更优**（本质应换成低难度问法）

## M8 · 发票自动录入（跨簇 3 项，含外部取证）
- **用户输入**：`帮我做发票自动录入。`
- **已知**：产物、输入＝电子 PDF　**缺失**：抽取字段、异常复核责任、部署方式
- **合并问法**：`要抽取哪些字段、异常复核归谁、部署在云还是内网？`（3 子问）
- **拆开问法**：先字段 → 再看异常 → 部署最后
- **是否同一决策簇**：否（内容／流程责任／基础设施）
- **子问题数 vs R2**：3 ≤ 3 → 合规
- **认知负担**：中高（"复核归谁"通常需要问财务）
- **裁定**：**拆开更优**（合规但不应合并：其中一项需跨部门取证，会拖住另外两项）

## M9 · 图片生成（跨簇 3 项，含依赖）
- **用户输入**：`给我们的产品做一张配图。`
- **已知**：产物＝配图　**缺失**：画面主体、风格、比例
- **合并问法**：`画什么主体、什么风格、什么比例？`（3 子问）
- **拆开问法**：主体 → 风格 → 比例
- **是否同一决策簇**：否（内容／视觉／技术），且风格依赖主体
- **子问题数 vs R2**：3 ≤ 3 → 合规
- **认知负担**：中（用户要先决定主体才能谈风格）
- **裁定**：**拆开更优**（合规但低效：把依赖关系推给用户）

## M10 · 网页视觉细节（同簇但低价值）
- **用户输入**：`做一个公司介绍页。`
- **已知**：产物、受众　**缺失**（名义上）：首屏动画、字体、圆角
- **合并问法**：`首屏要不要动画、字体用哪套、圆角多大？`（3 子问，全 P3 局部）
- **拆开问法**：逐个问
- **是否同一决策簇**：是（同属视觉细节）
- **子问题数 vs R2**：3 ≤ 3 → 合规
- **认知负担**：低
- **裁定**：**不该问**——合并合规但不产生信息增益，多数可默认；正解是不问、进「待确认假设」

## M11 · 数据报表（跨簇 4 项）
- **用户输入**：`帮我搭一个自动化的数据报表流程。`
- **已知**：产物　**缺失**：数据来源、频率、使用者、异常责任
- **合并问法**：`数据从哪来、多久跑一次、给谁看、错了谁负责？`（4 子问）
- **拆开问法**：第一轮问来源 + 频率（同簇：数据链路），第二轮问使用者 + 用途
- **是否同一决策簇**：否（数据链路／使用场景／责任）
- **子问题数 vs R2**：4 > 3 → **越界**
- **认知负担**：高
- **裁定**：**拆开更优**（且合并越界）

## M12 · 专业导演分镜（跨簇 2 项，专业用户）
- **用户输入**：`给这支产品片写分镜，一镜到底，24fps、浅景深、三幕结构。`
- **已知**：产物、运镜、帧率、景深、结构　**缺失**：品牌露出、声音设计
- **合并问法**：`结尾要不要品牌露出、声音设计走哪条路线？`（2 子问）
- **拆开问法**：分两轮
- **是否同一决策簇**：否（合规／听觉），但两项都是用户能立刻决定的具体项
- **子问题数 vs R2**：2 ≤ 3 → 合规
- **认知负担**：低（专业用户）
- **裁定**：**可接受的合并**（跨簇但回答成本低；属边界案例，不算"明显更优"）

## 四项结论

1. **明显更优的合并问法**：M1、M2、M3、M4、M5——共同特征是**同一决策簇 + 子问题 ≤3 + 用户能一次权衡给出一致答案**。这类合并能避免"分轮回答自相矛盾"，还省下提问额度。
2. **认知负担过高的复合问题**：M6、M7、M11（4 子问，跨簇，越 R2 上限）；M8、M9（3 子问不越界，但跨簇或含跨部门取证／依赖推理，仍应拆开）；边界案例 M12（跨簇但成本低，可接受）；反例 M10（合并合规、负担低，但**低价值**，正解是不问）。
3. **当前 R2 是否真的过严**：**不过严。** R2 只管上限与计数口径，M1～M5 这类合并问法在 R2 下**本来就合规**（3 ≤ 3）。R2 的真实缺陷不是"禁止合并"，而是**缺少正向判据**——没有任何条款说明"何时应该合并"。同时更正上一轮 V0.2 报告中的表述：V2 案例把 R2 描述为"倾向否定合并提问"属于**过强解读**，应更正为"R2 未禁止合并，只是没有规定何时应该合并"。
4. **若需修改 R2，最小例外条件**：严格说**不需要修改 R2**。最小补充是一条**独立的正向条款**（建议未来放入 §11 系列，而非改 R2）：*若多个缺口属于同一决策簇（用户需同时权衡才能给出一致答案），可合并为一问，并按实际子问题数计入 1～3 额度；当合并后子问题数 >3、或跨决策簇且其中含需外部取证／依赖推理的项时，不得合并。* 若坚持落在 R2 文本上，最小改动也仅为在"算 3 个"后补一句"同簇合并不视为规避写法"——但这会削弱反规避意图，**不建议**。

## 固定回归标签（V0.2 冻结候选 · §11.7 补判据后）

| 标签 | 案例 | 用途 |
|---|---|---|
| **约束型依赖反例**（一答案改变另一问题的可行取值／选项集合／判断标准／后续提问方式 → 按 §11.6 不合并） | **M3、M5、M9** | 防止未来把"主题相关"误当"可合并" |
| **共同决策跨簇合并例**（同一决策的不同表达维度、≤2、全低成本、无依赖 → 可合并） | **M12** | 证明跨簇例外条款可用，且与约束型依赖形成对照 |
| 其他 | M1、M2、M4（同簇合并）／M6、M7、M8、M11（越界或跨簇拆开）／M10（低价值不该问） | 覆盖六项条件与六条拆开条件 |

**回归状态**：M1～M12 **12/12 唯一裁定**，作为 §11.7 固定回归长期保留。

## §11.6 × §11.7 边界（已裁决 · 判据已入册）

- 交互出现在 **M3、M5、M9**：这三例的候选缺口**看似同簇或低负担**，但上游答案会改变下游的**可行取值／选项集／问法**，因此触发 §11.6 优先条款 → 一律拆开。这改写了落盘前对 M3、M5 的"合并更优"判断。
- 与 M12 的对照给出唯一判据：**上游答案是否改变下游的可行取值／选项集／问法**（约束型依赖）→ 拆开；若两者只是**同一个决策的两半**（受众+任务、平台+时长+目标动作）→ 允许合并。
- **已入册**：该判据已补入 `SKILL.md` §11.7「补充判据（约束型依赖 vs 共同决策）」（仅边界说明，未新增规则编号、未新增状态、未改 R2、未改 §11.6 优先级）。
